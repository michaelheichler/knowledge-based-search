# Bug and reliability list, 2026-06-29 sweep

Found during the post-build logic review. Not all are crashes; some are contract
drift, fragility, or wiring holes. Each lists location, problem, fix, and a
verification step. Run V before closing.

## Critical (L1)

### B29. `_ddg_target` mangles protocol-relative URLs
- Location: `server/engines.py:174-180`.
- Problem: `return href if href.startswith("http") else "https:" + href`
  produces `https:example.com/foo` for `//example.com/foo` (single slash,
  invalid). Any bare protocol-relative link from the HTML endpoint becomes
  unparseable downstream.
- Fix: `urllib.parse.urljoin("https://duckduckgo.com", html.unescape(href))`
  for the non-uddg branch, after the `uddg=` extraction.
- V: unit test with a fixture containing `//host/p`; assert result starts
  with `https://host/p`.

### B30. `library_first` is dead in isolation
- Location: `hooks/detector.py:23-40`.
- Problem: prompt "verify a claim" matches `library_first.words` but no
  `recency/research/deep` word, so `parts` stays empty and the function
  returns `None` before reaching the library-first block. Skill is never
  nudged for method-only cues.
- Fix: evaluate `library_first` before the `if not parts: return None`
  early return, or treat a library hit as an implicit `research` route.
- V: `assert nudge_for("verify this claim", TRIGGERS)` includes
  `mcp__library`.

### B31. Undocumented 5th tool breaks the redirect chain
- Location: `server/mcp_server.py:82-96` (`deep_context_aware_search`),
  absent in `SKILL.md`, `README.md`, `session_start.py` primer, and
  `plan.md` (which caps the surface at four).
- Problem: the tool exists, the description tells the agent to load the
  skill, the skill never teaches it. The agent loops.
- Fix: either add a section in `SKILL.md` and a primer line, or drop the
  tool from `TOOL_SCHEMAS` and `_call_tool`.
- V: skill-creator evals confirm the surface the agent knows about
  matches the registered tools.

### B32. `deep_research` top-level summary is the head of round 1
- Location: `server/mcp_server.py:162-163`.
- Problem: `_summary_text([item["summary"] for item in searches])` breaks
  at 500 words; each `item["summary"]` is already up to 1000. The
  top-level summary is therefore the first 500 words of round 1, and
  sub-rounds contribute nothing.
- Fix: concatenate all `searches[*]["summary"]` and slice once at
  `_SUMMARY_MAX_WORDS`, or rename to make the truncation explicit.
- V: integration test with `max_rounds=3` and 3 distinct queries asserts
  that the summary contains content from each round.

### B33. `deep_research` `max_rounds` upper bound not enforced
- Location: `server/mcp_server.py:142-156`.
- Problem: `max_rounds = max(1, int(max_rounds))` honors any value; the
  JSON schema caps at 6 but the code does not. A caller passing
  `max_rounds=100` does 100 `web_search` calls.
- Fix: `min(6, max(1, int(max_rounds)))`, matching the schema and the
  same pattern used in `deep_context_aware_search:168`.
- V: unit test with `max_rounds=100` asserts loop bound of 6.

### B34. `deep_research` early-termination can starve `max_rounds`
- Location: `server/mcp_server.py:155`.
- Problem: `if not new_hosts: break` exits on the first round whose
  results come from already-seen hosts. News/research queries that
  surface the same authoritative domain (Reuters, arXiv) across
  sub-queries exit after round 1. Plan T3.5 AC: "bounded by
  `max_rounds`."
- Fix: count `max_rounds` independently of host novelty; expose the
  novelty break as an opt-in `min_new_sources` config.
- V: integration test with three queries that all return results from
  one domain asserts the loop runs `max_rounds` times.

### B35. `rag.py` host crash is not recoverable in-process
- Location: `server/rag.py:96-109`.
- Problem: the pre-spawn poll uses `stop_if_absent=True` and returns
  `None` immediately when the socket file is missing. The function
  then exits the lock without spawning a replacement. After a host
  crash, all subsequent `embed`/`rerank` calls fall through to `None`
  for the rest of the process lifetime.
- Fix: use `stop_if_absent=False` in the pre-spawn poll, or set it
  `True` only when a pid file confirms another process owns the socket.
- V: kill the host (`kill -9 <pid>`) and call `rank` again; assert a
  fresh host is spawned and answers.

### B36. JSON-RPC crash leaves the client hanging
- Location: `server/mcp_server.py:452-458`.
- Problem: `except Exception: traceback.print_exc(...); raise` writes
  to stderr (invisible to the MCP client) and re-raises. The stdio
  client waits forever for the next `jsonrpc` line.
- Fix: emit a JSON-RPC error envelope before re-raising
  (`{"jsonrpc":"2.0","id":null,"error":{"code":-32603,"message":...}}`).
- V: simulate a tool crash (raise inside `_call_tool`) and assert the
  client receives a valid `jsonrpc` error.

## Major (L2)

### B37. Hardcoded `PYTHON` path in all three merge scripts
- Location: `claude-code/merge-claude-settings.py:9`,
  `codex/merge-codex-config.py:10`, `pi/merge-pi-settings.py:8`.
- Problem: the placeholder `__KBS_PYTHON__` is designed to be portable
  but every merge script overwrites it with
  `/Users/michael/dev/skills/skill-model-loader/.venv/bin/python`.
  Repo is unshareable.
- Fix: read from `KBS_PYTHON` env var; fall back to
  `<repo>/../skill-model-loader/.venv/bin/python` if it exists; else
  raise with a clear message.
- V: install in a different user account; assert the merge picks up
  the local interpreter.

### B38. Engine defaults ignore `config.json` shape
- Location: `server/engines.py:426-440`.
- Problem: `_build_tasks` defaults `google`/`bing`/`startpage`/
  `mojeek` to `True`. The user's `server/config.json` only declares
  `searxng_url` and `duckduckgo`, so 5 scrapers always run, including
  the blocked google/bing paths (see B4 in `bugs.md`). The plan says
  SearXNG primary, with the rest as a labelled degraded fallback.
- Fix: default all non-`searxng`/`duckduckgo` engines to `False`;
  require explicit opt-in. The blocked engines can stay as no-ops
  with a single warning at startup.
- V: with default `config.json`, assert only `searxng` and
  `duckduckgo` tasks are spawned.

### B39. `as of now` / `right now` are too greedy
- Location: `hooks/triggers.json:11` (recency.words).
- Problem: substring match (`word in low`) means "as of now" matches
  "as of nowhere" and similar prose. `right now` matches "all right
  now and then."
- Fix: anchor with regex (`\\bas of (now|today)\\b`, `\\bright now\\b`)
  and drop the rest, or move these to the patterns list.
- V: `assert nudge_for("as of nowhere we are", TRIGGERS) is None` and
  `assert nudge_for("what is right now trending", TRIGGERS)` is not
  None.

### B40. `best_text` falls back to a link-heavy `whole_page`
- Location: `server/fetch.py:67-70`.
- Problem: when no block has a positive score, `best_text` returns the
  `whole_page` text, which counted `link_chars` for every `<a>`
  segment. A page that is all navigation becomes a wall of menu items.
- Fix: if the chosen block has `link_chars * 2 >= chars`, return `""`
  (or `best_text` returns the empty string so the caller surfaces
  "no readable content").
- V: feed a fixture of pure nav markup; assert the result is empty.

### B41. Pi extension is repo-bound
- Location: `pi/extensions/knowledge-based-search/index.ts:6`,
  `pi/merge-pi-settings.py`.
- Problem: `const ROOT = path.resolve(__dirname, "../../..")` only
  resolves to the repo when the absolute repo path is registered in
  `data["extensions"]`. A symlink or copy into
  `~/.pi/agent/extensions/` would break the hook invocation silently.
- Fix: add an env override `KBS_DIR`; if unset, walk up from
  `__dirname` looking for `hooks/session_start.py` and fall back to
  clear error.
- V: copy the extension dir to a temp location; assert the hook
  resolves the repo via the env override.

### B42. `_norm_url` does not sort query params
- Location: `server/engines.py:402-405`.
- Problem: dedup keys differ for `?a=1&b=2` vs `?b=2&a=1`. Mild dedup
  gap that lets near-duplicates through.
- Fix: parse with `urllib.parse.parse_qsl(keep_blank_values=True)`,
  sort, re-encode, then concatenate.
- V: unit test with two URLs differing only in query-param order;
  assert they normalize to the same key.

### B43. `deep_research` description does not warn about cost
- Location: `server/mcp_server.py:71`.
- Problem: plan T3.5 AC: "Description warns it is expensive." Current
  text: "True multi-step reasoning is the calling agent job." No
  cost/tokens warning.
- Fix: rewrite the description to flag the cost
  ("Bounded multi-round search. Expensive: each round fetches and
  ranks. Prefer `web_search` for one-shot questions.").
- V: read-through against plan T3.5 AC.

### B44. `session_start.py` primer does not warn about cost either
- Location: `hooks/session_start.py:6-16`.
- Problem: same as B43, but in the session-start injection. The
  primer is the agent's first exposure to the tool set; cost warnings
  belong here too.
- Fix: append one line: "`deep_research` is bounded but expensive;
  reach for `web_search` first, escalate only if needed."
- V: read-through; grep the primer for the keyword "expensive."

### B45. Library nudge fires when `mcp__library` is not registered
- Location: `hooks/detector.py:37-38`, `hooks/session_start.py:14`.
- Problem: when the user has not installed the library MCP, the
  hook still nudges the agent toward `mcp__library`, leading to a
  failed tool call. Plan T6.1 implies multi-runtime install; the
  library is an optional addition.
- Fix: add a presence check (config file or env var) and drop the
  library line if absent; or instruct the agent to skip silently
  if the tool is not available.
- V: with no library installed, run a "verify a claim" prompt and
  assert the nudge does not name `mcp__library`.

### B46. Double unlink of socket on shutdown
- Location: `server/rag_host.py:184-198`.
- Problem: `server.server_close()` removes the socket; line 198 calls
  `os.unlink(sock_path)` again. Cosmetic, but the second call hides
  ENOENT silently.
- Fix: drop the second unlink, or rely on `server_close()` only.
- V: run the host, SIGTERM it, assert the socket is gone and no
  errors on stderr.

## Minor (L3)

### B47. `merge_snippet` order in `merge-claude-settings.py`
- Location: `claude-code/merge-claude-settings.py:51-58`.
- Problem: `merge_lists` preserves the order of the first occurrence.
  After `remove_our_hooks` strips our entries, the incoming snippet is
  appended; the first user-added hook is preserved, but the new
  snippet is always last. Acceptable, but re-running produces the
  same order (idempotent) only when the snippet itself is stable.
- Fix: none required; document the ordering rule in the function
  docstring.
- V: idempotency test (`tests/test_merge_installers.py`) passes.

### B48. `skill_gate` reads the full transcript on every MCP call
- Location: `hooks/skill_gate.py:33-44`.
- Problem: scans line-by-line; performance degrades linearly with
  transcript size. Reasonable for typical sessions, painful for
  long ones.
- Fix: keep a per-session cache of "skill loaded" (file mtime + a
  small marker file) so the check is O(1) after the first hit.
- V: time the gate on a 10MB transcript fixture before and after.

### B49. `quick_web_search` default `num_results=8` vs `web_search` `5`
- Location: `server/mcp_server.py:42-56`.
- Problem: inconsistent defaults between the two main search tools.
  Not a bug per se, but the asymmetry is not justified in the plan.
- Fix: align to 8 in both, or document why `web_search` is smaller
  (it fetches pages, so cost grows).
- V: read-through; update plan or code for consistency.

### B50. `mcp_server.py` exposes `engines._norm_url` as a leaky internal
- Location: `server/mcp_server.py:177, 193, 195, 209, 212, 221`.
- Problem: `mcp_server` reaches into `engines._norm_url` rather than
  calling a public function. Coupling is fine in a small repo, but
  the prefix `_` advertises "private."
- Fix: rename to `engines.norm_url` (no underscore), or expose a
  `dedup_key(hit)` helper.
- V: grep confirms no remaining `_norm_url` callers outside
  `engines.py` and `mcp_server.py`.

### B51. `method_inject.py` ignores the event payload
- Location: `hooks/method_inject.py:18-21`.
- Problem: parses `sys.stdin` and discards it. PostToolUse could
  vary the reminder by tool (e.g., emphasize citations after
  `web_search`, operators after `quick_web_search`).
- Fix: read the event, branch on `tool_name`, emit a tool-specific
  reminder; or accept the static design and add a comment.
- V: read-through; either implement or document.

### B52. `_reformulate` may produce only one candidate
- Location: `server/mcp_server.py:382-406`.
- Problem: candidates list length depends on input shape; a single
  keyword with `best` or `top` in it produces exactly one
  reformulation. `deep_research` then has 2 calls, not `max_rounds`.
  Acceptable per plan, but the early break can shrink the work
  below the configured cap.
- Fix: pad the candidate list with `words[:3]`-style fallbacks
  until it reaches `limit`; or document that "max_rounds is a
  ceiling, not a floor."
- V: read-through; update the comment on `deep_research`.

### B53. `summary` cap (1800 chars) vs `summary` word cap (1000)
- Location: `server/mcp_server.py:16-17, 131`.
- Problem: `_SUMMARY_MAX_WORDS=1000` builds the text, then
  `_cap_chars(1800)` truncates. ~1000 words is ~6000 chars; the
  char cap is the binding constraint. The word cap is a no-op in
  practice.
- Fix: pick one. Plan T3.2 AC: "default response near 500 to 1000
  tokens." 1800 chars is ~450 tokens. Either bump to 4000 chars
  (~1000 tokens) or remove the word cap.
- V: integration test asserts final response size.
