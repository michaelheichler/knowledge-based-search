## Overview

This chapter (labeled Chapter Eight in the text) walks through creating a Linux virtual machine as the foundation for an OSINT investigation environment. It covers the choice of operating system, installation procedures for every supported combination of host OS and VM client, and initial customization of the resulting Debian desktop.

## Choice of Operating System

The authors recommend Debian as the Linux base for the OSINT VM. Unlike Ubuntu (a Canonical product), Debian provides an official ARM build for Apple Silicon machines, ships with no default telemetry, does not impose Ubuntu Pro prompts or Snap software requirements, and does not follow a fixed release calendar. Ubuntu could be substituted with minor changes, but the guide is written exclusively for Debian to avoid branching instructions.

The reference version is Debian 12.5 stable. That release receives updates and security patches for at least three years as the current major version, plus two additional years of long-term support after Debian 13 is released, giving a practical support horizon extending to at least mid-2027 and likely 2028. Readers are told to always use the most current stable release.

Pop!_OS is the author's personal host OS of choice for privacy and security, but it is not recommended for the VM because Debian is considered more appropriate for a broad audience.

## Mandatory Account Configuration

Across every installation path, one convention is mandatory: the user account name, username, full name, and password must all be set to "osint" (lowercase). Scripts and tutorials throughout the rest of the book depend on this exact value, and deviations cause failures in later steps. Because the VM sits inside a secured host machine, minimal password security is acceptable.

No root password is set during installation. The primary user is granted root privileges, which is standard practice for a single-user VM.

## Installation Paths by Host and VM Client

The chapter covers six distinct paths. Each shares a common Debian installation sequence but differs in the VM client used and in the integration steps required after initial boot.

### macOS Host (ARM / Apple Silicon) with UTM

Download the arm64 ISO from `https://cdimage.debian.org/debian-cd/current/arm64/iso-cd/` (example filename: `debian-12.5.0-arm64-netinst.iso`). In UTM, create a new Virtualize/Linux VM, allocate half of system RAM and half of CPU cores (never leave cores as "Default"), set the maximum virtual disk to 150 GB, and enable file sharing to a chosen host folder (Downloads is recommended). Name the VM "Debian Stock".

During installation, select "Install" rather than Graphical Install, accept defaults for language and keyboard, decline a domain name, skip the root password, partition the disk using the guided option for all files in one partition, select GNOME as the desktop environment alongside the Debian desktop environment package and standard system utilities, eject the ISO when prompted, and reboot.

After first boot, disable Location Services and skip the initial setup screens. Install the Spice integration layer for clipboard and folder sharing:

```
sudo apt install spice-vdagent spice-webdavd -y
```

To make the shared folder visible inside Debian, shut down the VM, open UTM settings, change "Directory Share Mode" to "Spice WebDAV", save, reboot, click the Shared Folder icon in the UTM window, and access it under "Other Locations" in the Debian Files application as "Spice client". The share can take several minutes to appear and must be re-mounted each session.

Recommended UTM settings to confirm while the VM is shut down: USB Support set to USB 3.0, Directory Share Mode set to Spice WebDAV, Emulated Display card set to virtio-ramfb, Retina Mode enabled.

### macOS Host (Intel) with UTM

Use the amd64 ISO from `https://cdimage.debian.org/debian-cd/current/amd64/iso-cd/`. Creation and installation steps are identical to the ARM path except the installer offers a "Graphical Install" option and disk selection shows "QEMU HARDDISK". Post-install steps for Spice and shared folder configuration are the same.

### Linux Host with VirtualBox

Download the amd64 ISO. In VirtualBox, create a new VM named "Debian Stock", attach the ISO, enable "Skip Unattended Installation", allocate half of RAM and half of CPUs, disable EFI, and set maximum disk to 150 GB. In Settings, enable bidirectional Shared Clipboard and Drag and Drop, and add the Downloads folder as an auto-mounted shared folder.

Install Debian using Graphical Install, set disk target to "VBOX HARDDISK", and select GNOME. After first boot, shut down. The automated Guest Additions installer does not work correctly with Debian, so download the VBoxGuestAdditions ISO manually from `https://download.virtualbox.org/virtualbox` matching the exact VirtualBox version (for example, 7.0.10). Mount it in Storage settings, boot the VM, run the software from the Files application, then execute:

```
sudo groupadd vboxusers
sudo usermod -aG vboxusers osint
sudo groupadd vboxsf
sudo usermod -aG vboxsf osint
```

Remove the Guest Additions ISO attachment afterward and reboot. The shared folder appears as "sf_downloads" inside the VM.

### Linux Host with VMWare Workstation Pro

Steps mirror the VirtualBox path through the Debian installer. Disk target is labeled "VMWare" and GRUB targets /dev/sda. VMWare Tools are installed by copying the `VMWareTools...gz` archive from the mounted VMWare CD to Downloads, extracting it, and running `vmware-install.pl` as a program. A known bug at time of writing prevents the shared folder feature from functioning. The recommended workaround is to use a USB device for file transfer.

### Windows Host with VirtualBox

Identical to the Linux/VirtualBox path with one difference in the shared folder dialog (uses "Select Folder" instead of "Open"). Guest Additions are installed through the VirtualBox top menu "Devices > Insert Guest Additions..." option rather than by downloading manually, followed by the same group membership commands.

### Windows Host with VMWare Workstation Pro

Steps are the same as the Linux/VMWare path, with the installer option labeled "Installer disc image file" instead of "Use ISO image". VMWare Tools installation follows the same extraction and `vmware-install.pl` procedure. The shared folder limitation and USB workaround apply here as well.

## Preserving Stock Debian

After completing installation for any path, the chapter instructs readers to shut down the VM and clone it before any customization. The unmodified clone is kept as "Debian Stock" and the working copy is renamed "OSINT VM". The Stock VM is booted monthly to receive updates and kept ready to produce fresh clones, which prevents rebuilding from scratch when testing breaks something.

Cloning by client:
- UTM: right-click the VM and choose "Clone", then rename via "Edit".
- VirtualBox: right-click and choose "Clone", accept defaults, provide a new name.
- VMWare Workstation Pro: right-click and choose "Manage > Clone".

Removing a VM follows a similar right-click path in each client, with options to remove only the menu entry or also delete the associated files.

## Initial Debian Customization

All customization is performed on the "OSINT VM" only, not on the Stock copy.

**Display.** Right-click the desktop, open Display Settings, select the maximum resolution, and apply 200% scaling if text is too small. The goal is maximum resolution within the VM client with appropriate scaling inside Debian.

**Persistent Dock.** Debian's default dock disappears when clicking the workspace. Install the "Dash to Dock" GNOME extension from `https://extensions.gnome.org/extension/307/dash-to-dock`, then configure it to appear on the left, disable Intelligent Autohide, enable Panel mode, and set icon size to 32.

**Terminal in Dock.** Right-click Terminal in the applications grid and select "Pin to Dash" to keep it accessible from the dock.

**Terminal Appearance.** The default Gnome Terminal has a white background, which hides white text output from many Linux tools. Change the theme variant to "Dark" in Terminal Preferences.

**Background and Window Buttons.** Debian's GNOME does not expose a simple UI for solid-color backgrounds. The following Terminal commands set a specific gray background and add minimize, maximize, and close buttons to all windows:

```
gsettings set org.gnome.desktop.background picture-uri ''
gsettings set org.gnome.desktop.background picture-uri-dark ''
gsettings set org.gnome.desktop.background primary-color 'rgb(66, 81, 100)'
gsettings set org.gnome.desktop.wm.preferences button-layout ":minimize,maximize,close"
```

**System Settings.** Open the Settings application and disable Notifications, Screen Lock, File History and Trash, and Automatic Suspend. Enable Natural Scrolling if preferred.

**Centered Windows.** Open the Tweaks application, go to Windows, and enable "Center New Windows" to prevent new windows from always opening on the left side of the screen.

**Desktop Icons.** By default Debian does not show files on the desktop. Install the "Desktop Icons NG (DING)" extension from `https://extensions.gnome.org/extension/2087/desktop-icons-ng-ding`, then run `cd ~/Desktop && rm *.desktop` to remove default icon files placed there automatically.

**Updates.** Keep both VMs updated with:

```
sudo apt update && sudo apt upgrade -y
```

The authors check for updates weekly and note that a later chapter provides a script to automate this.

## Key Terms

- **Debian 12.5 stable**: the recommended base Linux distribution
- **UTM**: VM client for macOS (supports ARM and Intel hosts)
- **VirtualBox**: VM client for Linux and Windows hosts (preferred on newer hardware)
- **VMWare Workstation Pro**: alternative VM client for Linux and Windows (preferred on older hardware)
- **Spice / spice-vdagent / spice-webdavd**: UTM integration layer for clipboard and folder sharing
- **VBoxGuestAdditions**: VirtualBox integration layer for screen resizing and folder sharing
- **VMWare Tools / vmware-install.pl**: VMWare integration layer
- **GNOME**: desktop environment selected during installation
- **Dash to Dock**: GNOME extension for a persistent sidebar dock
- **Desktop Icons NG (DING)**: GNOME extension for desktop file icons
- **sf_downloads**: VirtualBox auto-mounted shared folder name visible inside the VM
- **osint**: mandatory username, account name, and password for all VMs built with this guide
- **Debian Stock**: the preserved unmodified VM clone
- **OSINT VM**: the working clone used for all investigation and customization
