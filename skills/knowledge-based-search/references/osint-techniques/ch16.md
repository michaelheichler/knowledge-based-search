This chapter (labeled Chapter Ten in the source) covers manual installation and use of a large set of OSINT applications within a Debian Linux virtual machine. The author separates manual processes from automated scripts. Readers are asked to absorb the manual approach first so they can testify to their actions, troubleshoot problems, and understand what happens behind the scenes. Automation via bash scripts is deferred to the following chapter.

## Environment Foundations

All applications are installed through Terminal, not the Debian software store. Python programs go into isolated environments using either `pipx` or `python3 -m venv` to prevent dependency conflicts that plagued earlier configurations where everything was installed into the root operating system. The base setup commands are:

```
sudo apt update
sudo apt install python3-pip python3-venv pipx git -y
cd /usr/lib/python3.11 && sudo rm EXTERNALLY-MANAGED
```

The `EXTERNALLY-MANAGED` file removal suppresses a pip warning that appears on every install. `pipx` is preferred for single-package Python apps. `venv` is preferred when a package has many complex dependencies.

## Video Tools

**VLC** (`https://www.videolan.org/`) is installed with `sudo apt install vlc -y`. On first launch, the "Allow metadata network access" option should be disabled.

**FFmpeg** (`https://ffmpeg.org/`) is a Terminal-only toolset installed with `sudo apt install ffmpeg -y`. Key commands for a file called `evidence.mpg`:

- Play unusual or corrupt video: `ffplay evidence.mpg`
- Convert to MP4: `ffmpeg -i evidence.mpg evidence.mp4`
- Extract all frames as PNG images: `ffmpeg -y -i evidence.mpg %04d.png`
- Extract one frame per second: `ffmpeg -i input.mp4 -vf fps=1 %04d.png`
- Extract audio as 320k MP3: `ffmpeg -i evidence.mpg -f mp3 -ab 320000 -vn music.mp3`
- Rotate video counterclockwise (for sideways phone video): `ffmpeg -i evidence.mpg -vf transpose=0 evidence.mp4`
- Merge two videos: `ffmpeg -i video1.mp4 -i video2.mp4 -filter_complex "[0:v][0:a][1:v][1:a]concat=n=2:v=1:a=1" -vsync vfr output.mp4`
- Remove redundant (motionless) frames: `ffmpeg -i evidence.mpg -strict -2 -vf "select=gt(scene\,0.005),setpts=N/(25*TB)" evidence.mp4`

The frame extraction command is described as the most frequently used, particularly when video evidence will be used in court.

**YT-DLP** (`https://github.com/yt-dlp/yt-dlp`) is the author's most-used Linux utility, installed with `pipx install yt-dlp && pipx ensurepath`. It works with YouTube, Vimeo, and most major video sites. Key usage:

- Download a single video at best quality: `yt-dlp "URL"`
- Download an entire channel: `yt-dlp "https://www.youtube.com/user/USERNAME/videos"`
- Download with metadata (comments, subtitles, description): add flags `--write-comments`, `--write-subs`, `--sub-langs all`, `--write-description`
- Skip the video and get only text data: add `--skip-download`
- Embed subtitles: `--embed-subs`
- Cap resolution to avoid large file sizes: `-f 'bestvideo[height<=1080]+bestaudio'` (also works for 1440p, 720p, 480p)
- Extract audio as MP3: `yt-dlp "URL" -x --audio-format mp3 --audio-quality 320k`
- Convert to MP4 on download: `yt-dlp "URL" --recode-video mp4`

When FFmpeg is installed, YT-DLP automatically downloads separate high-quality audio and video streams and merges them. JSON output files are best viewed in Firefox.

**Fragmented video downloads** apply when YT-DLP fails on streaming sites. Many sites deliver video as hundreds of small `.ts` fragment files with an `.m3u8` playlist. The process: open browser DevTools (right-click, Inspect), go to the Network tab, play the video, find the `.m3u8` file in the list, copy its URL, and feed that URL directly to `yt-dlp`. This reconstructs the fragments into a single file.

**Blocked downloads** can sometimes be bypassed by spoofing the HTTP Referer header. In the Network tab of the Inspector, click the video's network entry and look for the Referer field. Then pass that value to yt-dlp with `--referer https://REFERER_DOMAIN/`. The author describes using this technique to recover a television episode no longer available anywhere else.

**Streamlink** (`https://streamlink.github.io/`) is installed with `pipx install streamlink`. It handles live and pre-recorded video streams. Key commands:

- Watch a Twitch stream through VLC: `streamlink https://www.twitch.tv/USERNAME best`
- Archive a live stream to a file: `streamlink https://www.twitch.tv/USERNAME best -o FILENAME`
- Watch and archive simultaneously: `streamlink https://www.twitch.tv/USERNAME best -r FILENAME`
- Convert the archived file to MP4 using FFmpeg: `ffmpeg -i FILENAME -c copy ~/Documents/FILENAME.mp4`

When Streamlink cannot identify a stream URL, the Stream Detector browser extension (covered in the next chapter) can capture the M3U8 URL manually, which can then be fed to Streamlink.

## Username Tools

All username tools produce false positives. The recommendation is to run multiple tools and use the results together to raise or lower confidence.

**Sherlock** (`github.com/sherlock-project`) is installed with `pipx install sherlock-project`. Basic usage: `sherlock USERNAME --csv -o ~/Documents/Report.csv`.

**SocialScan** (`github.com/iojw/socialscan`) is installed with `pipx install socialscan`. It queries fewer services but produces reliable results. It also accepts email addresses: `socialscan EMAIL@DOMAIN --json ~/Documents/output.txt`. JSON output is required for email queries because results are color-coded in the terminal.

**Blackbird** (`github.com/p1ngul1n0/blackbird`) checks over 500 sites. It is installed via venv and run with `python3 blackbird.py -u USERNAME --pdf`. The PDF report is saved to the `results/` folder inside the Blackbird directory. The author prefers it because of its JSON output and readability within Firefox.

**Maigret** (`github.com/soxoj/maigret`) is a fork of Sherlock that scans over 2,800 sites. The author calls it the most robust username tool. It is installed via venv and run with `maigret -a -P -T USERNAME` (all modules, PDF output, text output). Reports go to the `reports/` folder.

**WhatsMyName-Python** (`github.com/C3n7ral051nt4g3ncy`) is a fork of the no-longer-functional WhatsMyName application. It is slow but thorough, and occasionally finds results missed by the other tools.

**BDFR** (Bulk Downloader for Reddit, `github.com/aliparlakci/bulk-downloader-for-reddit`) archives all posts and comments from a specific Reddit user into JSON files organized by Subreddit. Install: `pipx install bdfr`. Commands:

- Download all posts: `bdfr archive ~/Documents/USERNAME/ --user USERNAME --submitted`
- Download all comments: `bdfr archive ~/Documents/USERNAME/ --user USERNAME --all-comments`

## Email Tools

**Holehe** (`github.com/megadose/holehe`) queries dozens of services to check if an email address is associated with accounts. Install: `pipx install holehe`. Usage: `holehe EMAIL@DOMAIN > ~/Documents/output.txt`. Result legend: `[+]` means account found, `[-]` means not found, `[x]` means rate-limited or blocked.

**Eyes** (`github.com/N0rz3/Eyes`) checks whether a custom-domain email is hosted at Proton Mail, and attempts to link it to accounts on X (Twitter) and GitHub. It is installed via venv.

**GHunt** (`github.com/mxrch/Ghunt`) queries the Google API to retrieve account data associated with a Google email address, Google Drive ID, or GAIA (Google Accounts and ID Administration) ID. It requires valid login cookies from an active Google account. Configuration involves navigating to `mail.google.com` in the VM's Firefox, using the Network Inspector to find entries for `oauth2_4/` and `aas_et/`, copying the token values, and providing them to `ghunt login`. Alternatively, the GHunt Firefox extension automates this step.

Queries:
- By email: `ghunt email EMAIL@DOMAIN`
- By Google Drive ID: `ghunt drive DRIVE_ID`
- By GAIA ID: `ghunt gaia GAIA_ID`

A query on `larry@google.com` returned the account holder's name, profile photo, last profile edit date, GAIA ID, four YouTube channels, active Google services, and Maps review status. GHunt is described as advanced and frequently failing, requiring fresh credentials. The chapter instructs readers to check the GitHub project page for the currently working configuration method.

**H8Mail** (`github.com/khast3x/h8mail`) queries email addresses and usernames against breach data services. Install: `pipx install h8mail`. After generating a config file with `h8mail -g`, the Leak Lookup free service is enabled by removing a comment character: `sed -i 's/\;leak\-lookup\_pub/leak\-lookup\_pub/g' h8mail_config.ini`. Usage: `h8mail -t EMAIL@DOMAIN -c ~/Downloads/h8mail_config.ini`. A username can also be queried: `h8mail -t USERNAME -q username -c ~/Downloads/h8mail_config.ini`.

**Hash tools** from `github.com/HashPals/` help identify and crack hashed passwords found in breach data. Two tools are available: `name-that-hash` (identifies hash type) and `search-that-hash` (attempts to find the plain-text value using online services). Both install via pipx. Example: running `sth --text "5f4dcc3b5aa765d61d8327deb882cf99"` returns the MD5 hash of the word "password".

## Image Collection Tools

**Gallery-DL** (`github.com/mikf/gallery-dl`) bulk-downloads image collections from 150+ sites including Tumblr, 4chan, Flickr, Imgur, and Reddit. Install: `pipx install gallery-dl`. Usage: `gallery-dl "ALBUM_URL"`.

**RipMe** (`github.com/RipMeApp/ripme`) is a graphical alternative. It requires Java (`sudo apt install default-jre -y`) and is launched with `java -jar ripme.jar`. It supports Imgur, X (Twitter), Tumblr, Instagram, Flickr, Photobucket, and Reddit.

**Instagram tools** are covered by three programs that require rotating between them because Instagram actively blocks automated access. The three are Instaloader, Toutatis, and Osintgram.

- Instaloader and Toutatis install together: `pipx install instaloader && pipx install toutatis`
- Osintgram installs via venv

All three require logging into Instagram in the VM's Firefox first. Instaloader stores credentials after a one-time login command (`instaloader --login=USERNAME`). Toutatis requires a Session ID extracted from the Firefox Inspector's Cookies tab (`sessionid` field from any Instagram network request). Osintgram requires running `make setup` inside its directory.

Toutatis returns full name, userID, business/private account status, follower and following counts, post count, obfuscated phone number, and obfuscated email. Osintgram can retrieve photos, stories, comments, captions, followers, followings, and account info. "Challenge" errors from Instagram mean the activity was flagged. Logging in through Firefox and confirming the activity as non-malicious clears the block.

## Domain and Website Tools

**EyeWitness** (`github.com/ChrisTruncer/EyeWitness`) automates screenshot collection from URLs, useful when working from a large list of suspect websites. It requires geckodriver for Firefox. A single-URL query: `./EyeWitness.py --single https://TARGET.com -d ~/Documents/EyeWitness/`. A file-based batch query: `./EyeWitness.py -f ~/Desktop/sites.txt --web -d ~/Documents/EyeWitness/`. Output is `Report.html` containing screenshots alongside server IP, page title, modification date, and full page source. The author describes processing over 300 URLs into a report generated in minutes.

**HTTrack** (`httrack.com`) makes a full local copy of a static website for offline navigation. Install: `sudo apt install httrack webhttrack -y`. The graphical version (`webhttrack`) runs in a browser. It works well on small business websites and blogs, not on large dynamic sites like social networks. The author used it once to extract gigabytes of scraped LinkedIn data from a third-party site before it disappeared.

**Waybackpy** (`github.com/akamhy/waybackpy`) queries Internet Archive metadata for a domain, installed with `pipx install waybackpy`. It retrieves all known URLs indexed for a domain, identifies the oldest and newest archived snapshot, and deduplicates results. It does not download the actual HTML content of archived pages.

**Waybackpack** (`github.com/jsvine/waybackpack`) downloads the actual HTML content from all Archive.org snapshots for a URL. Install: `pipx install waybackpack`. The URL must end with a trailing `/` or the tool will not work. Each snapshot is saved in a date-labeled folder. HTML files can be opened in Firefox to see how a page appeared on a given date. A keyword search across the folder set can identify snapshots containing specific terms of interest.

**Amass** (`github.com/owasp-amass/amass`) enumerates subdomains of a target domain. It is slow but thorough. Installation uses `dpkg --print-architecture` to determine whether to download the ARM or AMD64 binary. Execution: `./amass intel -o ~/Documents/OUTPUT.txt -active -ip -whois -d TARGET.com`.

**Photon** (`github.com/s0md3v/Photon`) crawls internal pages of a target website and produces three output files: `external.txt` (outbound links), `files.txt` (documents and other files such as PDFs), and `internal.txt` (internal page URLs). Installed via venv, executed with `python3 photon.py -u TARGET.com -l 3 -t 100`.

**Sublist3r** (`github.com/aboul3la/Sublist3r`) is a fast subdomain finder, less thorough than Amass but significantly faster. A test against `cnn.com` found 808 subdomains. Installed via venv, executed with `python3 sublist3r.py -d TARGET.com -o ~/Documents/OUTPUT.txt`.

**TheHarvester** (`github.com/laramies/theHarvester`) searches a domain for subdomains, hosts, and email addresses by querying search engines. A test against `cnn.com` returned 72 hosts and 16 email addresses. Executed with `python3 theHarvester.py -d TARGET.com -f ~/Documents/OUTPUT.json -b duckduckgo`. Output is a JSON file best viewed in Firefox.

**Carbon14** (`github.com/Lazza/Carbon14`) analyzes image metadata embedded in a webpage to estimate the true age of content. The author used it while investigating an anonymous blog where all posts shared the same recent date after an import. Carbon14 found an image created in 2022, suggesting older original content. Dates can be intentionally or unintentionally altered, so results are investigative leads rather than forensic evidence.

**Change Detection** (`github.com/dgtlmoon/changedetection.io`) monitors URLs for changes locally, without sending the URL to any external service. Install: `pipx install changedetection.io`. Launch: `changedetection.io -d ~/Documents/ChangeDetection -p 5000 & sleep 3 && firefox http://127.0.0.1:5000`. The interface shows a diff of changes between visits.

**Archive Box** (`github.com/ArchiveBox/ArchiveBox`) is an all-in-one local website archiver introduced in 2022. Install: `pipx install archivebox`. After initialization (`archivebox init`), adding a URL triggers simultaneous capture via SingleFile through Chrome, PDF generation, a screenshot, a wget download of the live page, an Archive.org snapshot fetch, HTML extraction, and media file download. Launch: `archivebox server 0.0.0.0:8000 & firefox http://0.0.0.0:8000/`.

## Metadata Tools

**Exiftool** (`https://exiftool.org/`) is installed with `sudo apt install libimage-exiftool-perl -y`. A single image: `exiftool evidence.jpg`. A bulk analysis of all images in a folder exported to CSV: `cd ~/Desktop/Evidence && exiftool * -csv > ~/Desktop/Report.csv`. The author describes using this on 200 blog images to produce a spreadsheet with GPS coordinates identifying locations relevant to an investigation.

**Metagoofil** (`github.com/opsdisk/metagoofil`) finds and downloads documents from a target domain via search engines. It works better when not behind a VPN. Multiple file types should be run separately: pdf, doc, xls, ppt, docx, xlsx, pptx. Downloaded documents can then be analyzed with Exiftool.

**MediaInfo** (`https://mediaarea.net/en/MediaInfo`) displays metadata from video files, installed with `sudo apt install mediainfo-gui -y`. Its most valuable use is on video files sent directly from a mobile device, which may contain camera make, model, OS version, and GPS data. Videos downloaded from the internet typically do not retain this information.

**mat2** (Metadata Anonymisation Toolkit 2, `https://0xacab.org/jvoisin/mat2`) removes metadata from images before uploading during covert operations. Install: `sudo apt install mat2 -y`. Usage: `mat2 dirty.jpg`. This creates `dirty.cleaned.jpg`.

**xeuledoc** (`github.com/Malfrats/xeuledoc`) extracts hidden metadata from Google Docs, Sheets, and Slides, including the document owner's name, email address, and Google identifiers. Install: `pipx install xeuledoc`. Usage: `xeuledoc GOOGLE_DOC_URL`.

**Sherloq** (`github.com/GuidoBartoli/sherloq`) is a standalone offline image manipulation detection tool. It replicates many online metadata and tampering analysis methods without requiring an upload. It does not support ARM-based processors. After installation via venv, it is launched with `python3 ~/Downloads/Programs/sherloq/gui/sherloq.py`. One analysis mode called "Principal Component Analysis" highlights areas of potential digital manipulation.

## OSINT Frameworks

**Spiderfoot** (`github.com/smicallef/spiderfoot`) is a browser-based automated reconnaissance tool that accepts a domain, IP address, or email address, then runs hundreds of queries and presents results in categories such as external accounts, human names, leak site content (Pastebin), similar domains, and web technologies. It also generates a graph of connections. Installed via venv, launched with `python3 ./sf.py -l 127.0.0.1:5001 & firefox http://127.0.0.1:5001`. The "All" use case is most thorough but also most intrusive toward the target.

**Recon-ng** (`github.com/lanmaster53/recon-ng`) is a modular web reconnaissance framework covered in the most detail of any single tool in the chapter. Key concepts:

- **Workspaces** isolate each investigation: `workspaces create CASENAME`
- **Marketplace** holds available modules: `marketplace search`, `marketplace install MODULE`, `marketplace info MODULE`
- **Modules** are loaded and executed: `modules load MODULE`, then `options set SOURCE VALUE`, then `run`
- **Cumulative storage**: every query adds to the workspace database, and running new modules on previously found data expands the collection automatically

Demonstrated modules include `profiler` (username search), `bing_domain_web` (Bing host discovery), `google_site_web` (Google host discovery), `brute_suffix` (alternate TLD discovery), `pgp_search` (email discovery from PGP keys), and `html` (HTML report generation). Reports are saved to `~/.recon-ng/workspaces/CASENAME/results.html`. API keys are required for some modules. The chapter notes the project may have been abandoned but tools still perform well for specific tasks.

**Mr. Holmes** (`github.com/Lucksi/Mr.Holmes`) is a menu-driven tool covering social account OSINT, phone number OSINT, domain and IP OSINT, email OSINT, dork generation, people OSINT, and encoding and decoding. Installed by running its `install.sh` script. The phone number module (requires the full international number without the leading `+`) returns carrier, country, area, timezone, and name if available, then generates hundreds of Google and Yandex dorks in various formats. Reports are saved to `~/Downloads/Programs/Mr.Holmes/GUI/Reports`. The author notes that clicking "OK" kills the application. The Enter key must be pressed instead.

**sn0int** (`github.com/kpcyrd/sn0int`) is a framework similar to Recon-ng. It does not currently support ARM-based processors. It uses workspaces, scoped entities, and installable modules. An example with the `ctlogs` module queries certificate transparency logs to find subdomains. Documentation is at `https://sn0int.readthedocs.io`.

**Internet Archive CLI** (`archive.org/developers/internetarchive`) downloads large collections from Archive.org. Install: `pipx install internetarchive`. To download only MP4 files from a collection: `ia download --search 'collection:COLLECTION_ID' --glob="*.mp4"`.

## Geospatial Tool

**Google Earth Pro** (`google.com/earth`) is not available on ARM-based systems. Key investigative features include enabling layers one at a time (Photos, Roads, 3D Buildings, Gallery with YouTube videos), and the Historical Imagery slider (clock icon in the toolbar) that shows satellite images of a location across different dates. Drug enforcement agents use the historical imagery feature to monitor suspected drug cultivation. The author cites it as a tool that has assisted investigations over a decade by providing satellite imagery unavailable from other online sources.

## Screen Capture

The author recommends all screen captures occur inside the VM rather than from the host, citing a real 2014 case in which a detective's host-recorded video accidentally exposed a file of covert accounts, which the defense then sought access to.

Native Debian keyboard shortcuts: `PrtSc` saves a full screenshot to the Pictures directory, `Shift + PrtSc` selects a region, `Alt + PrtSc` captures the active window. Kazam (`github.com/henrywoo/kazam`, installed with `sudo apt install kazam -y`) provides video screen recording. It is minimal, leaves no branding in output, but is buggy on ARM-based Debian.

## VM Maintenance

Standard update commands: `sudo apt update && sudo apt upgrade -y`. After installation sessions, run `sudo apt update --fix-missing`, `sudo apt --fix-broken install`, and `sudo apt autoremove -y` to repair broken installs.

**BleachBit** (`https://www.bleachbit.org/`) is installed with `sudo apt install bleachbit -y` and run with administrator privileges. All options except "Free disk space" should be selected. The author ran it after this chapter's testing and removed 1.5 GB of unnecessary data.

## Large File Transfer

The shared folder method can fail when copying hundreds of large videos from the VM to the host. A more reliable alternative is to format a USB drive as FAT from within the VM (using the Disks application), allowing the drive to be read by any operating system. The procedure involves ejecting the drive from the host, then loading it into the VM through VirtualBox's Devices menu. Files larger than 4 GB cannot be stored on a FAT-formatted drive, but the author states this has not been a problem in practice.

## Chapter Themes

The chapter returns to three points throughout. First, no single tool is reliable on any given day, so redundancy across tools is necessary. Second, manual knowledge of each command matters so investigators can testify to their actions and troubleshoot problems rather than simply pushing a button. Third, everything in this chapter will be wrapped into custom bash scripts in the following chapter, so the manual process is a foundation, not the permanent workflow.
