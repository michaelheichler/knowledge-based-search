## Purpose and Orientation

Chapter 2 explains how to configure a macOS machine as a secure, minimally exposed host for OSINT investigations. The host itself is never used for investigative browsing. All investigation happens inside virtual machines running on top of it. The chapter's job is to get that host into a clean, private, and defensible state before any VM work begins.

The authors state a preference for macOS as the OSINT host, because Apple Silicon (M-series) machines run VMs faster than comparable Linux or Windows hardware, produce less heat, and are reasonably secure by default. The VM software of choice on macOS is UTM, a free and open-source application.

## Hardware Recommendations

For new purchases, the authors recommend a MacBook Pro with an M-series processor rather than older Intel-based models. The 14-inch MacBook Pro is described as the sweet spot for productivity and value. Among chip tiers, the Pro variant (not the base or Max) is recommended for most users. Minimum suggested configuration is 32 GB RAM. Storage of 512 GB works for casual use, but 1 TB is better. External drives can supplement internal storage at lower cost. M1 and M2 machines are adequate for OSINT work. Upgrading between M-series generations is unnecessary unless moving from an Intel machine.

## Fresh Installation

Before configuring anything, the authors require starting from a clean OS install. The process for macOS Sonoma (version 14.0 at time of writing) is:

1. Update the OS to the latest stable version via System Settings > General > Software Update.
2. Erase and reset: System Settings > General > Transfer or Reset > Erase All Content and Settings.

Upon first boot of the clean install, the authors walk through the setup wizard with specific choices that minimize data exposure:

- Select "My computer does not connect to the internet" when prompted for network setup.
- Skip the Migration Assistant.
- Choose "Set Up Later" to bypass Apple ID. The authors state they have never associated an Apple ID with their OSINT machine and do not intend to. Without an Apple ID link, Apple has limited ability to associate activity on the machine with a specific account.
- Create a local account with a generic name (such as "Laptop" or "Computer") and a strong password with no hint.
- Disable Location Services.
- Deselect all analytics options.
- Disable Siri.
- After setup, disable Wi-Fi and Bluetooth in System Settings.

## Firewall and Privacy Settings

The built-in macOS firewall is enabled and hardened:

- System Settings > Network > Firewall > enable.
- Disable "Automatically allow built-in software to receive incoming connections."
- Disable "Automatically allow downloaded signed software to receive incoming connections."
- Enable Stealth Mode.

Additional privacy settings to apply:

- Siri and Spotlight: disable all Siri Suggestions and Privacy toggles for every listed app.
- Privacy and Security > Analytics and Improvements: verify all are disabled.
- Privacy and Security > Apple Advertising: disable Personalized Ads.
- General > Software Update: click the info icon and deselect all automatic update options.

## Full-Disk Encryption (FileVault)

The authors describe enabling FileVault as "the most important setting within this chapter." macOS does not encrypt the drive by default, which means physical forensic access could extract files from a lost or stolen device. Steps:

- Privacy and Security > Turn On FileVault.
- Choose "Create a recovery key and do not use my iCloud account."
- Store the recovery key somewhere safe.

## Finder Configuration

By default, macOS hides files in the Library folder and other hidden paths. To expose them, press Shift + Command + . (period) while in Finder. The Finder settings (General, Tags, Sidebar, Advanced tabs) are also adjusted to personal preference. The goal is full visibility into the file system for backup purposes.

## Encrypted External Drives

External USB drives used for macOS host backups should be encrypted. The process in Disk Utility requires:

1. View > Show All Devices.
2. Select the device (not the formatted volume) and click Erase.
3. Change the Scheme to "GUID Partition Map."
4. Choose "APFS (Encrypted)" as the format.

This applies only to drives used from the macOS host. Drives intended for use inside a Linux VM should not be formatted this way, as the VM will need its own access to them.

## Rosetta

For M-series Macs, Rosetta 2 should be confirmed as installed. It allows applications built for Intel (x86) to run on ARM hardware. The installation command (requiring internet access) is:

```
softwareupdate --install-rosetta --agree-to-license
```

## Antivirus and Antimalware

Mac computers have no built-in antivirus. Commercial free products such as Avast and Kaspersky are not recommended because of questionable business practices. However, the authors state it is "irresponsible to have absolutely no protection whatsoever on an investigative machine," particularly because court testimony may require disclosure of security software. Three open-source tools are recommended, none of which run continuously in the background.

First, Homebrew (Brew) must be installed, as it serves as the installation manager for all three tools. The install command is fetched from brew.sh:

```
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
```

After installation, run `brew doctor`, `brew update`, `brew upgrade`, and `brew analytics off` to confirm the setup and disable usage telemetry.

**Task Explorer** (objective-see.com/products/taskexplorer.html): Scans running processes against VirusTotal and alerts with a red flag if a suspicious file is found. Does not remove threats. Installed with:

```
brew install --cask taskexplorer
```

**KnockKnock** (objective-see.com/products/knockknock.html): Scans for programs set to launch at boot, which is how most viruses persist. Does not remove threats. Installed with:

```
brew install --cask knockknock
```

Both Task Explorer and KnockKnock are from Objective-See and are recommended for weekly execution.

**ClamAV** (clamav.net): Open-source antivirus database. Does not run in the background and does not remove viruses by default. It only reports the location of suspicious files. It does not score well on commercial "Top 10" antivirus lists, which the authors attribute to those lists being paid placements. ClamAV is valued here for two reasons: it catches Windows-targeted malware that may be present as email attachments (and could infect Windows VMs), and it allows the investigator to confirm in court reports that a traditional antivirus was used. The installation sequence:

```
brew install clamav
sudo mkdir /usr/local/sbin
sudo chown -R `whoami`:admin /usr/local/sbin
brew link clamav
cd /opt/homebrew/etc/clamav/
cp freshclam.conf.sample freshclam.conf
sed -ie 's/^Example/#Example/g' freshclam.conf
```

To update virus definitions and run a scan:

```
freshclam -v
clamscan -r -i /
```

To scan and automatically remove detected files (use with caution, as this can delete necessary files):

```
clamscan -i -r --remove=yes /
```

Full scans with ClamAV can take hours. The authors note they do not run it often, but say investigators working federal cases should run all three tools weekly and document that the machine was clean.

## Telemetry Blocking

macOS collects substantial telemetry by default. A software firewall can stop this. The authors mention Little Snitch (paid) and LuLu (free) as options. However, because all OSINT investigation happens inside VMs rather than inside macOS itself, the macOS software firewall cannot see VM traffic. For a dedicated OSINT host machine the authors consider a software firewall optional. Full guidance on personal device telemetry blocking is deferred to a separate macOS privacy guide.

## VPN

A VPN routes traffic through an encrypted tunnel to a remote server, masking the investigator's true IP address and location from target websites. The authors recommend paid VPN providers over free ones, because free providers often monetize through data aggregation. The recommended provider is Proton VPN, whose applications are fully open-source. Install on macOS:

```
brew install --cask protonvpn
```

The authors' policy is to remain connected to the VPN at all times when the macOS device is on the internet. VMs running on the host share the same VPN IP address. At home, the VPN is handled at the router/firewall level rather than at the computer, so the app is used mainly while traveling.

## Password Manager

Investigators create many covert accounts across online services. A password manager is required to track credentials. The authors recommend KeePassXC: open-source, cross-platform, and offline (no cloud sync). It is stored on the host machine rather than inside VMs, because VMs may be deleted and rebuilt regularly. Install on macOS:

```
brew install --cask keepassxc
```

Setup: create a new database with a strong unique master password, move the encryption strength slider to maximum, store the database file in a safe location, and keep an encrypted backup on a USB drive. The master password should be memorized. The database file should never be stored online.

For each covert profile, the workflow is to let KeePassXC generate a random password of at least 40 to 50 characters, then copy and paste it into the service. This ensures that a breach of one service does not expose credentials for any other. The KeePassXC browser extension is not recommended for OSINT work because it would require copying the master database into VMs unnecessarily.

## Chapter Summary

By the end of Chapter 2, the reader should have a macOS machine that has been freshly installed, stripped of Apple ID association, encrypted at the disk level, hardened with firewall and privacy settings, and equipped with three antivirus tools, a VPN, and an offline password manager. The machine is not used directly for investigation. It serves only as a clean, secure host for the virtual machines described in subsequent chapters.
