## Overview

This chapter covers the recommended virtualization software for macOS hosts: UTM (available at mac.getutm.app). The author departs from prior editions, which relied on VirtualBox for all platforms. VirtualBox is no longer recommended on Apple devices for two reasons: it does not fully support Apple Silicon (ARM architecture), and macOS security prompts require repeated confirmations and system reboots during updates. UTM is presented as a simpler and more stable replacement.

## What UTM Is

UTM is a free, open-source virtualization and emulation program. On Apple Silicon machines it uses Apple's Hypervisor framework to run ARM operating systems at near-native speeds. On Intel Macs it virtualizes x86/x64 systems. It also supports cross-architecture emulation (x86/x64 on Apple Silicon, ARM64 on Intel), though emulation is slower than virtualization. No paid alternative offers all of these capabilities in one package. UTM is built on QEMU, which has historically been difficult to configure directly.

Installation via Homebrew:

```
brew install --cask utm
```

## Virtualization vs. Emulation

UTM asks the user to choose one of these two modes when creating a VM.

**Virtualization** uses the host's hardware (via a hypervisor) and allocates dedicated resources to the guest. It is fast. A constraint: the guest OS must match the host processor architecture. An M-series Mac cannot virtualize x86/x64 systems, only ARM-based ones.

**Emulation** uses software to translate guest code into the host's instruction set. It is slower but flexible across architectures. The chapter notes emulation is available in UTM but not used in the covered workflows.

## Creating a macOS VM (Apple Silicon Hosts Only)

To run a macOS guest on an M1/M2/M3 Mac:

1. Download an IPSW restore file from a legitimate source. The chapter references `https://mrmacintosh.com/apple-silicon-m1-full-macos-restore-ipsw-firmware-files-database/` and gives an example filename: `UniversalMac_14.2.1_23C71_Restore.ipsw`.
2. In UTM, choose "Create a New Virtual Machine", then "Virtualize", then "macOS 12+".
3. Browse to the IPSW file.
4. Set RAM to 50% of host RAM, CPU cores to half the host's performance cores (example: 4 cores on an M1 Pro with 8 performance cores).
5. Set the drive size, then save.
6. In Display settings, set the resolution (example given: 3840x2160) and enable HiDPI.

The resulting macOS VM runs nearly as fast as the native host. Its drive file is a fixed size regardless of actual data inside it. The VM file is stored at `/Users/[username]/Library/Containers/UTM/Data/Documents/` and has the `.utm` extension.

**Optional shared folder between host and guest macOS:**
Enable File Sharing in macOS System Settings, share the desired folder, set the VM network to "Shared Network" in UTM settings, select the same folder as the VM's shared directory, then from within the guest Finder connect to the host as a network server using host credentials.

**Disabling network before first boot:** Right-click the VM's Network item in UTM and select "Remove". To re-enable, open VM Settings, click "New" in the left menu, add a Network device, and save.

**UTM and software firewalls:** Because UTM uses Apple's native virtualization framework, software firewalls such as Little Snitch cannot intercept traffic to or from UTM VMs. The workaround for fully offline operation is the network removal procedure above.

## Creating a Windows 11 VM (ARM ISO, Apple Silicon Hosts)

This section is described as optional. Windows VMs on M-series Macs require ARM builds of Windows 11. The recommended tool for obtaining the ISO is CrystalFetch:

```
brew install --cask crystalfetch
```

CrystalFetch downloads Windows installation media directly from Microsoft and converts it to the proper format. Select "Windows 11", "Apple Silicon", the desired language and edition, then download and save the ISO.

To create the VM in UTM: choose "Virtualize" then "Windows", browse to the ISO, set RAM to 50% of host RAM and CPU to half the performance cores, set drive size. In Display settings, change the Display Card to "virtio-ramfb" and enable all checkboxes. During Windows installation, declare no product key and install the UTM Guest Tools when prompted. After installation, clear the ISO from the CD-ROM setting. The VM can run in trial mode or with a purchased license.

## USB Device Access

For Windows and Linux VMs, UTM exposes attached USB devices through a "USB Devices" icon in the VM window. Selecting a device transfers it from the host to the guest. macOS will warn about removing a drive without ejecting, but no harm results. By default UTM uses a USB 3.0 driver. If an older drive is not recognized, switch to USB 2.0 in the VM's Input settings (or vice versa).

## Read-Only VM Execution

UTM can launch a Windows or Linux VM without saving any changes. Right-click the VM and choose "Run without saving changes". This is useful for testing new software in a clean environment without risk of permanent changes to the VM.

## Clones, Exports, and Moving VMs

While a VM is shut down, the main UTM window offers options to clone, share (export), or move the VM. Cloning preserves the original and creates an independent copy useful for per-investigation instances. The Share option exports the entire VM as a `.utm` file for archiving or transfer. VMs can be moved once using the "Move selected VM" button to a preferred folder on the host.

## Snapshots

UTM provides a Terminal-based snapshot feature, but it is less capable than VirtualBox's snapshot system. The author does not use UTM snapshots, preferring clones and exports instead.

## VM Size and Shrinking

Windows and Linux VMs accumulate disk space over time, including space from deleted content. To reclaim it: shut down the VM, open its Settings in UTM, select the IDE drive, and click "Reclaim Space". The macOS VM drive size is fixed and cannot be shrunk.

## VPN Compatibility Note

Using Proton VPN on the macOS host with "Kill Switch" mode enabled blocks internet access to all UTM VMs. The recommended workaround is to disable Kill Switch mode in the Proton VPN host application while using a UTM VM.

## Key Facts and Terms

- **UTM**: free, open-source, mac.getutm.app. Installs via `brew install --cask utm`.
- **IPSW**: the restore file format used to install macOS in a VM. Sourced from Apple CDN via mrmacintosh.com.
- **CrystalFetch**: helper tool for downloading the Windows 11 ARM ISO. Installs via `brew install --cask crystalfetch`.
- **VM storage path**: `/Users/[username]/Library/Containers/UTM/Data/Documents/`
- **Hypervisor framework**: Apple's native virtualization layer used by UTM on Apple Silicon.
- **Little Snitch**: software firewall that cannot intercept UTM VM traffic because of how Apple's virtualization framework operates.
- Recommended RAM allocation for any VM: 50% of host RAM. Recommended CPU: half of host performance cores.
- The author's hardware: 2021 MacBook Pro with M1 chip. Reported boot times: Linux VM under 10 seconds, Windows VM under 19 seconds, macOS VM approximately 6 seconds.
