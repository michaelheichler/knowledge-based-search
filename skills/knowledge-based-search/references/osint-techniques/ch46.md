## Overview

This chapter (labeled Chapter 38 in the converted ebook) walks through the software setup required for the data-intensive work covered in the rest of the guide. It covers three operating systems (macOS, Linux, and Windows) and then addresses VPN selection and configuration. The goal is a uniform toolset across all platforms so that subsequent tutorials run identically regardless of OS.

## Core Tools and Their Roles

Five command-line utilities appear across all three platforms and are treated as mandatory.

- **Wget**: downloads files from the internet within a terminal.
- **Ripgrep**: a fast replacement for Grep that searches files and folders for specific text. It is faster than standard Grep but has limitations with large datasets.
- **Qgrep**: creates compressed databases from data and returns search results far faster than Ripgrep. Installed manually from `https://github.com/zeux/qgrep/releases/tag/v1.3` by downloading the platform-appropriate zip, extracting it to `~/Documents/Qgrep`, and marking the binary executable with `chmod +x`.
- **jq**: a command-line JSON processor used to parse long JSON entries into a single line.
- **Sed, Awk, Cut (GNU versions)**: text-processing utilities essential for manipulating large data files. On macOS the native versions are slower and less capable than their GNU counterparts, so the chapter replaces them. On Windows these tools do not exist by default and must be installed.

Additional tools installed on all platforms: **FreeFileSync** (data backup and synchronization), **Telegram** (data acquisition from channels, with a noted content-moderation risk), **Transmission** (BitTorrent client for large dataset torrents), and **Tor Browser** (access to Tor-network sites used in ransomware and leak research).

**BBEdit** is recommended only for macOS as a text viewer capable of opening multi-gigabyte files and allowing immediate find-and-replace.

**Zenity** is required on macOS for scripts that present selection menus (already present on Pop!_OS and Ubuntu).

## macOS Setup

The package manager is **Homebrew** (brew.sh). Installation runs a single curl/bash command from the terminal. After installation, four commands confirm readiness: `brew doctor`, `brew update`, `brew upgrade`, and `brew analytics off` (the last disables usage telemetry).

Because macOS ships with its own sed, awk, and cut, Homebrew installs the GNU replacements under prefixed names (`gsed`, `gawk`, `gcut`). To make the GNU versions the default, their paths must be added to `~/.zshrc`. The file is created with `touch ~/.zshrc`, opened with `open -a TextEdit ~/.zshrc`, and three PATH lines are pasted in:

```
PATH="/opt/homebrew/opt/gnu-sed/libexec/gnubin:$PATH"
PATH="/opt/homebrew/opt/gawk/libexec/gnubin:$PATH"
PATH="/opt/homebrew/opt/coreutils/libexec/gnubin:$PATH"
```

After reopening Terminal, `sed --version` should return "sed (GNU sed) 4.9", `awk --version` should return "GNU Awk 5.3.0", and `cut --version` should return "cut (GNU coreutils) 9.4". The coreutils package also replaces Sort and other utilities.

Python is confirmed and linked with `brew install python`, `brew unlink python && brew link python`, and `python3 -m pip install pip`.

Telegram is installed with `brew install --cask telegram`, Transmission with `brew install --cask transmission`, and Tor Browser with `brew install --cask tor-browser`.

## Linux Setup

Linux systems already include sed, awk, cut, and related utilities in their GNU forms, so no replacement step is needed. The setup sequence is:

```
sudo apt update
sudo apt upgrade -y
sudo apt install -y wget
sudo apt install -y curl
sudo apt install -y python3-pip
sudo apt install -y ripgrep
sudo apt install -y jq
sudo apt install transmission
```

Qgrep is installed manually using the same extract-and-chmod steps as macOS, using the "ubuntu" zip file. Telegram on Ubuntu uses `sudo snap install telegram-desktop`. On systems without Snap, the binary is downloaded from `https://desktop.telegram.org`, extracted, and run directly. The Tor Browser installation process changes often and should always follow the current instructions at `https://tb-manual.torproject.org/installation/`. FreeFileSync does not work well on ARM processors but is fine on typical Intel or AMD hardware.

## Windows Setup

Windows is described as risky and more complicated for breach data work. The experience is never as fluid as Linux or macOS. The package manager is **Chocolatey**, installed by first setting PowerShell execution policy to `AllSigned` and then running the Chocolatey install command from an elevated PowerShell prompt.

After Chocolatey is ready, Command Prompt (run as Administrator) handles all further installs:

```
choco install -y wget
choco install -y ripgrep
choco install -y sed
choco install -y awk
choco install -y curl
choco install unxutils
choco install -y freefilesync
choco install -y telegram
choco install transmission
chocolatey install jq
```

Qgrep is installed manually: the "windows-x64" zip is downloaded, `unzip` is installed via Chocolatey, and the binary is placed in `C:\users\%username%\Documents\Qgrep`. The Tor Browser executable is found at `https://tb-manual.torproject.org/installation/`.

## VPN: Purpose and Threat Model

The chapter makes a detailed case for using a VPN before conducting any of the described data work. Without a VPN, every website visited receives the user's home IP address. Six concrete threats follow from this.

1. **Internet activity logging**: an ISP can be subpoenaed to produce a log of every domain visited with dates and times.
2. **Search queries**: while HTTPS hides the content of searches from an ISP, any site lacking proper SSL exposes queries.
3. **Location disclosure**: a subpoena to an email provider like Gmail can yield the user's IP address at a specific time, and a second subpoena to the ISP converts that IP to a physical address.
4. **Fingerprinting**: websites record and track the unique IP address across visits and sessions.
5. **Download history**: firms monitoring torrent activity collect IP addresses and issue legal threats demanding payment.
6. **Breach data exposure**: breached databases almost always include the IP address of the user, which can be searched to link accounts or locate a home.

A VPN routes traffic through an encrypted tunnel to a remote server. The user's ISP sees only that a connection was made to the VPN. All subsequent traffic is encrypted. Websites see the VPN's shared IP address rather than the user's home address. The chapter stresses that VPNs provide privacy, not anonymity, and do not make a user untraceable.

## VPN Selection Criteria

The chapter recommends **Proton VPN** and explains the reasoning through eight criteria.

- **No Logging**: reputable VPNs claim to keep no logs of customer usage. PureVPN was caught surrendering logs under court order. Fast VPN was found storing user data indefinitely. Proton VPN has never had a known exposure of user logs. Policy details are at `https://protonvpn.com/support/no-logs-vpn`.
- **Audits**: third-party audits provide more confidence than self-reported policies. In April 2022 Proton VPN hired Securitum to audit logging practices. Audit results for all Proton products are published at `https://proton.me/blog/security-audit-all-proton-apps`.
- **Open Source**: publicly available source code allows external scrutiny, though it does not confirm that the live environment matches the published code. The chapter treats this as a useful but secondary factor.
- **Jurisdiction**: Proton VPN is based in Switzerland and responds only to Swiss court orders. The chapter cautions against over-relying on jurisdiction as a protection, noting that any country can cooperate with another and that a VPN cannot stop a determined government.
- **Ownership**: an independently owned VPN with a large user base is preferred over a brand owned by a VPN conglomerate.
- **Advertising**: many VPN review sites are paid placements or owned by VPN companies recommending their own products. These are ignored entirely.
- **Connection options**: multiple server locations in numerous countries are expected from any reputable provider.
- **Firewall compatibility**: the VPN should work within home firewall software. Proton VPN is confirmed to work well with pfSense and OpenVPN-based setups.

**Mullvad** is acknowledged as a respected option but is not recommended. Testing in late 2021 showed slow speeds and dropped connections. Testing in late 2022 showed problems maintaining OpenVPN connections within a firewall. Mullvad account numbers can also be brute-forced without a password.

## Payment for VPN Service

Paying with Bitcoin from an offline local wallet is the most private option, as it avoids creating a financial trail linked to the user's name. Proton VPN's Bitcoin payment instructions are at `https://protonvpn.com/support/vpn-bitcoin-payments`. Even with Bitcoin, the VPN provider sees the user's home IP address during the purchase session. The chapter concludes that paying by credit card is acceptable for most users because Proton VPN's no-logging policy means they cannot link a VPN IP address back to an account or a home address.

## Using the VPN

For daily use, the standard Proton VPN application (available at protonvpn.com for desktop and mobile) is recommended for most users. The author notes that at home a network-wide firewall with integrated VPN handles all traffic, so the VPN application is only launched when away from the home network. The chapter closes by directing readers to the next chapter on Terminal commands, which it describes as essential preparation for all later work on leaks, breaches, logs, and ransomware data.
