## Overview

This chapter (labeled Chapter 15 in the source text) explains why OSINT investigators need a virtual Android environment, how to build one using Android Studio, and what mobile applications it enables. A secondary section covers Genymotion as an alternative. The chapter's central argument is that a growing share of social network activity happens exclusively on mobile devices, so an investigator who works only from a web browser is increasingly blind.

## Why Android Emulation

Investigators need mobile access for three reasons.

First, some platforms, including Snapchat, Tinder, TikTok, and Kik, either refuse browser access entirely or restrict important features to their mobile apps. Second, documentation is easier from a desktop emulator: full-screen captures, video recording, and direct copy-paste into reports are all straightforward, whereas documenting findings from a physical phone is tedious. Third, conducting investigations from a personal or work phone exposes that device to forensic discovery, and any malware encountered can persist across future cases. An emulated device is isolated, so neither of those problems applies.

Emulation recreates the Android operating experience inside an application window. Like a Linux VM, nothing crosses in or out. Unlimited virtual devices can be created, one per investigation, preventing contamination between cases.

The chapter explicitly drops Genymotion and VirtualBox as primary recommendations. The stated reasons: Genymotion requires an account and tracks activity. Its free tier may violate terms of service in professional use. It depends on VirtualBox, adding complexity. VirtualBox does not support Apple M1 or later chips. Both tools only support x86 virtual machines, blocking native ARM builds. Many mobile apps specifically block Genymotion and VirtualBox environments. And native Android virtualization produces better results.

## Primary Method: Android Studio

Android Studio (developer.android.com/studio) is the tool Google built for Android developers. The chapter recommends it as the best OSINT virtualization option because it is cross-platform, free, requires no account, and provides native ARM virtualization on modern hardware.

### Installation

Install commands per platform:
- Linux: `sudo snap install android-studio`
- macOS: `brew install --cask android-studio`
- Windows: `choco install androidstudio`

### Initial Configuration

After launching Android Studio: decline importing settings, allow default downloads, choose "Don't Send" for analytics, select Standard installation, accept agreements, and click Finish. Then create a New Project, confirm "Empty Activity", name the project (the author used "OSINT"), and allow further downloads.

In the Device Manager panel, a default device such as Pixel_3a will appear. The chapter recommends adding a Pixel 6 Pro with the most recent API level. To make emulated devices launch in their own window rather than inside the developer portal, go to Tools, then Emulator, and disable "Launch in a tool window".

### Installing Apps Without a Google Account

The recommended approach avoids Google accounts entirely. After launching a device:

1. Open Chrome, search for F-Droid, download and install it. F-Droid is an open-source package installer for Android.
2. Inside F-Droid, search for and install Aurora Store. Aurora Store is an anonymous replacement for the Google Play Store that connects through a proxy.
3. Open Aurora Store, accept terms, grant all permissions, and select "Anonymous" login.
4. From Aurora Store, install any desired apps.

Apps the chapter lists as installed and moved to the home screen: Facebook, Messenger, WhatsApp, Instagram, X (Twitter), Snapchat, Kik, TikTok, TextNow, Truecaller, Bumble, Telegram, YouTube, Tinder.

If a VPN is active, Aurora Store may be blocked. The author notes having to connect to a dedicated VPN IP address to complete the connection during setup.

### Controlling the Emulator

The floating sidebar provides a home circle button, a back arrow, and a recent-apps square. Click-and-hold moves app icons. Swiping right or left navigates between home screens. Wi-Fi can drop without explanation. Re-enabling it under Settings restores connectivity. The power button on the floating bar turns the device off.

### Cloning and Managing Devices

In Device Manager, click the three-dot menu next to a device and choose "Duplicate" to create a clone. Cloning lets investigators start each case from a clean, pre-configured baseline without repeating setup. "Show on disk" reveals the machine folder for archiving. Devices can also be deleted from this menu.

### Launching Devices from the Terminal (macOS)

To bypass the full Android Studio GUI, navigate to the emulator directory:

```
cd ~/Library/Android/sdk/emulator/
./emulator -list-avds
```

This lists configured devices, for example `Pixel_6_Pro_API_33`. Launch options:

- Quick-boot, save changes: `./emulator -avd Pixel_6_Pro_API_33`
- Cold-boot, save changes: `./emulator -avd Pixel_6_Pro_API_33 -no-snapshot-load`
- Quick-boot, discard changes: `./emulator -avd Pixel_6_Pro_API_33 -no-snapshot-save`
- Wipe all custom data: `./emulator -avd Pixel_6_Pro_API_33 -wipe-data`

The author's standard use is the first command (quick-boot with saved state). A helper script with these options is published at https://inteltechniques.com/data/osintbook11/android.txt. The script presents a numbered menu to list devices or launch with various boot options.

### Location Spoofing

The extended controls, accessible through the three-dot menu at the bottom of the floating bar, include a Location tab. Setting coordinates there reports a fake location to any app that requests it. The chapter confirms accuracy by checking the Maps app. This matters most for location-aware apps such as Tinder.

## Applications and Investigation Techniques

### Facebook, Messenger, Instagram

The mobile app enables "Check In" to a location. After granting the emulator's spoofed location to Facebook, a posted check-in makes the investigator appear to have been at that location. The chapter describes using this to add credibility to a cover profile, and to mislead a subject who was tracking a victim's location by posting false check-ins from random places.

### WhatsApp

WhatsApp requires account creation with a telephone number (cellular, landline, or VOIP all work). Once configured, it allows direct messaging with targets who avoid standard SMS. Some targets who refuse normal text messages communicate freely over WhatsApp.

### X (Twitter)

Sharing the spoofed location through the mobile app makes the investigator appear to be somewhere else, useful for confusing a target who monitors the investigator's social media.

### Snapchat

Some Snapchat content is only visible within the mobile app. A browser-based approach for public posts is addressed elsewhere in the book, but the mobile app is necessary for full access.

### TikTok

The TikTok website does not support native keyword search. The mobile app does. The chapter recommends installing it during setup rather than later.

### TextNow

Because the virtual device has no cellular connection and no assigned phone number, it cannot send or receive SMS natively. TextNow provides SMS capability inside the emulator, so all communications and evidence stay within the virtual device archive.

### Truecaller

Truecaller performs reverse caller ID lookups for cellular and landline numbers and identifies the account owner. Mr. Number and Showcaller are mentioned as additional mobile-only options in this category.

### Tinder

Tinder uses location to show nearby users. The chapter describes setting the emulator's GPS to a target's home address and searching for that person's age and gender within one mile. If the target's profile appeared, it confirmed the person was near that location. The investigator could then try the work address or other locations until a match appeared, determining approximate whereabouts without leaving their own location.

### Contact Exploitation

Adding a target's phone number or email address to the Android virtual device's Contacts app causes many installed apps to treat the target as a known contact, bypassing restrictions that would otherwise block the connection between real details and connected profiles. This can surface:

- Associated Facebook accounts via "Find Friends"
- Google Play purchase history and reviews
- Associated X (Twitter) accounts via "Find Friends"
- WhatsApp usernames registered to the number

The chapter gives a Signal example: after registering Signal with a Google Voice number and adding a target's cellular number to Contacts, Signal confirmed the target was active on Signal, and opening a message compose window (without sending) revealed the name the target had registered.

CashApp is mentioned as another app that displays a complete profile when given a target's phone number.

### Secure Communications Apps

For covert contact with targets in sensitive investigations (the chapter mentions sex trafficking as an example), investigators should have Proton Mail and Wire installed in the virtual environment. These keep evidence contained in the VM and protect the host machine. The chapter also recommends creating multiple accounts through these providers and logging in only after cloning a clean machine.

## Alternative: Genymotion

Genymotion (genymotion.com) is covered as a secondary option for investigators who encounter problems with Android Studio. Some users report it feels faster and smoother on Windows. It works on Windows, macOS, and Linux, but not on newer Apple processors.

Setup requires a free account (alias information is acceptable). Download the "Personal Edition" from genymotion.com/download, choosing the version without VirtualBox if VirtualBox is already installed.

Inside Genymotion, create a device by selecting the highest Android API level available (10.0 at time of writing) and a device model such as Google Pixel XL. Rename the device (for example, "Android 10.0 Original"), set Android Version to the highest option, and click "Install".

Genymotion devices lack Google services by default. The built-in fix is to click "Open GAPPS" inside the virtual device, which redirects to opengapps.org. Select ARM64, the matching Android version, and "Stock", download the zip file, then drag and drop it onto the running device and restart. This installs the Google Play Store. A Google account (created in advance on a traditional computer, not inside the VM, because Google demands phone verification during creation) is then needed to access the store. If any app refuses to install because of device incompatibility, the F-Droid and Aurora Store technique from the Android Studio section can be replicated.

The GPS spoofing feature in Genymotion is available through the icons on the right column of the emulator window. Toggle it on, then enter coordinates directly or select a point on an interactive map. The chapter recommends setting altitude, accuracy, and bearing to 0. A green check mark confirms spoofing is active.

### Cloning in Genymotion (via VirtualBox)

Genymotion relies on VirtualBox internally. To clone a device: power it off completely, open VirtualBox, right-click the machine, and choose "Clone". Select "Full Clone" and "Current Machine State". The clone can be used for a specific investigation while the original remains untouched. The author keeps the original labeled (for example, "Android Original 9.0") and only opens it for updates, cloning for every active case.

### Exporting for Evidence

VirtualBox can export a virtual machine as a single appliance file via File, then Export Appliance. This file can be archived to DVD or flash media. Another investigator can import it using "Import Appliance" in the File menu, giving them an exact replica of the investigation environment. The chapter notes this is why a new virtual device per investigation matters: a clean environment is easy to archive and distribute as discovery.

## Other Emulation Options

BlueStacks (bluestacks.com) and Andy (andyroid.net) are mentioned as third-party alternatives offering similar functionality with added overhead. Both rely on VirtualBox internally. The chapter does not recommend them over Android Studio, which is described as the most native Android implementation.

## Closing Points

The chapter closes with the argument that OSINT collection is shifting toward mobile-only apps and that emulation is therefore required for thorough investigations. Practicing on non-essential apps and data is recommended before using these methods on real cases. Apps will sometimes block access from virtual devices as an anti-fraud measure, but the chapter treats occasional investigation success as worth the difficulties.
