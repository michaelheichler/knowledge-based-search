## Overview

This chapter explains how investigators can obtain, organize, and query publicly available stolen databases to advance OSINT investigations. The intended audience is security researchers and law enforcement, not criminals. The chapter draws a sharp ethical line: looking up information in leaked data is legal and legitimate, but using discovered credentials to access any account is illegal.

## Ethical and Legal Context

Two groups download breached databases. The first group consists of criminals who use credentials from one breach to try the same username and password on other services (credential stuffing). The second group consists of security researchers and investigators who protect the data from further distribution and use it only for defensive or investigative purposes. The chapter argues that criminal hackers already exploit this data daily (for example to "dox" law enforcement officers after high-profile incidents) and that investigators should use the same techniques against criminals. All instruction here is framed around offline analysis only.

## LinkedIn User ID Database

A version of the LinkedIn breach surfaced in 2017 containing only user ID numbers and associated email addresses, with no passwords. Because it contains no credentials, it was archived on the Wayback Machine. At the time of writing it could be downloaded from `https://archive.org/details/LIUsers.7z`.

After decompressing the file, a Ripgrep command searches for any email address or member ID:

```
rg -aFiN janewilson@microsoft.com linkedin_users.txt
# result: 1332567, janewilson@microsoft.com

rg -aFiN 1288635 linkedin_users.txt
# result: 1288635, John.h.007@gmail.com
```

The member ID can be found by viewing the source of a LinkedIn profile page and searching for the term "member:". This technique converts a known LinkedIn profile into a personal email address and vice versa. Member numbers only exist for accounts created before 2015.

## COMB (Compilation Of Many Breaches)

In 2021 an unknown group released "Compilation Of Many Breaches" (COMB), a dataset of 3.2 billion email address and password pairs drawn from many prior breaches (LinkedIn, Dropbox, Myspace, Adobe, and others). The file is titled `CompilationOfManyBreaches.7z` and is roughly 20 GB compressed, expanding to 106 GB. The archive password, as posted on Twitter by user @BubbaMustafa, is `+w/P3PRqQQoJ6g`. Decompression requires 7-zip (Linux/Windows) or Keka (Mac).

Finding the torrent via Google:
```
site:github.com "CompilationOfManyBreaches.7z"
site:github.com "1.4 billion"
```

COMB includes a native search script. From inside the COMB folder:

```
chmod +x query.sh
bash ./query.sh michael.bazzell@gmail.com
bash ./query.sh michael.bazzell          # partial match, returns all variants
```

The tool is case-sensitive and requires exact input. For domain-wide or password-based searches, the tool is too limited, so Ripgrep is used directly:

```
rg -aFiN mikewilson@microsoft.com         # exact email
rg -aFiN bigbucks55                       # search all files for a password
rg -aFiN @altonpolice.com                 # all credentials from a domain
```

Searching a discovered password reveals other accounts that reused it. Because many people reuse passwords across services, a work email and an unknown personal email often share the same password, connecting the two identities. The more unique the password, the more confidence the investigator can place in that connection.

A real case example: a federal child exploitation investigation located a suspect email address used under an alias. Querying the address in breach data revealed a unique password. Searching that password exposed one other account in the suspect's real name. An arrest followed the next day.

## RaidForums Databases

A torrent (introduced in a prior chapter covering voter data) contains 459 GB of databases originally hosted on RaidForums. The chapter focuses on three criminal-marketplace databases within it as demonstrations.

- **CrackingForum.com**: a single text file with plain-text email addresses and passwords for all 469,550 members.
- **CrackingItaly.com**: a single text file with member ID, full name, email address, hashed password, and IP address for all 18,132 members. Presence here confirms a suspect was a member of a criminal hacking community.
- **DemonForums.net**: a SQL file. Searching "mybb_users" in a text editor locates the user table. After removing surrounding content and cleaning formatting, the remaining 11,614 lines of user data are queryable by username and email.

## Telegram as a Breach Source

Telegram channels distribute breach data freely and are searchable without spending forum credits. Recommended channels include "We Leak Database", "LEAKS AGGREGATOR", "DataLeak", "Open Leak", and "Leakbase Official". A curated list of additional channels is maintained at `https://github.com/fastfire/deepdarkCTI/blob/main/telegram.md`. When a breach appears for sale on a site such as BreachForums.is, searching the relevant keyword on Telegram often yields a free download. The "DataLeak" channel was shut down around April 2024, illustrating how quickly these resources disappear.

Demonstrations in the chapter: a "USA Payday Loans" dataset (1 million records) found by searching "Payday" in Telegram, a "250 Million USA Huge Leak" (250,807,711 records) found by searching "250 million", and the Fotolog breach found by searching "Fotolog". In each case the data matched what was being sold on forum sites but was available at no cost on Telegram.

Searching ".sql" in Telegram also yields recently breached SQL database files.

## Finding Breach Data via Google SQL Queries

Google can surface publicly exposed SQL database files. A progression of operators narrows results:

1. `ext:sql "create table"` (26,300 results, filters to actual SQL files)
2. `ext:sql "create table" "@gmail.com"` (5,160 results, indicates real user data)
3. `ext:sql "create table" "@gmail.com" "'password'"` (3,060 results, adds a password table)
4. `ext:sql "create table" "gmail.com" "'password'" "@yahoo.com" -site:github.com` (67 results, multiple email domains, no test repos)

A SQL user record typically contains: user ID, username, email address, hashed password, registration date, last visit date, and sometimes IP address. The same approach applies to text files: `ext:txt "create table" "gmail.com" "'password'" "yahoo.com" -site:github.com`. To find a specific known breach, the pattern is: `"myspace" ext:rar OR ext:zip OR ext:7z OR ext:txt OR ext:sql`.

Security note: when browsing these sites or downloading data, trackers, viruses, and malicious software are common. A macOS or Linux machine combined with a reputable VPN provides meaningful protection.

## Hashes

Most websites store passwords in hashed form. Hashing is a one-way transformation that converts a plain-text password into a fixed-length string. Common hash algorithms:

- **MD5**: insecure, cracks quickly. Hash of "password1234": `BDC87B9C894DA5168059E00EBFFB9077`
- **SHA1**: slightly more secure but still easy to crack. Hash of "password1234": `E6B6AFBD6D76BB5D2041542D7D2E3FAC5BB05593`. LinkedIn passwords were stored in SHA1.
- **SHA256**: hash of "password1234": `B9C950640E1B3740E98ACB93E669C65766F6670DD1609BA91FF41052BA48C6F3`
- **SHA512**: much longer, far harder to crack.
- **BCRYPT**: used in more recent breaches, difficult to crack without dedicated hardware.

A "salt" is a small piece of extra data incorporated into the hash. If the breach includes the salt, cracking becomes harder but remains possible with enough resources. If the salt is absent, cracking with standard tools is effectively impossible.

In older breached databases, MD5 and SHA1 are most common. Recent breaches tend to use BCRYPT or SHA512.

## Hashes.org Archive

The site Hashes.org (offline since late 2020) maintained billions of pre-cracked hash-to-password mappings. Its entire archive is available as a 90 GB compressed torrent, linked from:

- `https://pastebin.com/pS5AQNV0`
- `https://old.reddit.com/r/DataHoarder/comments/ohlcye/hashesorg_archives_of_all_cracked_hash_lists_up`

After decompression, the archive contains two folders: "Hashlists" and "Leaks". Files in the Leaks folder are named by breach source and algorithm, for example `20_casio-com_found_hash_algorithm_plain.txt`. Each line pairs a hash with its plain-text password:

```
MD5 00747af6279313863a0319070bdbfb80:168130
```

The workflow: find a hashed password in a breach, identify its algorithm using TunnelsUp (tunnelsup.com/hash-analyzer), then search the hash against the archive with Ripgrep:

```
rg -aFiN 14FDF540E39F0F154C8D0B3BD82ACE100B779DFA
```

Results reveal the plain-text password and which specific breaches contained it. If the same password appears in those breaches and connects to the target's known email, that is a strong investigative lead. If the plain-text password was already known (from COMB, for example), searching the password directly finds breach source files:

```
rg -aFiN verybad1234
# returns: Leaks/713_forums-nodoubt-com_found_hash_algorithm_plain.txt.zip MYSQL5 887b0eb...:verybad1234
```

## HashMob

HashMob (hashmob.net) is the active successor to Hashes.org. The "Official lists" section offers free downloads without registration. Files are named by breach ID and hash type, for example `330.3200.found` for breach 330 using bcrypt. Each line follows `hash:password` format. Looking up breach ID 330 on the HashMob API at `https://hashmob.net/api/v2/hashlist/official` shows it is from a breach at Zildjian.ru. The download command:

```
wget --content-disposition -i https://inteltechniques.com/data/hashlists.txt
```

Warning: the result is 90 GB. A paid HashMob account allows real-time API queries without maintaining a local archive, updated daily.

## MD5 and Salted Hash Examples

For plain MD5 hashes found in a breach:
```
174@gmail.com:482C811DA5D5B4BC6D497FFA98491E38
# resolves to: password123

185@gmail.com:22F4182AAE2784FB3D1A432D44F07F46
# resolves to: reader12
```

For MD5 with salt (common in Vbulletin forums), both the hash and salt are required. The salt follows the hash after a second colon:
```
menball@aol.com:9d9e3c372d054c0769bd93181240be36:tye
# resolves to: eliza!%
```

For SHA1 hashes, the same rg search against the archive applies. Two passwords that differ only in case produce completely different SHA1 hashes, so case matters:
```
403E35A2B0243D40400AF6BB358B5C546CDDD981:letmein!
B1C4BBC4D7546529895CFABF8C1139CA7E486E18:LetMeIn!
```

## Name That Hash and Search That Hash

Name That Hash and Search That Hash (github.com/HashPals/) are preferred over single-purpose online tools. Installation:

```
sudo pip install -U search-that-hash
sudo pip install -U name-that-hash
```

Usage:
```
sth --text "5f4dcc3b5aa765d61d8327deb882cf99"
# result: Text: password, Type: MD5

nth --text "5f4dcc3b5aa765d61d8327deb882cf99"
# result: Most Likely MD5, HC: 0 JtR: raw-md5
```

Other online resources for MD5 and SHA1 lookup (limited to simple passwords in their dictionaries): osint.sh/md5, md5decrypt.net, md5online.org, dcode.fr/sha1-hash, md5hashing.net.

## Cit0day Collection

In 2020, a criminal marketplace called Cit0day.in displayed a law enforcement seizure notice and simultaneously released 23,618 hacked databases (226 million credentials) for free. The seizure is widely considered fake. The data is searchable on Telegram by querying "cit0day" (with a zero replacing the letter O) for the channel "cit0day collection in tg". The full collection downloads as three compressed files titled "Full Clouds Cit0day_2", expands to a 9.1 GB 7z archive, and decompresses to a 30 GB folder of 72,780 files.

Each breach folder typically contains: a main hash file (most important), a "Result.txt" or "decrypted" file (plain-text passwords worth keeping), and redundant files (NotFound.txt, Rejected.txt, Result(HEX).txt) that can be discarded.

Cleaning commands:
```bash
cd ~/Downloads/Telegram\ Desktop/Cit0day_RF/Data/

find . -iname 'Rejected.txt' -delete
find . -iname 'NotFound.txt' -delete
find . -iname 'Result(HEX).txt' -delete
find . -iname '*not found*.txt' -delete
find . -iname '*final*.txt' -delete

find . -iname '*result*' -exec cat {} \; > Pass1.txt
find . -iname '*decrypt*' -exec cat {} \; > Pass2.txt
find . -name '*no hash*' -exec cat {} \; > Pass3.txt
find . -iname '*result*' -delete
find . -iname '*decrypt*' -delete
find . -name '*no hash*' -delete
cat Pass1.txt Pass2.txt Pass3.txt > Cit0DayPass.txt
rm Pass1.txt Pass2.txt Pass3.txt
```

Renaming files to strip brackets and parentheses (requires `rename`, installed via `brew install rename` or `sudo apt install rename`):
```bash
find . -type f -execdir rename 's/\{[^\}]+\}//g;s/<[^<]+>//g;s/\[[^\]]+\]//g;s/\([^\)]+\)//g' {} \;
```

Moving all files to a single Databases folder:
```bash
mkdir /Volumes/DATA/Databases/
find . -type f -name '*.txt' -execdir mv {} /Volumes/DATA/Databases/ \;
rename "s/ //g" *
```

The result is 22,762 text files at 20.37 GB (down from 30 GB). A line count (`find . -name '*.txt' | xargs wc -l`) reveals approximately 50 million actual credentials, far less than the reported 226 million, which was inflated by redundant data. Media-reported credential counts often include duplicate data. Running your own line count gives a more accurate figure.

A query for a target email in this cleaned collection:
```bash
rg -aFiN test9876@gmail.com
# result from original breach file: test9876@gmail.com:ef5381e56a457e62bf22976b5b4f4f8f
# result from Cit0DayPass.txt: test9876@gmail.com:mypassword
```

Archive.org hosts a number of breach dumps. Searching for "nulled.io" on Archive.org leads to the `nulled.io_database_dump`, a 10 GB database from the Nulled hacking forum uploaded by user "ntgrg". Clicking that profile reveals other similar uploads.

## DogForum.sk and EscortReviews.com Examples

Two small examples from the "Guron" torrent (241 GB compressed, about 1 TB decompressed, 1,315 breach databases from 2016 to 2021) illustrate what breach SQL files contain.

**DogForum.sk** (17,000 users, stolen January 13, 2021): each record in the phpbb3_users table includes user number, IP address at registration, UNIX registration timestamp, username, hashed password, password change timestamp, email address, date of birth, last visit timestamp, and time zone. UNIX timestamps convert to readable dates (for example, 1275503507 = June 2, 2010 18:31:47 GMT). The time zone field (+3) can indicate geographic region.

**EscortReviews.com** (470,000 users, stolen January 27, 2021): each record in the user table includes user ID, username, MD5 password hash, password change date, email address, personal website, join and last visit timestamps, date of birth, and IP address. Running the MD5 hash through Search-That-Hash reveals the plain-text password ("escorts" in the fictitious example, a weak password). This site was used for prostitution, making it relevant for human trafficking investigations.

SQL files can be trimmed with `cut` and `sed` to reduce size:
```bash
cut -d, -f1,6,7,8,10,11,13,15,16,29 dogforum.sk.sql > DogForum.txt
```
This reduced a 12.5 MB file to 2.4 MB.

## Password Uniqueness Check

Before treating a discovered password as a strong lead, check its commonality at haveibeenpwned.com/Passwords. "escorts" appeared in 847 breaches (no investigative value). "escorts!" appeared in only one breach (high-confidence pivot). A unique, complex password creates a much stronger link between accounts.

## H8Mail

H8Mail (github.com/khast3x/h8mail) aggregates many breach services into one command-line tool:
```bash
sudo pip install -U h8mail
cd ~/Downloads
h8mail -g
sed -i 's/\;leak\-lookup\_pub/leak\-lookup\_pub/gI' h8mail_config.ini
h8mail -t bill@microsoft.com
```

Without API keys the tool returns minimal results. With keys from Snusbase, Leak-Lookup, HaveIBeenPwned, Emailrep, Dehashed, or Hunterio, results expand significantly. The configuration file `h8mail_config.ini` uses semicolons to comment out unused services. The `sed` command above pre-enables the free Leak-Lookup public key (`1bf94ff907f68d511de9a610a6ff9263`). A search of test@email.com with this key alone returned 172 results spanning TicketFly, TrueFire, and Tumblr.

## Sample Investigation Walkthrough

Target email: `johndoe1287@gmail.com` (suspected burner account used for harassment, no presence found online).

1. Query all collected databases: `rg -aFiN johndoe1287@gmail.com` returns `johndoe1287@gmail.com:H8teful0ne45`
2. Search the password: `rg -aFiN H8teful0ne45` returns three accounts with similar names and the same password, suggesting a common owner (johndoe@gmail.com, johndoe1287@hotmail.com).
3. Convert the password to hashes using passwordsgenerator.net (MD5, SHA1, SHA256).
4. Search each hash: `rg -aFiN D15FB15C1BC88F4B7932FD29918D1E9E9BBE7CA5` returns a hit from a Houston Astros forum breach, placing a user with that password on that site.
5. The variant spelling "H8teful" combined with "johndoe" across multiple accounts and the hash hit increases confidence that all accounts belong to the same person.
6. Next step: search each newly identified email through the same workflow and through online breach services.

Password-to-hash conversion for step 3 uses:
```
https://passwordsgenerator.net/md5-hash-generator/
https://passwordsgenerator.net/sha1-hash-generator/
https://passwordsgenerator.net/sha256-hash-generator/
```

## IntelTechniques Breaches and Leaks Tool

The custom tool at `https://inteltechniques.com/tools/Breaches.html` consolidates all the online search options from this chapter into a single interface. It accepts email addresses, usernames, domains, phone numbers, IP addresses, names, passwords, and hashes. It also generates MD5, SHA1, and SHA256 hashes from a plain-text password for immediate further research.

## Key Principles

Breach data (COMB, RaidForums databases, Cit0day, individual SQL dumps) is described as the most productive source in online investigations, outperforming social media. The core investigative loop: find a target email, discover a password, search that password to find other accounts, convert the password to common hashes and search those, then repeat with each new email or account discovered. Password uniqueness determines how much confidence to place in any connection. Investigators must never attempt to log in to any account with recovered credentials and must never allow obtained data to be further distributed.
