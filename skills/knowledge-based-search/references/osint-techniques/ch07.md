## Overview

Chapter 1 makes the case that virtual machines (VMs) running Linux are the correct environment for OSINT investigations. It argues from contamination risk, legal defensibility, and practical security, then traces the history of the authors' custom OSINT VM project (Buscador) and explains why investigators should now build and maintain their own VMs instead of relying on third-party builds.

## The contamination problem

Any computer used for general work accumulates tracking cookies, browser history, cached data, malware, and artifacts from previous investigations. If evidence collected on such a machine enters legal proceedings, a forensic expert can challenge its integrity. Screen captures may contain unrelated artifacts that compromise a case. The chapter uses an active prosecution as an example: when a defense team sought access to the investigator's full computer, the investigator was able to limit disclosure to a 4 GB VM file rather than a full hard-drive clone, because the entire online investigation had been conducted inside an isolated VM.

## What virtual machines are and why they solve the problem

A VM is an operating system running on top of another operating system through a software layer. Each VM is fully isolated from the host OS and from every other VM on the same machine. Deleting a VM removes all activity, cookies, viruses, and evidence tied to that session. A clean clone can be spun up in minutes. Because malicious code almost universally targets Windows, using Linux as the investigation OS also greatly reduces infection risk.

The chapter recommends one VM per case. This approach protects the host OS from infection, prevents cross-contamination between cases, and preserves the integrity of past and future investigations. If a copy of the investigative environment is ever required by a court (motion of discovery), a saved VM state can be produced cleanly.

## Buscador

In 2016, Michael Bazzell was contacted by David Westcott, who had experience distributing custom Linux builds. Together they designed a purpose-built OSINT virtual machine released in 2017 under the name Buscador (Spanish for "Seeker"). Buscador was modeled on the philosophy behind security distributions such as Kali Linux but oriented entirely toward OSINT work.

Its key design goal was removing the barrier between power users and non-technical investigators. On standard Linux, most tools require launching a Terminal and typing exact commands. Buscador gave every included tool its own clickable icon in a Dock. Clicking an icon walked the user through menus, collected required inputs, executed the underlying commands behind the scenes, and returned results directly to the user. Web browsers were pre-configured with custom settings and extensions, and OSINT applications were pre-configured to accept queries immediately.

## Why Buscador is no longer recommended

The chapter states clearly that the authors' views on pre-built VMs have changed. Buscador is no longer updated and has received no security patches since 2019. The online repository for application updates no longer functions. Users running it encounter errors from outdated applications, and most lack the knowledge to apply fixes themselves. The download link has been removed from the authors' site. The ease-of-use design that made Buscador appealing also meant users depended on the authors for maintenance they can no longer provide.

## The book's goal

The chapter describes the book's purpose as teaching the reader to build and maintain their own OSINT Linux VM from scratch, achieving the same usability as Buscador through custom scripts. The reader will install and test OSINT applications, write scripts to simplify daily use, archive investigative work, and be able to explain every step taken. The authors argue that building your own VM means you can replicate it, update it, and account for every action taken inside it.

The chapter closes by noting that the following six chapters are divided by host operating system (macOS, Linux, Windows), presented in that order of recommendation, with macOS first. Whatever host OS is used, all remaining guidance in the book applies equally.
