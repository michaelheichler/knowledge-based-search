This chapter covers the configuration of a Linux host machine for OSINT work. The author considers a Linux host running a Linux VM the most reliable setup, producing fewer software errors than macOS or Windows equivalents.

## Complete System Wipe with Ventoy

Rather than using embedded reset functions, the author reinstalls Linux from a bootable USB drive prepared with Ventoy (https://github.com/ventoy/Ventoy/releases). Ventoy formats a drive so that multiple ISO files placed at the root are all selectable at boot, without any per-ISO configuration. The recommended hardware is a SanDisk Extreme Portable 1TB USB SSD, which boots live systems without delay and also serves as a fast file-transfer drive.

Installation steps:

1. Download the Linux Ventoy archive (e.g., `ventoy-1.0.79-linux.tar.gz`) and decompress it.
2. Open Terminal, navigate to the extracted folder, and run `./VentoyGUI.x86_64`.
3. Select the USB device and click Install (this overwrites all existing data on the device).
4. Copy desired ISO files (e.g., Debian) to the root of the drive.
5. Reboot, select the USB boot option in BIOS, and choose the target OS.

The remaining space on the ExFAT partition can hold arbitrary data alongside the ISO files.

## Antivirus with ClamAV

The author recommends ClamAV on Linux hosts primarily for evidentiary reasons. If OSINT work is reviewed in court, the absence of antivirus software may be challenged by opposing counsel even though Linux faces minimal virus risk. ClamAV is more likely to detect Windows-targeted viruses (for example, malicious email attachments) than Linux-targeted ones, but having it installed and scheduled allows the investigator to testify to running security software without qualification.

Install and update:

```
sudo apt update
sudo apt install -y clamav clamav-daemon
sudo systemctl stop clamav-freshclam
sudo freshclam
sudo systemctl start clamav-freshclam
```

Scan commands:

```
clamscan -r -i /          # report only, no deletion
clamscan -r -i --remove=yes /   # report and delete infected files
```

The first scan (report only) should always be run before the destructive version. False positives occur and should be researched online before acting.

## Telemetry Removal

Ubuntu installs telemetry-related packages by default. The following command removes them:

```
sudo apt purge -y apport apport-symptoms ubuntu-report whoopsie
sudo apt autoremove -y
```

The author states this is safe to run on other Debian-based systems as well.

## System Cleaner: BleachBit

The author recommends BleachBit for weekly cleaning. Install it with:

```
sudo apt install bleachbit
```

The application offers two launchers in the Dock. The second runs with administrative privileges and is the preferred option. On first launch, dismiss the configuration dialog, select all options except "Free disk space," preview the recommended cleaning, then execute it.

## Full-Disk Encryption

Full-disk encryption is recommended for any Linux host, but not for Linux VMs. Some distributions such as Pop!_OS enable it by default. Ubuntu exposes it through the "Advanced Features" option during installation. Selecting "Use LVM with the new Ubuntu installation" together with "Encrypt the new Ubuntu installation for security" enables disk encryption and prompts for an encryption passphrase.

## VPN Configuration with Proton VPN

VPNs route traffic through an encrypted tunnel to a distant server, preventing local network observers from reading traffic and preventing target websites from seeing the investigator's true IP address or organization. The author distinguishes privacy from anonymity: a VPN provides the former, not the latter.

The recommended provider is Proton VPN. Its Linux application is open-source, which makes hidden malicious code harder to introduce. The author's policy is to remain connected to Proton VPN at all times when on the Linux device. VMs running on that host share the same VPN IP address. When traveling, Proton VPN runs as an application on the laptop. At home, a VPN-capable firewall handles the tunneling so no per-device VPN application is needed (covered in the companion book "Extreme Privacy: VPNs & Firewalls"). The author pays for the VPN subscription with Bitcoin under an alias.

Installation follows Proton VPN's official Debian instructions at https://protonvpn.com/support/official-linux-vpn-debian.

## Password Manager: KeePassXC

OSINT investigators accumulate many covert accounts across services. The author recommends KeePassXC, an open-source, offline password manager that stores credentials in an encrypted local database and never synchronizes to the internet. It is cross-platform (Linux, macOS, Windows). The database should live on the host machine rather than inside any VM, so it remains accessible regardless of which VM is active and is not lost when a VM is rebuilt.

Install on Debian-based systems:

```
sudo add-apt-repository ppa:phoerious/keepassxc
sudo apt update && sudo apt install keepassxc
```

Setup procedure:

1. Open KeePassXC and create a new database with "Database > New Database."
2. Name the database, move the encryption settings slider to maximum, and set a strong master password (unique, never used elsewhere, written down until memorized).
3. Save the database to a chosen location, then verify it opens with the master password.

To manage a covert account entry (using a Facebook profile as the example):

1. Create a group named after the service.
2. Add a new entry with the account name, username, and URL.
3. Use the password generator (dice icon) to create a password of at least 40 characters (50 if the site allows it), verify it via the eyeball icon, and apply it.
4. Change the actual account password to the generated value.

Generated passwords are random strings of letters, numbers, and special characters. They are not memorized. They are copied from the manager at login. Using a unique password per site means a breach of one site does not expose other accounts or reveal the investigator's true identity through password reuse.

A backup of the database file should be kept on an encrypted USB drive, never on the internet, so that a system failure does not destroy all stored credentials.

The author no longer recommends the KeePassXC browser extension for OSINT work. It is not insecure, but using it would require copying the master database into VMs, which creates unnecessary links between investigations. Keeping the database only on the host eliminates that risk.
