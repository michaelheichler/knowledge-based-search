## Overview

This chapter explains how to configure a macOS machine as a clean, secure host for OSINT investigations conducted entirely through virtual machines. The author prefers macOS with Apple Silicon over Windows or Linux hosts because of speed, low power consumption, and the quality of the UTM virtualization application for ARM-based machines. No investigation activity happens directly within macOS. The host only runs VMs.

## Hardware Selection

The author recommends current MacBook Pro models with M-series (M1, M2, or M3) ARM-based processors. The 14" MacBook Pro is considered the best combination of value and productivity. M1 and M2 machines are sufficient for OSINT work. M3 adds longevity. The "Pro" processor variant is recommended over the standard chip for the additional CPU and GPU cores, while the "Max" is unnecessary for most users. Recommended configuration: 32 GB of RAM, at least 512 GB of storage (1 TB preferred), with external drives as a more affordable alternative to large built-in storage upgrades.

## Fresh macOS Installation

Before any configuration, the author recommends formatting the drive and installing a clean copy of macOS regardless of the machine's prior history. On macOS Sonoma, this is done through System Settings > General > Transfer or Reset > Erase All Content and Settings. The process requires entering the system password and confirming all warnings. Older macOS versions (Ventura, Monterey, Big Sur) offer equivalent reset options through the Erase Assistant or Recovery mode.

## Initial Setup: Privacy-First Configuration

During first launch, the author advises the following choices to minimize data exposure:

- Skip internet connection during setup when possible.
- Skip the Apple ID step entirely and confirm with "Skip". The machine should never be associated with an Apple ID.
- Create a local account with a generic name (for example, "Laptop" or "Computer") and a strong password with no hint.
- Disable Location Services, Siri, Screen Time, and all analytics options during setup.

After setup, within System Settings:

- Disable Wi-Fi and Bluetooth, and disable "Ask to join networks" and "Ask to join hotspots".
- Enable the macOS Firewall. Disable "Automatically allow built-in software to receive incoming connections" and "Automatically allow downloaded signed software to receive incoming connections". Enable Stealth mode.
- Under Privacy and Security, disable all Analytics and Improvements options and disable Personalized Ads.
- Disable automatic software update options.

## Full-Disk Encryption with FileVault

The author describes enabling FileVault as the most important step in the chapter. Without it, forensic equipment with physical access to the machine can extract data. The steps are: System Settings > Privacy and Security > Turn On FileVault, then choose "Create a recovery key and do not use my iCloud account". The recovery key must be saved somewhere safe. FileVault then encrypts the entire drive.

## Finder and Hidden Files

macOS hides files and folders such as the Library directory by default. Pressing Shift + Command + Period (.) in Finder toggles visibility of hidden files. The author also adjusts Finder settings (General, Tags, Sidebar, Advanced tabs) to match personal preferences. Additionally, the Dock is configured to hide suggested and recent apps, and the lock screen is set to require a password immediately upon display sleep or lid close.

## Encrypted External Drives

External USB drives should be encrypted before use for macOS host backups. The method requires Disk Utility. The key steps are: select "Show All Devices" under the View menu, select the physical device (not the volume), click Erase, change the Scheme to "GUID Partition Map", and then select "APFS (Encrypted)" as the format. This option is only suitable for drives accessed exclusively from macOS. Drives intended for use inside a Linux VM should not use this method.

## Rosetta

Rosetta is Apple software that allows applications built for Intel x86 chips to run on ARM-based M-series machines. The author recommends confirming it is installed with the Terminal command:

```
softwareupdate --install-rosetta --agree-to-license
```

## Antivirus and Antimalware

The author advises against free commercial antivirus products (Avast, Kaspersky, and similar). Instead, three open-source tools are recommended, none running continuously in the background. The rationale includes legal defensibility: if an investigation is challenged in court, the investigator can state that the machine was scanned and clean.

All three are installed through Homebrew (brew.sh). Homebrew is installed by pasting the following into Terminal:

```
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
```

After installation, run `brew doctor`, `brew update`, `brew upgrade`, and `brew analytics off` to confirm configuration and disable Homebrew's usage metrics.

**Task Explorer** (objective-see.com/products/taskexplorer.html): Checks all running processes against VirusTotal and flags suspicious files with a red indicator. Does not remove infections. Install:

```
brew install --cask taskexplorer
```

**KnockKnock** (objective-see.com/products/knockknock.html): Scans for persistent programs set to launch at boot, which is a common behavior of malware. Does not remove infections. Install:

```
brew install --cask knockknock
```

**ClamAV** (clamav.net): An open-source, community-driven antivirus database. It runs only on demand and does not operate continuously. It does not remove viruses by default but reports the presence and location of suspicious files. In practice it has identified Windows-targeted malware present as email attachments on macOS machines, which is useful for protecting Windows VMs. Install and configure:

```
brew install clamav
sudo mkdir /usr/local/sbin
sudo chown -R `whoami`:admin /usr/local/sbin
brew link clamav
cd /opt/homebrew/etc/clamav/
cp freshclam.conf.sample freshclam.conf
sed -ie 's/^Example/#Example/g' freshclam.conf
```

Update the virus database and scan:

```
freshclam -v
clamscan -r -i /
```

To scan and automatically remove found files (use with caution, may remove legitimate files):

```
clamscan -i -r --remove=yes /
```

The author recommends running Task Explorer and KnockKnock weekly. ClamAV full scans take hours but are recommended for government investigators who may need to report the machine's status in court.

## Telemetry

macOS collects and transmits telemetry data. A software firewall such as Little Snitch (paid) or LuLu (free) can block this. However, because all investigation activity occurs inside VMs and firewall apps cannot intercept traffic within VMs, a software firewall on the macOS host is less critical for investigators who rely exclusively on VMs. More detail is provided in the author's separate macOS privacy guide.

## VPN Configuration

A VPN routes traffic through an encrypted tunnel to a remote server, hiding the user's true IP address and location from visited websites. The author recommends Proton VPN as a paid, open-source provider. Free VPN providers are discouraged because they often monetize through data aggregation. Install:

```
brew install --cask protonvpn
```

The author's policy is to connect through Proton VPN whenever the macOS device is on the internet. VMs running on the host share the same VPN IP address. At home, VPN protection is handled at the router or firewall level rather than within the laptop itself. The author pays for Proton VPN with Bitcoin under an alias name but acknowledges this may be unnecessary for most readers.

## Password Manager

The author recommends KeePassXC, an open-source, offline, cross-platform password manager (Mac, Windows, Linux), installed on the macOS host rather than inside any VM. Because VMs may be deleted, rebuilt, or exported, storing credentials inside them is risky. Keeping the password database on the host ensures access across all VMs. Install:

```
brew install --cask keepassxc
```

Setup involves creating a new database, moving the encryption strength slider to maximum, and assigning a strong unique master password. The database file should be backed up to an encrypted USB drive.

For covert investigation accounts, KeePassXC generates random passwords at a recommended length of at least 40 to 50 characters when the site permits. Passwords are copied and pasted from the manager at login. This ensures that a breach of any one site does not expose credentials elsewhere. The master password must be memorized and never reused. The author no longer recommends the KeePassXC browser extension for OSINT work because it creates unnecessary connections between sessions inside VMs.

## Summary

After completing this chapter, the macOS device functions as a clean, encrypted, VPN-protected, malware-monitored host with a local account (no Apple ID), full-disk encryption via FileVault, hardened firewall settings, and an offline password manager. All actual investigation activity takes place inside virtual machines, keeping the host operating system isolated from investigative exposure.
