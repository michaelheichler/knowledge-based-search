title: OSINT VM Automated Build
source: OSINT Techniques (Bazzell, Edison, 11th ed.)
---

This chapter (labeled Chapter 14 in the book) presents a single automated script that reproduces the entire OSINT virtual machine built manually throughout the preceding chapters.

## The Script

The chapter opens with the core command:

```
wget https://uvm:317@inteltechniques.com/osintvm/install.sh && chmod +x install.sh && ./install.sh
```

This command downloads a script called `install.sh` from the authors' server (authenticated with the credentials `uvm:317`), marks it executable, and runs it. The script carries out every Linux configuration step, software installation, download, and customization described in the book starting from "Debian Customization" in Chapter Eight. The user is prompted once for a password and once for a dialogue confirmation. Everything else runs unattended. Firefox and Tor Browser launch and close automatically during the process. On a suitable base VM the whole build completes in roughly 15 minutes.

## How to Use It

The intended starting point is the Debian Stock VM described earlier in the book. The reader creates a fresh clone of that stock VM, opens a Terminal, and enters the command above. The result is a fully configured OSINT VM identical to the one built manually throughout the book.

The script file is saved to the Home folder of the Debian install after download, and its contents mirror the manual commands from the book, executing each line in sequence.

## Why It Appears at the End

The chapter explains why the script was not introduced at the beginning of the book. The authors' position is that manually building the VM is educationally valuable in itself. Understanding each configuration step matters more than possessing the finished product. Providing the script first would let readers skip that learning. The script is described as "cheating" in that sense.

At the same time, the chapter acknowledges legitimate uses for the script: quickly spinning up an additional OSINT VM, or returning to the book a year later and applying all updates made to the script since publication. Because the authors can update the script on their end, running it against a fresh stock VM always applies the current version of every tool and setting.

## Limitations and Fallback

Running a script rather than executing commands manually means errors during execution are easy to miss. If the script fails on a particular VM, the chapter instructs the reader to fall back to the manual methods to identify and fix the problem. The authors encourage readers to attempt the manual process first and use the script only once they are confident in their ability to build the VM by hand.
