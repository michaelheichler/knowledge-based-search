## Overview

This chapter covers routine care of the OSINT Linux virtual machine (VM) environment after initial setup. It assumes the reader has two VMs: "Debian Stock" (a clean Debian install) and "OSINT VM" (fully configured for investigations). The three maintenance tasks are updating, shrinking, and cloning or exporting. The chapter also covers optional alternative desktop environments.

## Updates

The OSINT VM should be launched weekly and updated using the Updates Tool script from the Dock, which applies all system and application updates. The Debian Stock VM should be updated monthly by running `sudo apt update && sudo apt upgrade` in Terminal. Keeping both current ensures the stock VM is ready to serve as a rebuild source at any time.

## Shrinking

VM disk files grow over time because even deleted and updated content is preserved in underlying storage. Shrinking recovers that wasted space. The chapter covers three hypervisors.

**UTM (macOS).** With the OSINT VM shut down, select it in the UTM main window, open its Settings, choose the VirtIO drive, click "Reclaim Space," confirm, and save. This should be done after every update.

**VirtualBox.** The process requires two stages. First, inside the running VM, empty the trash and run `dd if=/dev/zero of=zerofillfile bs=1M` in Terminal. This fills free space with zeros so the compaction step can detect and remove it. Then, with the VM shut off, open Terminal on the Linux or Windows host, navigate to the VM folder (for example, `cd ~/VirtualBox\ VMs/OSINT\ VM/`), and run `VBoxManage modifymedium disk OSINT\ VM.vdi --compact`. The `.vdi` file shrinks if free space was available.

**VMware Workstation Pro.** With the VM shut down, select it, go to VM > Settings, choose the hard disk, and click "Compact Disk."

## Cloning

Investigations should always be conducted in a clone of the OSINT VM, never in the original, so the configured master remains uncontaminated. Clones are named with a date such as "OSINT VM 2024.02.01" to track when they were made.

**UTM.** With the VM shut down and its window closed, click the "Clone selected VM" icon (two overlapping documents) in the upper-right of the main UTM window. Confirm the operation, right-click the new clone, select Edit, rename it, and save.

**VirtualBox.** With the VM shut down, right-click the OSINT VM, select "Clone," provide a name, click Next, and click Clone. Each clone gets its own data folder.

**VMware Workstation Pro.** With the VM shut down, right-click the OSINT VM, select Manage > Clone, click Next three times, provide a name, click Next, then Finish.

## Exporting

Exporting produces a portable copy of the VM for archiving, sharing, or off-site backup.

**UTM.** Use the "Share Selected VM" option to export the VM as a `.utm` file. Choose the destination folder in the dialogue and save.

**VirtualBox.** Two methods are available. The simpler option is to right-click the shut-down VM, select "Show in File Manager," and copy the VM folder to an external drive. The alternative is File > Export Appliance, selecting the VM and clicking through Next twice then Export to produce a single appliance file importable into any VirtualBox instance.

**VMware Workstation Pro.** Right-click the shut-down VM, select "Open VM Directory," and copy the entire folder to another location.

## Alternative Desktop Environments

The book uses Gnome as the default desktop environment because all tutorials are tuned for it. Other environments can be installed from Terminal:

- Cinnamon: `sudo apt install task-cinnamon-desktop -y`
- KDE Plasma: `sudo apt install task-kde-desktop -y` (press Enter twice during install)
- LXDE: `sudo apt install task-lxde-desktop -y`
- LXQt: `sudo apt install task-lxqt-desktop -y`
- MATE: `sudo apt install task-mate-desktop -y`

After installing an alternative, log out, click the username, click the settings icon at the lower right before entering the password, and select the desired environment. Debian defaults to the last-chosen environment on subsequent logins. The author does not install any of these alternatives but notes that some may prefer environments that more closely resemble Windows.

## Closing Rules

The chapter ends with a set of operating principles. Keep the Debian Stock VM updated but never use it for investigations. Keep the OSINT VM updated and configured but never run investigations in it. Always shrink the OSINT VM before cloning. Work only inside dated clones. Store a backup copy off the primary device. When a tool breaks after an update, move on and wait for a future update to fix it.
