This chapter (labeled Chapter 39 in the book) introduces the Terminal commands used throughout the data collection section. It has two goals: explain what each command does and why, and provide numbered practice assignments so readers can verify their understanding before moving on.

## Operating Environment

All commands run in Terminal on macOS or Linux, or in Command Prompt on Windows. Windows has persistent differences: file paths use backslash instead of forward slash, the tilde shorthand for the home directory is replaced by `C:\users\%username%\`, the in-place edit flag (`-i`) is not available in the Windows version of sed, and the sort deduplication flag is `/unique` rather than `-u`. The chapter notes these differences throughout and states a preference for macOS and Linux for data processing work.

## Navigation Commands

The `cd` command changes the working directory. The `ls` command (or `dir` on Windows) lists the contents of the current directory. On macOS and Linux, `~/` refers to the home directory regardless of the username. The `mkdir` command creates a directory. The `rm` command deletes files. Deleting a directory requires `rm -r`. The `mv` command moves a file or folder to a new location.

## cat

`cat` reads the contents of a file and writes them to output. Its main use here is combining multiple files into one by listing them before the `>` redirect operator. For example, `cat cat-1.txt cat-2.txt > cat-final.txt` merges two files into one. This becomes important when working with hundreds of small log files that need to be consolidated before querying.

## sed

`sed` (stream editor) performs find-and-replace operations on text files. It works on files of any size, including files too large to open in a text editor such as a 100 GB dataset. The basic syntax is `sed -i "s/FIND/REPLACE/gI" file.txt`, where `s/` means substitute, `g` means replace all occurrences per line, `I` means case-insensitive (requires the GNU version of sed), and `-i` edits the file in place. On Windows, `-i` is not supported, so a separate output file must be specified with `>`.

Special characters such as colons, commas, underscores, and quotes must be preceded by a backslash to be treated literally (for example, `s/username\://gI` removes the string `username:`).

A practical use case: a breach file may contain lines like `username:test1,email:test@gmail.com,password:pass123,ip_address:10.2.2.3,phone:5551212,id:32`. Running sed to remove each field label reduces file size substantially. A 200 GB file becomes nearly half the size after removing redundant label text.

The chapter provides a table of common sed patterns, including removing data before the first comma or colon, removing empty lines, removing the first N characters from each line, removing everything after the last underscore, and stripping hyphens from phone numbers.

All commands on macOS and Linux should be prefixed with `LC_ALL=C` when the data may include non-ASCII characters. This sets the character locale to ASCII, prevents errors, and in some cases speeds up processing.

## cut

`cut` extracts specific columns from a comma-separated value (CSV) file. The flag `-d,` specifies the comma as the delimiter, and `-f` followed by column numbers specifies which columns to keep (columns are numbered from 1). For example, `LC_ALL=C cut -d, -f3,4 input.txt > output.txt` retains only columns 3 and 4. This is faster than identifying specific text with sed when you want to discard entire columns of unwanted data.

## sort

`sort -u` sorts a file alphabetically and removes duplicate lines. On Windows, the equivalent is `sort /unique`. For large files on macOS and Linux, the recommended command is `LC_ALL=C sort -u -b -i -f -S 80% --parallel=8 input.txt > output.txt`. The flags mean: `-u` keeps only unique entries, `-b` ignores leading blanks, `-i` ignores non-printable characters, `-f` treats uppercase and lowercase as equal, `-S 80%` allocates 80 percent of system RAM as a buffer, and `--parallel=8` uses 8 CPU threads. The thread count should be adjusted to match the hardware. The chapter recommends not sorting files larger than roughly twice the available RAM.

## split

`split` divides one large file into smaller pieces. The flag `-C` followed by a byte count sets the maximum size per piece. For example, `split -C 25000000000 --additional-suffix=.txt SSN.txt` splits a file into 25 GB chunks named `xaa.txt`, `xab.txt`, `xac.txt`, and so on. The purpose is to make large files sortable on machines with limited RAM. After splitting, each chunk is sorted independently, and then the sorted chunks are merged back into a single deduplicated file using `sort -m -u sorted*`. The merge flag `-m` expects pre-sorted input and is faster than re-sorting. The chapter gives the example of a 260 GB file of names, dates of birth, and Social Security Numbers being reduced to 210 GB after deduplication via this split-sort-merge process.

## awk

`awk` filters lines in a file by pattern. A common use is discarding null or empty lines from breach data. The command `awk '/@/' input.txt > output.txt` keeps only lines containing the `@` character, which in practice retains lines with email addresses and removes blank or placeholder entries.

## wc

`wc -l` counts the number of lines in a file. This is used to determine how many entries a breach file contains before processing it.

## Ripgrep (rg)

Ripgrep is a command-line search tool installed separately. The standard query form used throughout this section is `rg -aFiN "target" file.txt`, where `-a` treats the input as text, `-F` treats the search term as a literal string rather than a regular expression, `-i` ignores case, and `-N` suppresses line numbers. Omitting the filename searches all files in the current directory.

To require two terms both to appear in a result, pipe the output of one Ripgrep query into a second: `rg -aFiN "Michael" | rg -aFiN "Bazzell" file.txt`. To match either of two alternatives, use a pipe character inside the search term: `rg -aFiN "Bazel|Bazzell" file.txt`. Omitting `-F` changes the behavior so each part of the query is matched independently as a regular expression component rather than as a full literal string.

## Practice Assignments

The chapter includes six numbered assignments with solutions at the end. They build in complexity: displaying a downloaded file (Assignment 1), combining four files (Assignment 2), using sed to strip field labels from a CSV (Assignment 3), using cut to extract specific columns (Assignment 4), sorting a file for unique entries (Assignment 5), and a full workflow using a real 19 MB Whois dataset (Assignment 6). Assignment 6 requires combining sed, cut, split, sort, and cleanup commands and produces a 1.1 MB file of domain names, registrant names, and registrant addresses with all duplicates removed.

## Overall Purpose

The chapter frames these commands as preparation for acquiring and working with large OSINT datasets such as breach data, voter files, and stealer logs. The core workflow is: download data, strip unnecessary field labels with sed, extract needed columns with cut, remove duplicates with sort (splitting first if the file is large), filter out invalid lines with awk, and query the cleaned result with Ripgrep.
