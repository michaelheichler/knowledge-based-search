## Overview

This chapter covers Firefox browser extensions (called add-ons) that support OSINT investigations. Firefox is the chosen browser because it natively respects privacy and security more than alternatives, and because it supports a wide range of useful extensions. The chapter explains how to install and configure each recommended add-on, and ends with guidance on exporting your configuration so it can be replicated across multiple Firefox installations or virtual machines. All configurations should be completed inside the original VM before cloning, exporting, or taking snapshots.

Add-ons can be installed by opening the Firefox menu, clicking "Add-ons", and searching by name in the search field at the upper right of the page.

## Firefox Multi-Account Containers

### What it does

Multi-Account Containers gives each browser tab a separate storage slice. Cookies, session tokens, logged-in states, and advertising tracking data from one container do not carry over to another. The result is that different services see each container tab as a distinct visitor. A traditional browser allows only one active login per service at a time. With containers, you can be logged into multiple accounts on the same service simultaneously, each in its own container, without logging out or opening a separate browser.

### Initial setup

1. After installing, click the Containers icon (three squares and a "+" character) in the upper right of Firefox.
2. Select "Manage Containers".
3. Delete all default containers by selecting each and clicking "Delete This Container".
4. Click the "+" in the upper left to create new containers. Enter a name (for example, "Alias 01"), choose a color and icon, and repeat as needed.

The author's investigation containers are: Personal, Alias 01, Alias 02, Alias 03, Alias 04, Leaks, Google, Harmful.

For personal devices, the recommended containers are: Communications (personal email and calendar), Financial (banking and credit card accounts), Search (all Google queries), Alias (social network accounts in another name).

### Key workflows

**Multiple logins to the same service.** Open the Containers menu, select Alias 01, navigate to the target service, and log in. Then open the Containers menu, select Alias 02, navigate to the same service, and log in to a second account. The two tabs are fully isolated. The target platform can still see that both sessions share the same IP address, but it cannot see cookies from one session in the other.

**Isolating suspicious links.** While viewing a target's profile and encountering a link to an unknown external site, right-click the link and choose "Open link in New Container", then select the "Harmful" container. The loaded page cannot access cookies from the container where the investigation account is logged in.

**Pinning a site to a specific container.** Create a container named "Google". Open a new Google container tab and navigate to google.com. Click the Containers menu and select "Always Open This Site in...", then choose the Google container. On the next navigation to google.com from any tab, select "Remember my decision..." and confirm. After that, any navigation to google.com (including searches from the URL bar and all other Google services such as Gmail and Google Voice) will open in the designated Google container automatically, regardless of which tab initiates the visit. To remove the rule, delete the container or go to Manage Containers, select the Google container, and delete the site policy.

**Limiting a container to designated sites.** In Manage Containers, select a container and enable "Limit to Designated Sites". This prevents accidental navigation of unrelated sites into a secure container.

### Practical notes

Creating per-site container rules for every service visited is overkill. There is no perfect configuration. Evaluate investigation needs and create only the containers that are necessary. Creating a rule that forces a social media site to always open in one container conflicts with the ability to log into multiple accounts on that service, because all logins would then go into the same container.

## uBlock Origin

### What it does

uBlock Origin replaces NoScript, Adblock Plus, Privacy Badger, and Disconnect. It blocks known invasive advertisements, tracking code, and malicious content by default. It also provides a fine-grained per-site and global script control panel for advanced users, and has the ability to bypass website restrictions such as article paywalls.

### Initial setup

1. Install from addons.mozilla.org.
2. Click the uBlock Origin icon, then the Dashboard icon (gear/settings appearance).
3. On the Settings tab, enable "I am an advanced user". This unlocks the expanded control menu.
4. On the Filters tab, enable "Block access to LAN" under the Privacy section.

### Understanding the advanced menu

After enabling advanced mode, clicking the uBlock Origin icon displays an expanded menu that changes per site.

- Column 1: script type or domain name.
- Column 2: global settings, applied to all websites.
- Column 3: per-site settings for the current page only.

Cell indicators:
- Single "+" means fewer than 10 scripts were allowed from that domain.
- Double "++" means 10 to 100 scripts were allowed.
- Single "-" means 1 to 9 scripts were blocked.
- Double "--" means 10 to 100 scripts were blocked.

Cell colors: grey means the default rule applies (uBlock Origin decides). Red means blocked. Green means allowed. Clicking the right (red) portion of a cell blocks. Clicking the left (grey) portion allows. After any change, click the padlock icon to save, then refresh the page.

### Practical procedures

**Allow all scripts on a single page (for evidence capture).** Click the power button in the upper-right of the uBlock Origin menu. This turns the left edge of the column green and allows all scripts to load on that page, including intrusive ones. This is used when capturing a page as evidence, because blocking scripts technically modifies the page. Allowing everything ensures the page renders exactly as intended.

**Block all scripts on all pages (when entering a dangerous site).** Click the right (red) section of the top cell in column 2. The entire global column turns red, blocking all scripts across all websites. Conduct research, then reverse the change by clicking the left (grey) section of the same cell. Save after each change.

**Bypass subscription paywalls.** On the paywalled page, click the right (red) section of the "3rd-party scripts" row in column 3. Save, then reload. Many paywall systems rely on a third-party script to check subscription status. Blocking that script removes the restriction on the page. This works on thousands of sites.

**Block inline scripts on news sites.** Click the right (red) section of the "inline scripts" row in column 3. Save, then reload. This removes autoplay video, pop-up advertisements, and overlapping images that interfere with reading. Do not use this when capturing a page as evidence, because it modifies how the page renders.

**Reset all custom rules.**
1. Set column 2 (global) back to grey by clicking the left section of the top cell in column 2.
2. Open Dashboard and go to the "My Rules" tab.
3. In the Temporary Rules column, select all text and delete it.
4. Click Save, then Commit.

This fully resets uBlock Origin to default behavior. Uninstalling and reinstalling does not always clear stored rule data.

## DownThemAll

DownThemAll downloads every linked file on a page in bulk. It identifies linked video, audio, images, documents, and other media types, then allows the user to select and download everything at once.

**Procedure.**
1. Navigate to a page containing linked files.
2. Click the DownThemAll toolbar menu and select "DownThemAll".
3. In the dialog window, click "All Files" to select everything, or use the type filters (Software, JPEG Images, Audio, Documents, Images, Videos, Archives) to narrow the selection.
4. Click "Download". Files go to the default OS download location.

**Example data set.** The archive URL `https://web.archive.org/web/20151110195654/http://www.updates4news.com:80/kyledata/` contains hundreds of large CSV and TXT files of marketing data including names, addresses, telephone numbers, and interests for millions of Americans. DownThemAll can download all files from this page, though the download may take hours and will consume significant disk space. The chapter advises not downloading this set until external storage methods (covered later in the book) are in place.

DownThemAll is the preferred bulk download option. Bulk Media Downloader should be installed as a backup.

## Bulk Media Downloader

Bulk Media Downloader captures audio and video links dynamically as the user scrolls a page, making it useful when DownThemAll does not function on a particular page.

**Procedure.**
1. Navigate to a page with embedded media.
2. Launch Bulk Media Downloader. A pop-up panel appears over the browser.
3. Select the desired file types (Video, Audio, Application, Image, Archive, Document).
4. Scroll the target page. The tool populates links as media elements are encountered.
5. Click Download to retrieve all found files (video files are saved as MP4).
6. Use checkboxes to include or exclude individual items or categories before downloading.

The tool works well on social media feeds, pages with many embedded clips, and document-heavy pages. Individual items can be selected or deselected before downloading.

## Exporting and Replicating Configuration

After completing all browser and add-on configurations in the primary VM, export the settings and apply them to any other Firefox instance or cloned VM. This ensures identical investigation environments across machines. All configuration should be done in the original VM before cloning or taking snapshots.
