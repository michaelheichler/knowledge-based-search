This chapter covers advanced Twitter search techniques, methods for recovering deleted or suspended content, extraction of metadata from individual tweets, live monitoring with TweetDeck, and structured data export using third-party tools. The accounts @humanhacker (Christopher Hadnagy) and @WestCornfield (Wes Corwin) are used as demonstration targets throughout.

## Search Operators

Twitter's search bar supports a set of operators that produce more targeted results than browsing a profile directly.

**Directional filters.** `from:SultryAsian` returns only outgoing tweets from that account. `to:SultryAsian` returns all public tweets addressed to the account, content the account owner cannot suppress from this search. Combining both operators isolates a conversation between two specific accounts: `to:SultryAsian from:HydeNS33k`. Replies can be isolated with `from:SultryAsian filter:replies`, or excluded with `from:SultryAsian -filter:replies`. Clicking "Latest" in search results places posts in reverse-chronological order.

**Location search.** `geocode:43.430242,-89.736459,1km` (no spaces) retrieves tweets posted within one kilometer of those GPS coordinates. Reliable radius values are 1, 5, 10, and 25 kilometers. Values outside that set produce inaccurate results. The unit can be changed from `km` to `mi`. The same query works as a browser URL parameter: `https://twitter.com/search?q=geocode:43.430242,-89.736459,1km`. Keywords can be appended to narrow results, for example `geocode:43.430242,-89.736459,1km "fight"`. Geo-enabled tweets are rare because location sharing is off by default on Twitter, so this technique yields results infrequently, but investigators should know it exists.

**Mandatory and optional terms.** Placing a name in quotes forces an exact match (the mandatory portion). Additional terms joined by uppercase `OR` require only one of them to appear in results: `"Michael Parker" kill OR stab OR fight OR beat OR punch OR death OR die`. The `OR` operator must be uppercase.

**Date range search.** The `since:` and `until:` operators filter by date in YYYY-MM-DD format. `since:2015-01-01 until:2015-01-05 "bomb threat"` returns posts containing that phrase within that window. The main value of date-range searching is reaching content older than what profile scrolling can access. For a target with 13,000 tweets such as humanhacker, the author recommends one query per calendar year back to the account's origin, for example `from:humanhacker since:2012-01-01 until:2012-12-31`, repeated for each year from 2006 onward. Replacing `from:` with `to:` collects incoming tweets for the same period. Using the username in quotes without a direction operator (`"humanhacker" since:2008-01-01 until:2008-12-31`) theoretically captures both directions but is less complete than explicit from/to queries. Date ranges also surface old personal data: `from:humanhacker email since:2006-01-01 until:2009-12-31` recovered a post containing the email address logan@social-engineer.org that was no longer visible on the live profile.

**Media and engagement filters.** `https://twitter.com/humanhacker/media/` shows only media-containing posts. `https://twitter.com/humanhacker/likes/` shows all posts the account has liked (requires being logged in). `from:inteltechniques filter:links` limits results to tweets with links. `from:inteltechniques min_faves:150` returns tweets with at least 150 likes. `from:inteltechniques min_replies:100` returns tweets with at least 100 replies. These operators chain together: `to:humanhacker from:AimsandShoot since:2018-03-01 until:2018-03-31 filter:links filter:replies` isolated a single tweet from thousands.

## Recovering Deleted, Suspended, and Missing Tweets

When a user deletes posts, wipes an account, or has the account suspended, external sources can recover content.

**Search engine caches.** Searching `Twitter WestCornfield` on Google and opening the cached version of the profile page (via the small green down-arrow next to the URL, then "Cached") recovered 20 deleted tweets from a capture dated December 12, 2017. Repeating the process on Bing yielded a cache from December 7, 2017, and Yandex held a cache from November 3, 2017. Each engine's snapshot reflects a different capture date and may contain unique posts not present in the others.

**Cached individual posts.** The query `site:twitter.com/westcornfield/status` forces Google to list direct links to individual posts from that account. Clicking a deleted post on Twitter returns an error, but opening the Google cached version of that search result displays the post content. This method identified deleted posts as far back as October 2017.

**Wayback Machine.** `http://web.archive.org/web/*/twitter.com/WestCornfield` retrieves archived snapshots of the profile. A capture dated December 6, 2017 displayed the profile as it appeared from November 8, 2017 onward, recovering an additional deleted tweet.

**Likes after deletion.** Even after a user wipes their own posts, `https://twitter.com/WestCornfield/likes/` may still display hundreds of previously liked posts, revealing the account's interests and associations. The author notes the entire multi-source process for this demonstration took under three minutes using a custom Twitter search tool discussed later in the chapter.

## Tweet Post Details

**Full-size images.** Right-clicking an embedded image and choosing "View image" loads a URL such as `https://pbs.twimg.com/media/Ek3FxAhVcAEJt_t?format=jpg&name=small`. Removing `&name=small` loads the original full-resolution version.

**Time zone verification.** The date and time shown below a tweet appears to be local time for the account owner, but this should not be assumed. Viewing the page source of the tweet (right-click, "View Source") and searching for `time_zone` via Ctrl+F (Windows/Linux) or Command+F (Mac) reveals the account's configured time zone, for example `Eastern Time (US & Canada),utc_offset>14400,tzinfo_name:America/New_York`. This confirms the exact local time of the post. The author describes knowing exact dates and times as mandatory for investigations that may reach a courtroom.

## TweetDeck (tweetdeck.twitter.com)

TweetDeck is a Twitter-owned tool with access to the live Twitter Firehose, the complete stream of all public posts. It requires a Twitter account login (alias accounts are acceptable and preferred). The interface presents multiple persistent columns, each tied to a search query or user monitor, added via the plus symbol in the upper left area.

The Search column type accepts any Twitter search syntax, including geocode queries and keyword combinations. The User column type tracks all public incoming and outgoing posts for a specified username. Multiple subjects can each occupy their own column, allowing an investigator to observe when two monitored accounts interact. Columns beyond what fits on screen are navigated with left and right arrows. Audible alerts can be set on a column so TweetDeck plays a sound when a new matching tweet arrives.

A real-world example from 2019: the author was investigating a death threat against a celebrity. A column of `to:myclient die OR shoot OR death` filtered the high volume of incoming tweets down to threat-relevant content and identified a suspect. A column of `from:suspect to:myclient` tracked all messages the suspect sent to the celebrity. A final alert column of `from:suspect to:myclient kill OR die OR shoot OR death` notified the author of new activity. The suspect was arrested a week later while attempting to burglarize the celebrity's apartment.

## Third-Party Tools

Most third-party Twitter tools require authentication through a Twitter account because of Twitter's API safeguards. The author recommends using a covert investigation account and never providing any third-party service with access to a real personal account.

**AllMyTweets (allmytweets.net).** Displays up to 3,200 tweets from a single account on one scrollable screen, most recent first, one per line. Supports in-page search via Ctrl+F and can be printed for distribution to analysts.

**TweetBeaver (tweetbeaver.com).** Described as the author's preferred third-party Twitter reporting tool, offering fourteen distinct options, all requiring Twitter account login via the API.

Convert Name to ID translates a username (for example, jms_dot_py) to its permanent numeric user ID (817668451). User IDs cannot be changed even when usernames can, making this the most reliable way to track a target across username changes. Convert ID to Name performs the reverse, recovering a current username from a known numeric ID.

Check if two accounts follow each other produces a plain-text report of the mutual follow relationship. Example output: `@inteltechniques does not follow @jms_dot_py` and `@jms_dot_py follows @inteltechniques`.

Download a user's favorites exports likes as a CSV spreadsheet or on-screen display, with fields for original author, date and time, tweet text, direct URL, and the author's biography.

Download a user's timeline extracts the most recent 3,200 posts with date, time, and direct URL for each. Running this tool daily on a target account allows the investigator to capture new posts and detect posts that were present on one day but deleted before the next run.

Get a user's account data provides a standardized export of all public account information: screen name, numeric Twitter ID, display name, account creation date, biography, location, URL, time zone, geo-enabled status, language, verified status, tweet count, follower count, and friend count. The example output for jms_dot_py (Justin Seitz, ID 817668451) shows the account created September 11, 2012, located in Saskatoon, Saskatchewan, set to Central Time, with 9,041 tweets, 7,095 followers, and 2,112 friends. A consistent format across multiple targets aids presentation during prosecution.
