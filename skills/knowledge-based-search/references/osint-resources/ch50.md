This unit is the second part of Chapter 30, covering note-taking tools (CherryTree and advanced text editors), formal report structure, link analysis and timeline tools, appendix construction, and document sanitization.

## CherryTree Templates

The chapter opens mid-discussion of CherryTree, a hierarchical digital notebook for Linux. To reuse a notebook structure across investigations, export a completed notebook via "Export" > "Export To CherryTree Document", select "All the Tree", and save the result as a .ctb file. To start a new investigation from that template on a clean VM: copy the .ctb file to the desktop, open it via "File" > "Open File", then immediately "Save As" with the case name or number as the new filename, keeping the storage type as "SQLite, Not Protected (.ctb)".

CherryTree's main limitation relative to OneNote is weaker drag-and-drop support and inconsistent handling of non-text file types. Its advantage is privacy. It is open-source and runs inside a Linux VM, avoiding the data exposure of Microsoft or other closed-source applications. A pre-built CherryTree template is included in the book's digital files download.

## Advanced Text Editors

Light IDEs (Interactive Development Environments) are presented as a practical complement to office suites. Their value for OSINT work comes from combining note-taking, markdown editing, terminal access, and script execution in a single interface. The editors covered were selected for open-source status, cross-platform availability (macOS, Windows, Linux), and balance of features versus ease of use.

**Atom** (atom.io) is the most beginner-friendly option. It is open-source, highly customizable through community plugins, and installs easily via package manager (`brew install atom` / `choco install -y atom` / `sudo snap install atom --classic`). The base install lacks a terminal. That functionality is added by two recommended plugins: HTML Preview (atom.io/packages/atom-html-preview) and Terminal Plus (atom.io/packages/terminal-plus). Atom is less responsive than other editors on large files.

**VSCode** (code.visualstudio.com) is nearly a full IDE with the largest extension catalog in its class. It includes a built-in terminal (CMD, PowerShell, or bash), supports markdown, and handles large files without slowing. Its weakness is Microsoft telemetry and data collection. Installation: `brew install visual-studio-code` / `choco install -y vscode` / `sudo snap install --classic code`. After installation, telemetry must be manually disabled: "File" > "Preferences" > "Settings", search "telemetry", uncheck "Telemetry: Enable Telemetry setting", then search "@tag:usesOnlineServices" and review each item. Recommended extensions: HTML Preview (github.com/george-alisson/html-preview-vscode), Default Browser (github.com/peakchen90/vscode-open-in-default-browser.git), PowerShell (github.com/PowerShell/vscode-powershell.git), Python (github.com/Microsoft/vscode-python), and Prettier Code (github.com/prettier/prettier-vscode.git). The Live Share extension enables real-time collaboration using end-to-end SSH encryption, but requires a Microsoft or GitHub account for read-write access. The book recommends using a covert GitHub account rather than a Microsoft account when team collaboration is needed.

**VSCodium** (vscodium.com) is an open-source clone of VSCode that removes Microsoft data collection by default. It is the recommended choice for investigators not already relying on Microsoft Office. Installation: `brew install vscodium` / `choco install -y vscodium` / `sudo snap install codium --classic`. Trade-offs relative to VSCode include a smaller community, a slightly less polished experience, and some extensions requiring extra installation steps. All application settings should still be reviewed manually for any options that call online services.

## Anatomy of an OSINT Report

The formal OSINT report follows a four-part structure: face-sheet, narrative, analysis, and appendix.

**Face-Sheet.** One to two pages. Its purpose is to let a supervisor or client understand the essentials at a glance: case name and number, analyst identity, investigative timeframe, subject identifiers, and key findings (bullet points or short paragraphs, no more than half a page). A table of contents, if used, appears between the case title and the key findings. The face-sheet alone is sufficient when supporting time-sensitive field operations such as fugitive apprehension. Two template variants are illustrated: a simple one-page profile sheet and a full agency format with logo, approval signatures, and a structured subject profile table covering name, DOB, address, phone numbers, employer, Social Security number, vehicles, associates, email addresses, usernames, and social media profiles. A separate event intelligence sheet format is also described for monitoring public events. It captures hashtag feeds, relevant social media accounts, relevant websites, groups or individuals of interest, and video feed sources.

**Narrative.** Follows the face-sheet and tells the story of how the key findings were reached. Organization can be chronological or structured around the findings as listed on the face-sheet. The book recommends first-person voice, concise phrasing as in a legal statement, and sufficient context for a reader (including a jury) to understand each finding. Length ranges from a couple of paragraphs to several pages depending on case complexity. The narrative must address any exculpatory evidence and represent it accurately, which is especially important in criminal justice and government work. When the report functions as an intelligence brief, confidence language such as "possible", "likely", or "highly likely" is preferred over percentage expressions. A methods section within the narrative describes compartmentalization from other casework, thoroughness, and the specific software and services used. The example narrative (Figure 30.05) shows a detective documenting the use of a fresh Chrome browser in a newly configured virtual machine, running keyword searches of the username "@Jakijumpjorp66" across Google, Bing, Yandex, Baidu, Sear, Yahoo, DuckDuckGo, and Exalead, then preserving the relevant Twitter page with the Fileshot extension.

**Link Analysis and Timelines.** Not required for every investigation but valuable for major cases. Specialist analysts at larger agencies often produce these using Maltego or IBM i2 Analyst's Notebook, working from the investigator's face-sheet, narrative, and a hand-drawn entity map. For investigators without analyst support, the book recommends the following free tools: Draw.io (diagrams.net/integrations.html), Visual Investigative Scenarios (vis.occrp.org), Gephi (gephi.org), Visual Site Mapper (visualsitemapper.com), MindMup (mindmup.com), NodeXL (nodexlgraphgallery.org), and NWU (knightlab.northwestern.edu/projects).

Draw.io is the preferred tool. The browser version prompts for cloud storage by default. Investigators should click "Change Storage", select "Device", and check "Remember this setting" to save locally. An offline desktop version is available for Linux (downloaded as a .deb package from github.com/jgraph/drawio-desktop/releases and installed via the software manager). After opening, shapes are dragged from the left panel into the chart, lines and arrows represent relationships, and labels are edited by double-clicking. Export formats include PDF, DOCX, PNG, and HTML. To modernize the default icon style: click "Extras" to select a theme (lighter themes for print, dark for screen), then "+More Shapes" to add sets such as "Web Icons" and "Web Logos" under "Other". A known quirk in VM use is that the save dialog window may be hidden behind the chart window. Clicking "Activities" at the top left of the VM exposes all open windows.

For dedicated timeline work, two browser-based tools are described. Event Viewpoint (eventviewpoint.com) is free, allows events with location, time span, and notes, and displays data as a list, timeline, or map. It requires a non-attributable account and should not be used with sensitive data because it collects user data. Time Graphics (time.graphics) is a premium browser-based timeline tool supporting events, pictures, video, and notes with export to PDF, DOCX, and JSON. It requires a valid email account. Only premium users can privatize projects, though a two-day free trial is available.

**Appendix.** Contains all supporting documentation and captured media: screenshots, still frames from video evidence, spreadsheets of social media contacts, and other digital evidence suitable for document format. These are working copies only. Digital originals are preserved separately on optical media or in whatever format agency policy requires.

For merging multiple PDF files into a single appendix document without Adobe Acrobat, the book recommends PDFsam Basic (pdfsam.org/pdf-merge), a free open-source application for Linux, Mac, and Windows. On Ubuntu: download the .deb package from pdfsam.org/download-pdfsam-basic/ and install via "Open with Software Install". To merge: open PDFsam Basic, use "Add" or drag-and-drop to load files, set "Merge Settings" > "Table of Contents" to "Generate from file names", and click "Run". The merged file is created in the same directory as the source files. Premium PDFsam versions (roughly $60 per year) add editing and format conversion but are closed source.

Hunchly (hunch.ly), described as one of the only paid tools the author uses daily, has a built-in report builder useful for generating the appendix even when not using Hunchly for the full report. To preserve the evidentiary copy first, click "Export" > "Export Case". To build the appendix: open "Export" > "Open Report Builder", title the report with the case name and number, rename the default "Section 1" to something like "Photo Evidence", drag "All Tagged Photos" from the left panel into that section, optionally drag "Page History Table" for a captured-pages list, then export as PDF or DOCX to the case directory. The key advantage of Hunchly-generated appendices is that each preserved page and image automatically carries its capture date, hash, and source URL.

## Document Sanitization

Reports created in proprietary applications (Word, Acrobat) embed metadata that can expose the investigator's account details. Removing that metadata from the report before submission (but never from evidentiary documents) is a recognized best practice.

In Microsoft Office: "File" > "Check for Issues" > "Inspect Document", check all boxes, click "Inspect", then click "Remove all" next to "Properties" to delete metadata such as the author username. This is not a complete cleanse but removes the most accessible identifiers.

In Adobe Acrobat: "Tools" > "Protect and Standardize" > "Redact" > "Remove Hidden Information". A panel lists the types of data found. Uncheck anything to keep, then click "Remove". Changes are not finalized until the file is saved as a new document. The recommended naming convention appends "san" or "clean" to the filename (for example, Policy_v6_san.pdf) to indicate sanitized status.
