This unit (appearing as Chapter 4 in the printed book) covers the installation and use of Linux-based automation tools for OSINT investigations. All tools are configured inside a Linux virtual machine. Custom shell scripts tie each group of tools into a menu-driven launcher, reducing the need to type Terminal commands during active investigations.

## Bulk Image Download

The author's preferred tool for bulk image retrieval is Gallery-DL, discussed elsewhere. When Gallery-DL does not support a target site, RipMe (github.com/RipMeApp/ripme) serves as a fallback. RipMe requires Java. The author refuses to install Java on Windows or Mac hosts because of security concerns, but accepts it inside a Linux VM. Installation requires downloading the JAR file, marking it executable, and double-clicking to launch. The user supplies a target URL and clicks "Rip". Downloads go to a "rips" folder inside Downloads. RipMe supports Imgur, Twitter, Tumblr, Instagram, Flickr, Photobucket, and Reddit. The VM script files are named "gallery.sh" and "gallery.desktop".

## Username and Email Enumeration

Five tools handle username and email account discovery. A single script ("usertool.sh") presents a menu that runs any of them and saves results to the Documents folder.

Sherlock (github.com/sherlock-project/sherlock) queries a username across many platforms and can export results to a CSV file. It occasionally produces false positives. The command is:

    python3 sherlock.py inteltechniques --csv -o ~/Documents/Report.csv

SocialScan queries a smaller set of services but produces reliable results. It accepts either a username or an email address:

    socialscan inteltechniques
    socialscan inteltechniques@gmail.com

Holehe is more robust than the previous two. It queries dozens of services using registration checks and password recovery prompts. It accepts an email address:

    holehe test@gmail.com

Results appear on screen and can be copied directly into a report.

WhatsMyName (github.com/WebBreacher/WhatsMyName) is the most thorough of the five but takes the most time and produces the most false positives. It runs against a username:

    python3 web_accounts_list_checker.py -u inteltechniques

The automated script appends output to a text file.

Email2Phone (github.com/martinvigo/email2phonenumber) queries an email address against online services looking for partial phone numbers associated with the account. Results are infrequent, but the occasional phone number discovery justifies the effort:

    python3 email2phonenumber.py scrape -e test@gmail.com

## Automated Website Screenshots (EyeWitness)

EyeWitness (github.com/ChrisTruncer/EyeWitness) automates the capture of screenshots and HTTP metadata from a list of URLs. The user creates a plain text file with one URL per line and passes it to the script:

    ./Eyewitness.py -f ~/Desktop/sites.txt --web -d ~/Documents/EyeWitness/

The resulting Report.html contains a screenshot of each site alongside the server IP address, page title, modification date, and full source code. This serves two purposes: it speeds up review of many sites at once, and it preserves the state of a page at the moment of capture. If a target later deletes or modifies a page, the report is evidence of the prior state. A custom script ("eyewitness.sh") accepts either a single URL or a text file and saves each report to a timestamped folder. The author used this tool to capture and review more than 300 suspect Twitter accounts, producing a several-hundred-page report in a few minutes.

## Domain Intelligence Tools

Six tools handle domain analysis. All are installed to a "Programs" folder inside Downloads and are accessed via a menu script ("domains.sh").

Amass is the slowest but most thorough. It brute-forces potential subdomains and can find entries no other tool discovers. In a test against cnn.com it found 282 subdomains. Reports go to Documents/Amass. Relevant commands:

    amass intel -whois -ip -src -active -d inteltechniques.com
    amass enum -src -ip -passive -d inteltechniques.com

Sublist3r runs faster but finds only common subdomains. In the same cnn.com test it found 808. Reports go to Documents/Sublist3r:

    python3 sublist3r.py -d inteltechniques.com

Photon does not look for subdomains. Instead it crawls internal pages of a target site. Reports go to Documents/Photon:

    python3 photon.py -u inteltechniques.com -l 3 -t 100

TheHarvester searches a domain for associated email addresses and hosts. In the cnn.com test it returned 72 hosts and 16 email addresses. Reports go to Documents/theHarvester:

    python3 theHarvester.py -d inteltechniques.com -b bing,google

Carbon14 analyzes images embedded in a target page and reads their metadata to infer the true age of content. It is useful for detecting blogs where content was backdated or imported from an older source. The author applied it to an anonymous WordPress blog that showed uniform recent dates but had clearly been migrated from an earlier site. Carbon14 revealed older image creation dates suggesting when the original posts were made. Dates can be altered intentionally or accidentally, so results are leads rather than forensic proof. Carbon14 works best on static sites and blogs and has also returned useful results on social network profiles:

    python3 carbon14.py https://inteltechniques.com

A natural workflow is to pass URLs discovered by the domain tools into EyeWitness for bulk screenshot review.

## Metadata Extraction and Removal

Five tools handle media metadata.

MediaInfo (installed as mediainfo-gui) reads metadata embedded in video files. The GUI defaults to a minimal view. Switching to View > Text reveals all available data, which for a video received directly from a mobile device can include the device make, model, OS version, GPS coordinates, and recording date. This level of detail is typically absent from videos downloaded from the internet. The ideal source is a file sent directly from the originating device.

ExifTool (installed as libimage-exiftool-perl) exports Exif metadata from batches of images to a CSV file. A folder of images named "Evidence" on the Desktop can be processed with:

    cd ~/Desktop/Evidence && exiftool * -csv > ~/Desktop/Report.csv

The author used this to process 200 images from a target's blog, producing a spreadsheet that included GPS locations useful to the investigation. Ubuntu's default image viewer can display Exif data for individual images through the Properties menu, but ExifTool is needed for bulk export.

MAT2 (Metadata Anonymisation Toolkit 2) removes metadata from a file before uploading it as part of a covert operation:

    mat2 dirty.jpg

This creates a new file named "dirty.cleaned.jpg" in the same folder. The original is never overwritten.

xeuledoc identifies the owner of a Google Document by extracting metadata that is not visible in the document itself. Given a document URL, it returns the owner's name, email address, Google account ID, and the document's creation and last-edit dates. The author demonstrated this against a Google spreadsheet used to distribute pirated copies of a book. xeuledoc returned the owner's name, Gmail address, and Google ID. The command is:

    xeuledoc https://docs.google.com/spreadsheets/d/1KXksBlvj7fXPNS4OYL0idQne3HXVnamtUPlh0ut3xwk

Sherloq (github.com/GuidoBartoli/sherloq) is a standalone graphical application for detecting digital manipulation in photographs. It replicates methods covered in Chapter 21 of the book but runs entirely offline. The offline capability matters when an image is sensitive enough that uploading it to an external service is undesirable. The user loads an image and works through the left-side menu. One option is Principal Component Analysis, which highlights regions that may have been digitally altered. Installation requires cloning the repository and installing dependencies including matplotlib:

    python3 ~/Downloads/Programs/sherloq/gui/sherloq.py

All metadata tools are accessible through a single "metadata.sh" script.

## Supporting Applications

LibreOffice (Writer for reports, Math for CSV files, Impress for presentations) is typically pre-installed in Ubuntu. If not, it can be added with `sudo snap install libreoffice`. The author prefers to write investigation reports in the host OS rather than the VM, keeping covert browsing and documentation on separate machines.

Tor Browser is installed via the micahflee PPA and is needed for some later tutorials. It is used for accessing sites that require Tor and for some browser extensions.

Chrome is installed directly from a .deb package downloaded from Google. Despite privacy concerns for personal use, Chrome is valuable in the OSINT VM because some browser extensions are Chrome-only and some investigation targets are best accessed through it.
