This chapter explains how to configure a native Mac or Windows machine to replicate the OSINT toolset that the book's Linux virtual machine provides. The author warns that conducting investigations on a native host without snapshot capability can contaminate evidence, and treats these builds as an alternative for readers who cannot or will not run a VM.

All commands from the chapter are available in digital form at these URLs (credentials: username "osint9", password "book!43wt"):

- https://inteltechniques.com/osintbook9/mac.txt
- https://inteltechniques.com/osintbook9/windows.txt

## Mac OSINT Host

### Package Manager: Homebrew

The first step is to install Homebrew (Brew), the Mac package manager introduced in Chapter One. The install command is:

```
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/master/install.sh)"
```

Installation may prompt for the user's password twice and a confirmation with Enter.

### Core Packages via Brew

After Brew is installed, the latest Python3 is installed to override the older system default:

```
brew install python3
```

Then a block of command-line tools and GUI applications is installed in two long Brew commands covering: zenity, youtube-dl, yt-dlp, ffmpeg, pipenv, mat2, httrack, exiftool, internetarchive, ripgrep, instalooter, fileicon, wget, streamlink, libmagic, firefox, google-chrome, vlc, tor-browser, google-earth-pro, keepassxc, mediainfo, phantomjs, and xquartz. Amass is installed from a separate tap (caffix/amass).

After installation, a cleanup and diagnostic sequence runs:

```
brew autoremove
brew cleanup -s
rm -rf "$(brew --cache)"
brew doctor
brew missing
```

If any package is unavailable, it should be removed from the install command to avoid blocking all other installations.

### Firefox Configuration

Firefox is configured by downloading a pre-built profile template from the author's site and copying it into the Firefox profiles directory, replacing the default-release profile. Pre-existing Firefox installations may conflict. Manual profile copying as described in Chapter Three is the fallback.

### Custom Scripts, Icons, and Tools

Two archives are downloaded from the author's site: tools.zip (the same tools distributed with the Linux VM) and mac-files.zip (Mac-specific scripts and icons). These are extracted and placed at:

- `~/Documents/scripts` for scripts
- `~/Documents/icons` for icon image files

### Python Tools Installed via pip

A single long `sudo -H python3 -m pip install` command installs these Python packages: youtube-tool, Instaloader, toutatis, nested-lookup, webscreenshot, redditsfinder, socialscan, holehe, waybackpy, gallery-dl, xeuledoc, bdfr, search-that-hash, h8mail.

Several tools are cloned from GitHub and their dependencies installed individually:

- Osintgram (Datalux/Osintgram)
- Sherlock (sherlock-project/sherlock)
- WhatsMyName (WebBreacher/WhatsMyName)
- email2phonenumber (martinvigo/email2phonenumber)
- Sublist3r (aboul3la/Sublist3r)
- Photon (s0md3v/Photon)
- theHarvester (laramies/theHarvester)
- Carbon14 (Lazza/Carbon14)
- Sherloq (GuidoBartoli/sherloq)
- Metagoofil (opsdisk/metagoofil)
- DownloaderForReddit (MalloyDelacroix/DownloaderForReddit)
- Recon-ng (lanmaster53/recon-ng)
- SpiderFoot (smicallef/spiderfoot)
- Elasticsearch-Crawler (AmIJesse/Elasticsearch-Crawler)
- GHunt (mxrch/ghunt)

A helper script (xvfb-run) is also downloaded from the exactcode SVN repository and placed in /usr/local/bin. The h8mail configuration file is patched with a sed command to fix a setting name. The build ends with a restart.

### Graphical Adjustments

The `fileicon` utility is used to assign custom PNG icons to each script file, giving them the same visual identifiers as the Linux VM. Scripts are added to the Applications folder via a symlink:

```
ln -s ~/Documents/scripts/ /Applications/
```

They are also added to the Dock using a `defaults write com.apple.dock` command. The full command is too long to print in the book and is included in the mac.txt file. It overrides the entire Dock configuration.

### Apple Gatekeeper

Because the custom scripts are unsigned, macOS Gatekeeper blocks them by default. The author recommends right-clicking each script, choosing Open, and confirming the security exception. This is a one-time step per file.

### No Single Install Script

Unlike the Linux VM chapter, no single automated install command is provided for the Mac build. The author cites a few reasons. First, the changes are made to a host OS rather than a disposable VM, so the author wants each step to be deliberate. Second, some steps require manual execution that cannot be replicated from Terminal, including allowing unsigned apps through Gatekeeper and manually launching custom programs during first use (Firefox being one example). For these reasons, the author asks that each step be applied manually.

### Updates

A custom Updates script (also accessible as an icon in the Dock) runs:

- `brew update`, `brew upgrade`, `brew upgrade --greedy`, and Brew cleanup commands
- `sudo -H python3 -m pip` upgrade for all outdated packages
- `git pull` for each of the cloned GitHub repositories

### Reversing the Mac Build

A full uninstall sequence is provided for readers who want to remove all changes. It runs pip uninstall for every installed package and repository, deletes the scripts and icons directories, removes the Programs directory under Downloads, unlinks the Applications/scripts symlink, uninstalls all Brew packages, resets the Dock configuration, and finally removes Brew itself using its official uninstall script:

```
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/master/uninstall.sh)"
```

The author notes that deleting Brew alone does not remove pip-installed dependencies, which is why all uninstall steps are listed explicitly. Some evidence of the installation (data files in Desktop or Documents) will remain and must be deleted manually.

## Windows OSINT Host

### Tool Choices and Batch Files

The author considered Windows Subsystem for Linux (WSL) but rejected it due to version inconsistencies between WSL 1 and WSL 2 and file-storage complications. PowerShell was considered but judged as overkill. The final approach uses traditional batch files (.bat) executed from Command Prompt.

Batch files parallel the Bash scripts used on Linux and Mac. They present menus, accept user input, change directories, execute Python scripts, redirect output to text files, and loop back to the home screen. The chapter prints and annotates the full Username Tool batch file (usertool.bat) to illustrate the syntax, explaining each directive:

- `@echo off`: suppresses command echoing
- `title`: sets the window title
- `:home`: labels the home section
- `cls`: clears the screen
- `echo`: displays text
- `set /p`: accepts user input
- `if "%web%"=="1" goto 1`: routes to a labeled section based on input
- `cd %userprofile%\...`: changes directory to a tool's location
- `py script.py %url%`: invokes Python with the user-supplied value
- `> %userprofile%\Documents\...-Tool.txt`: writes output to a text file
- `start "" ...`: opens the output file
- `goto home`: returns to the menu

All Windows scripts are included in the windows-files.zip archive at https://inteltechniques.com/osintbook9/windows-files.zip.

### Package Manager: Chocolatey

For Windows, Chocolatey is the package manager equivalent to Brew on Mac. It is installed by running a PowerShell command from an Administrator Command Prompt. The command downloads and executes the Chocolatey install script from chocolatey.org/install.ps1 and adds the Chocolatey bin directory to the system PATH.

### Core Applications via Chocolatey

A single choco install command installs: python3, youtube-dl, yt-dlp, googlechrome, ffmpeg, httrack, exiftool, exiftoolgui, ripgrep, vlc, tor-browser, googleearthpro, keepassxc, mediainfo, git, curl, unzip, wget, phantomjs, streamlink, firefox, and sed. A reboot is required after this step.

### Firefox Configuration on Windows

Firefox is configured by downloading the same ff-template.zip from the author's site and copying its contents into the default-release Firefox profile directory using xcopy.

### Custom Windows Scripts and Tools

tools.zip and windows-files.zip are downloaded from the author's site and extracted to the Desktop and Documents folders respectively. These contain the pre-configured .bat scripts and other assets.

### Python Tools on Windows

Python OSINT tools are installed via pip using an Administrator Command Prompt. The same set of packages used on Mac is installed (youtube-tool, Instaloader, toutatis, nested-lookup, internetarchive, webscreenshot, redditsfinder, socialscan, holehe, waybackpy, gallery-dl, xeuledoc, bdfr, search-that-hash, h8mail). The same GitHub repositories are cloned under `%userprofile%\Downloads\Programs`.

One difference from Mac: a specific Python version (3.9.4) is installed via Chocolatey alongside the default python3, because some tools require it. Where appropriate, `c:\Python39\python.exe -m pip install` is used instead of `py -m pip install` to target that version.

## General Notes

- All software covered is described as free for personal and commercial use without licensing restrictions.
- The tutorials assume a fresh Mac or Windows installation but are expected to work on existing installations, which may produce errors from conflicts with pre-existing software.
- Errors from previous editions of the book's build steps can generally be ignored. Running the update script at the end resolves version mismatches.
- PATH issues on Mac (missing Brew tools) are diagnosed with `brew doctor`.
- The builds produce machines that replicate practically every aspect of the Ubuntu OSINT VM described in the book.
