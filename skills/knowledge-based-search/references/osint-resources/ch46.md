This unit covers the latter portion of Chapter 28. It explains how to identify and crack password hashes found in breached data, query breach databases online and locally, locate unintentionally exposed data in open Elasticsearch servers, find SQL databases through Google, build and query a Usenet archive, and work with ransomware data and stealer logs.

## Hash Types and Dehashing

Breached credential files store passwords in hashed form rather than plain text. The typical file format is `email:hash` or `email:hash:salt`. Three formats appear most often.

**MD5** is the weakest format. A raw entry looks like `user@gmail.com:482C811DA5D5B4BC6D497FFA98491E38`. Searching the hash in a reverse-lookup service such as Hashes.org returns the plain-text password ("password123" in this example). MD5 hashes crack quickly.

**MD5 with salt (VBulletin)** adds a short salt string after the hash, separated by a colon. Both the hash and the salt are required to reverse the password. The entry `user@domain.com:9d9e3c372d054c0769bd93181240be36:tye` resolves to `eliza!%`. Semi-complex passwords with special characters are often already present in large dehashing databases.

**SHA1** is more secure than MD5 but still easy to crack. The LinkedIn breach used SHA1. Case matters: `letmein!` and `LetMeIn!` produce completely different SHA1 hashes. Investigators must search both forms.

### Dehashing Tools

Online options include `https://osint.sh/md5/`, `https://md5decrypt.net/en/`, `https://md5decrypt.net/en/Sha1/`, `https://www.dcode.fr/sha1-hash`, and `https://md5hashing.net/hash/sha1`. These are limited to simple passwords already in their dictionaries.

**Search That Hash** (`github.com/HashPals/Search-That-Hash`) queries multiple online converters at once. Install with `sudo -H pip install search-that-hash -I` and call with `sth --text "hash_value"`. The tool identifies the hash type and returns the plain-text password when possible. It is integrated into the OSINT VM as the "Breaches/Leaks Tool".

When online tools fail, a locally stored Hashes.org dataset is the fallback.

## Online Breach Search Resources

Several services allow querying breach data by various identifier types through direct URL submission, enabling automation.

**Email address** (`test@test.com`): haveibeenpwned.com/unifiedsearch/test@test.com, dehashed.com/search?query=test@test.com, portal.spycloud.com, check.cybernews.com, intelx.io.

**Username** (`test`): haveibeenpwned.com/unifiedsearch/test, dehashed.com/search?query=test.

**Domain** (`inteltechniques.com`): dehashed.com, intelx.io.

**Telephone, IP address, name, password, hash**: dehashed.com/search?query= accepts all of these. Google is also listed for passwords and hashes.

Sites without URL-based submission include LeakPeek (leakpeek.com), LeakedSource (leakedsource.ru), We Leak Info (weleakinfo.to), and Breach Directory (breachdirectory.org). These services change frequently and may have shut down by the time of reading.

**H8Mail** (`github.com/khast3x/h8mail`) aggregates many of these services into a single command-line utility.

Install and configure:
```
sudo -H pip install h8mail -I
cd ~/Downloads && h8mail -g
sed -i 's/\; leak\-lookup\_pub/leak\-lookup\_pub/g' h8mail_config.ini
```

Run a basic query: `h8mail -t bill@microsoft.com`

Without API keys this produces little output. Adding keys for Snusbase, WeLeakInfo, HaveIBeenPwned, Dehashed, and others produces far more results. In `h8mail_config.ini`, any line beginning with a semicolon is inactive. Removing the semicolon enables that service. The public Leak-Lookup key is pre-configured by the sed command. A search of `test@email.com` with the public key confirmed presence in breaches from TicketFly, TrueFire, and Tumblr.

## Local Breach Database Queries

With breach data stored on an external drive, navigate to it in Terminal (`cd '/media/osint/1TBExternal/'`) and use Ripgrep to search all files at once.

Search by email address: `rg -a -F -I -N johndoel287@gmail.com`

If a password is returned (for example `H8teful0ne45`), search for that password across all data: `rg -a -F -I -N H8teful0ne45`

This may reveal additional accounts using the same password. Similar usernames combined with a shared unique password is strong evidence of the same person.

To search databases that store hashed rather than plain-text passwords, convert the known password into each common hash format using online generators at `https://passwordsgenerator.net/md5-hash-generator/` (and equivalent SHA1 and SHA-256 pages), then search each hash with Ripgrep. Example hashes for the password `H8teful0ne45`:

- MD5: `9EF0EC63E2E52320CB20E345DCBA8112`
- SHA1: `D15FB15C1BC88F4B7932FD29918D1E9E9BBE7CA5`
- SHA-256: `37A790A268B9FE62B424BABFC3BCAB0646BFB24B93EC1619AAE7289E0D7086DB`

A search for the SHA1 hash returned a result placing the same password in a breach associated with the Houston Astros, warranting further investigation.

Attribution confidence depends on password uniqueness. A password like `H8teful0ne45` with recognizable username patterns strongly suggests the same individual. The password "password1234" across hundreds of sites has no attribution value.

Query speed depends heavily on hardware. Parsing 2TB of data on an internal SSD takes a few minutes. A spinning external drive triples that time. A dedicated machine with a 4TB internal SSD is recommended for daily use.

## Data Leaks via Open Elasticsearch Databases

A **data leak** is unintentional public exposure of data, typically from a misconfigured server, which differs from a deliberate criminal breach. Open Elasticsearch databases are a primary source of leaked data.

Shodan (shodan.io) is the main discovery tool. The search syntax is:
```
product:elastic port:9200 [keyword]
```

For example, `product:elastic port:9200 customer` finds databases containing an index named "customer". Shodan displays the IP address. Clicking through opens the live database in the browser.

To list all indexes in a found database, use the URL:
```
http://[IP]:9200/_cat/indices?v
```

Indexes are named sections within the database. Names like "customer", "leads", "member", and "bank" suggest personal data. Size matters: a 1KB index is not useful, while one containing gigabytes warrants investigation.

To view records in a specific index:
```
http://[IP]:9200/[indexname]/_search?size=100
http://[IP]:9200/[indexname]/_search?size=10000
```

The browser display limit is 10,000 records. Saving the page stores all visible content locally. For databases with millions of records, the crawler script is required.

**Elasticsearch Crawler** (`github.com/AmIJesse/Elasticsearch-Crawler`) downloads a full index and extracts only the specified fields.

Install:
```
cd ~/Downloads/Programs
git clone https://github.com/AmIJesse/Elasticsearch-Crawler.git
cd Elasticsearch-Crawler
pip install nested-lookup
```

Run: `python crawl.py`

The script prompts for the target IP address, index name, port (default 9200), and field names (email, first_name, last_name, phone, etc.). An empty field entry ends the list and the download begins. Output is saved as `[IP]-[indexname].txt` in the script directory, with one record per line.

The OSINT VM "Breaches/Leaks Tool" provides buttons for Shodan search, Index List, Index View, and Index Search. The Index Search option lets investigators search within a large index for a specific term without downloading all records.

Elasticsearch version 6.4.0 and newer blocks the crawler. Updating with `git pull https://github.com/AmIJesse/Elasticsearch-Crawler.git` may resolve this.

**Legal note**: Accessing open Elasticsearch data is technically public but sits in a legal grey area under the Computer Fraud and Abuse Act (CFAA), which is vague and broadly interpreted. Using such data to sell, extort, or publish it is criminal. The author recommends confirming that local laws and internal policies permit these techniques before using them, and notes he is not an attorney.

## SQL File Searches via Google

SQL (Structured Query Language) files are database exports. Many major breaches were originally released as SQL files. WordPress backups and forum exports also use this format. Google dorking locates publicly accessible SQL files by progressively narrowing:

```
ext:sql
ext:sql "create table"
ext:sql "create table" "@gmail.com"
ext:sql "create table" "@gmail.com" "'password'"
ext:sql "create table" "gmail.com" "'password'" "@yahoo.com" -site:github.com
ext:txt "create table" "gmail.com" "'password'" "yahoo.com" -site:github.com
```

The phrase `"create table"` is a standard SQL statement that filters out pages merely ending in `.sql`. Adding multiple email domains and excluding github.com narrows results from millions to a few hundred, each representing a SQL database containing real email addresses and a password table. A typical SQL record contains user ID, name, username, email address, a hashed password, user type, registration date, and last-visit date.

Pages can be saved as `.txt` files for a local archive. The author warns to use a Linux VM and a reputable VPN when browsing results due to trackers and malware present in this environment.

## Usenet Archives as a Public Data Set

Usenet is a decades-old discussion system. The Internet Archive hosts two major collections: `archive.org/details/giganews` and `archive.org/details/usenethistorical`. Together they contain over 43 million unique email addresses along with name, newsgroup, and subject data.

Install the Internet Archive command-line client: `pip install internetarchive`

Create item lists for both collections:
```
cd ~/Desktop
ia search 'collection:giganews' -i > giganews1.txt
ia search 'collection:usenethistorical' -i > usenethistorical1.txt
```

Download only CSV files (not the full message archives, which exceed a terabyte):
```
ia download --itemlist giganews1.txt --glob="*.csv.gz"
```

Decompress: `gunzip -r .`

Combine all CSV files into one, keeping columns 1, 3, 4, and 5 (date, name, email, newsgroup):
```
find . -type f -name \*.csv -print0 | xargs -0 cut -f1,3,4,5 > Giganews2.txt
```

For the Usenet Historical collection, download zip archives and extract From lines:
```
ia download --itemlist usenethistorical1.txt --glob="*.zip"
find . -name "*.zip" -exec unzip {} \;
rg -a -F -i -N "From: " > UsenetHistorical2.txt
```

Merge both files and remove duplicates:
```
sort -u -f Giganews2.txt UsenetHistorical2.txt > UsenetFinal.txt
```

Query the final file: `rg -a -F -i -N bazzell UsenetFinal.txt`

Practical uses include finding old email addresses that lead to otherwise unknown social profiles, identifying a target's interests from the newsgroups they posted to, verifying an email account's existence and minimum age, finding multiple addresses associated with a domain, and uncovering historical usernames or passwords. The author describes a case in which a newsgroup username matched a password in a breach dataset, which through a chain of searches eventually revealed the true name of an anonymous target.

The author has made a pre-built Usenet file available at `https://mega.nz/file/mSJGGDYI#oNIeyaG2oIHcHQFfGeFuq3zxUp_cCgARVf6bQNqp91s` (shortlink: `https://bit.ly/36937Pk`). The file contains name, email, and newsgroup fields from both collections with duplicates removed. It is 12GB uncompressed and 3GB compressed.

## Ransomware Data

Ransomware groups that fail to receive payment from victims publish stolen data on Tor (.onion) websites. The data includes private documents, databases, and email archives. The author considers this data outside the definition of OSINT, but notes investigators working on behalf of victim organizations need to know how to locate it.

Direct URLs are not provided, but Google queries can surface relevant Tor site information:
```
".onion" "Dopple" "ransomware" "url"
".onion" "Ragnar" "ransomware" "url"
".onion" "REvil" "ransomware" "url"
".onion" "Conti" "ransomware" "url"
".onion" "Vice Society" "ransomware" "url"
".onion" "Clop" "ransomware" "url"
".onion" "Nefilim" "ransomware" "url"
".onion" "Everest" "ransomware" "url"
".onion" "Cuba" "ransomware" "url"
```

The search `site:https://app.hacknotice.com "onion"` surfaces ransomware publication announcements on Hack Notice that include Tor URLs where stolen data is hosted.

## Stealer Logs

Stealer logs are text files exfiltrated from computers infected with malware, typically bundled into pirated software. They contain usernames, passwords, browser autofill data, IP addresses, screen captures, and system identifiers such as device names. Because the credentials are recently stolen, they are more likely to reflect current active passwords than older breach data.

Google queries to locate stealer log collections:
```
"stealer logs" "download"
"stealer logs" "Azorult"
"stealer logs" "Vidar"
"stealer logs" "Redline"
"stealer logs" "Raccoon"
```

Many results lead to criminal marketplaces. The author recommends extreme caution. Once a local collection is assembled, Ripgrep queries work the same way as with breach databases. In a case example, a throwaway email address not found in any breach appeared in stealer logs that also included a device name (`Desktop-u3ty6`). Searching that device identifier revealed dozens of additional email addresses and passwords used on the same machine, identifying the suspect as a 15-year-old whose computer was infected after downloading pirated antivirus software.

## Storage and Hardware Considerations

A VM with less than 100GB of allocated disk space will run out of room when collecting breach and leak data. External spinning drives are significantly slower than internal SSDs. The techniques work on any operating system with the required tools installed. For daily use, the author recommends a dedicated Linux host with a 4TB SSD internal drive. This machine should be used only for data storage and querying, not for conducting active online investigations, to limit exposure to malicious content in these environments.

## IntelTechniques Breaches and Leaks Tool

The OSINT VM includes a graphical tool that consolidates the online breach resources described throughout the chapter. Input fields are organized by type: email address, username, domain, telephone number, IP address, name, password or hash, and Elasticsearch queries. The tool links to services including HIBP, Dehashed, IntelX, CyberNews, and Spycloud. A password field at the bottom generates MD5, SHA1, and SHA-256 hashes for follow-up searches within local data.
