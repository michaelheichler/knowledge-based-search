## Windows Host Build: Python Tool Installation

This section completes the Windows OSINT workstation setup from Chapter 6. After Chocolatey and Firefox are configured, the next step is installing custom Python-based OSINT tools. Each tool is cloned from GitHub and its dependencies installed via pip. The commands use both `py` (Python 3.10) and `python` (Python 3.9) because some tools perform better with one version than the other. If a tool fails to run, open its launch script and switch between `py` and `python`.

Tools installed in this phase, each via `git clone` followed by `py -m pip install -r requirements.txt -I`:

- Sherlock (username search): `https://github.com/sherlock-project/sherlock`
- WhatsMyName: `https://github.com/WebBreacher/WhatsMyName`
- email2phonenumber: `https://github.com/martinvigo/email2phonenumber`
- Amass (subdomain enumeration, OWASP): downloaded as a zip binary from `https://github.com/OWASP/Amass/releases/latest/download/amass_windows_amd64.zip`
- Sublist3r: `https://github.com/aboul3la/Sublist3r`
- Photon: `https://github.com/s0md3v/Photon`
- theHarvester: `https://github.com/laramies/theHarvester`
- Carbon14: `https://github.com/Lazza/Carbon14`
- ExifTool GUI: zip download from `https://exiftool.org/gui/exiftoolgui516.zip`
- sherloq (image forensics): `https://github.com/GuidoBartoli/sherloq`
- metagoofil: `https://github.com/opsdisk/metagoofil`
- recon-ng (dependencies installed from a file named `REQUIREMENTS`, not `requirements.txt`): `https://github.com/lanmaster53/recon-ng`

All commands are available at the bottom of the `windows.txt` file hosted on the author's website so that updates can be applied when steps change.

Once installed, desktop shortcuts are created by dragging files from `Documents\windows-files\shortcuts`. The author does not provide a single combined installer command for Windows, for the same reasons given for Mac: each step must be run manually to catch errors.

## Windows Tool Updates

To keep all tools current, run a single update script or enter the following as Administrator:

```
choco upgrade all -y
pip freeze > requirements.txt
sed -i "s/==/>=/g" requirements.txt
pip install -r requirements.txt -U -I
del requirements.txt
```

Then navigate into each cloned tool directory and run `git pull` against its source repository.

## Reversing the Windows Build

To undo all changes and return the machine to its prior state, uninstall pip packages from each tool directory with `py -m pip uninstall -r requirements.txt -y`, then run:

```
rmdir /Q /S %userprofile%\Documents\windows-files\
rmdir /Q /S %userprofile%\Downloads\Programs
choco uninstall all
rmdir /Q /S \ProgramData\chocolatey
```

Delete desktop shortcut links with `del *.lnk`. After these steps, applications and visual traces are removed, though low-level installation artifacts may remain in the OS file structure.

## Mac and Windows Limitations

Neither Mac nor Windows fully replicates the Linux VM environment.

On macOS, some Homebrew-installed utilities (notably `phantomjs`) may be blocked by Gatekeeper because the developer is not Apple-verified. The workaround is to open System Preferences, go to Security and Privacy, then General, and click "Open Anyway" for the blocked app.

On Windows, batch files may trigger a warning ("prevented an unrecognized app from running") because they are not signed. Clicking "Run Anyway" on first execution resolves it.

Apple M1 (ARM) machines may have extensive compatibility problems, particularly with virtualization, due to chip architecture differences.

Some Windows applications such as Osintgram may fail due to Python 3.9/3.10 conflicts. The scripts include redundant pip invocations to mitigate most conflicts, but some tools may still behave poorly.

The summary at the end of Chapter 6 notes that on Mac and Windows, WebScreenShot replaces EyeWitness, and recon-ng is not available on Windows. All other tools function the same as on Linux.

## Chapter 7: Android Emulation

### Why Emulation Is Necessary

A large portion of current social media activity takes place on mobile devices only. Services including Snapchat, Tinder, and Kik have no usable web interface. Investigators who work only from a desktop miss content and functionality that is central to many investigations.

The case for emulation over using a real phone rests on three grounds. First, documentation: mobile screen captures are small, exporting images is cumbersome, and writing a report from a phone is tedious. An Android VM running inside a standard computer allows full-screen captures, video recording of an entire session, and direct pasting of findings into a report. Second, legal exposure: using a personal or work phone for investigations creates a device that opposing counsel can request in discovery for independent forensic analysis. Third, malware containment: a compromised mobile device can affect all future investigations conducted on that hardware. An emulated device is isolated and can be discarded.

A key benefit is that unlimited virtual devices can be created, one per investigation, eliminating cross-contamination between cases.

### Why Android, Not iPhone

iPhone simulators run only on Apple hardware, have limited features, do not connect to most real applications, and offer almost no value for OSINT. Android VMs work on any major operating system and provide full application functionality.

### Why Not Genymotion

Previous editions of the book relied on Genymotion. The author no longer recommends it as a starting point. The free version is increasingly difficult to find and carries strict licensing restrictions. Many mobile applications detect Genymotion virtual devices and crash immediately on load. Genymotion now requires an online account for any download and transmits usage data to its servers during operation. The preferred alternative is building Android VMs directly in VirtualBox without any third-party container software, and without entering Google account credentials.

### Android Image Sources

Two trusted sources provide Android images formatted for VirtualBox:

- OS Boxes: `https://www.osboxes.org/android-x86/` (VDI format, also offers VMware builds)
- Linux VM Images: `https://www.linuxvmimages.com/images/android-x86/` (OVA format, VirtualBox only)

Download the latest 64-bit version. At the time of writing, the version used is Android-x86 9.0 R2 Pie for VirtualBox.

### VirtualBox Setup for a VDI File

1. Open VirtualBox, click "New".
2. Provide a name such as "Android 9.0 VM" and a storage location.
3. Type: "Other". Version: "Other/Unknown (64-bit)".
4. Memory: at least 4096 MB, preferably 8192 MB.
5. Select "Use an existing virtual hard disk file", click the folder icon, click "Add", select the unzipped VDI file, click "Open", then "Choose", then "Create".
6. Right-click the new device, choose "Settings".
7. Under "Processor", select half of available cores.
8. Under "Display", set maximum video memory.
9. Click "OK".

### VirtualBox Setup for an OVA File

1. VirtualBox menu: "File" then "Import Appliance".
2. Click the folder icon, select the OVA file, click "Open", "Continue", "Import". Agree to any terms of service.
3. Right-click the new device, choose "Settings".
4. Rename if desired (e.g., "Android 9.0 VM (OVA)").
5. Under "System", set memory to at least 4096 MB, preferably 8192 MB.
6. Under "Processor", set half of available cores.
7. Under "Display", set maximum video memory.
8. Click "OK".

### First Launch and Display

Double-click the virtual device to start it. The window may be small. To enlarge: in the VirtualBox menu, select "View", highlight "Virtual Screen", then choose an expanded scale such as "Scale to 150%".

The cursor locks inside the Android window once clicked. The "Host Key" releases it. On Mac, this is typically the left Command key. On Windows, it is typically the right Ctrl key. The key is shown in the lower-right corner of the VirtualBox window.

### Initial Android Configuration

- Click and hold unwanted home screen icons, drag up to remove them.
- Drag the bottom black bar up to reveal all installed applications.
- Click and hold desired apps (Chrome, Settings) to place them on the home screen.
- Settings, Display: set Sleep to 30 minutes.
- Settings, Security and location: set Screen Lock to "None" and Location to "On".

### Installing Apps Without a Google Account

To avoid associating a Google account with investigations, the author uses a two-step anonymous install process through F-Droid and Aurora Store.

1. Open Chrome in the Android VM.
2. Decline sharing analytics with Google. Deny any Google account prompt.
3. Search "F Droid", click the first link, download and install F-Droid. Authorize installation when prompted.
4. Inside F-Droid, search "aurora store", select Aurora Store, install it, and open it.
5. At Aurora Store setup, click "Next", then "Ask", then "Allow" to grant permissions.
6. Select "Anonymous" to bypass Google account login.
7. Use Aurora Store to search and install any desired app.

F-Droid is an open-source package installer for Android. Aurora Store is an anonymous replacement for the Google Play Store. All subsequent app installation goes through Aurora Store.

### GPS Spoofing

The virtual device has no GPS chip, Wi-Fi radio, or cellular connection. Location-dependent apps require a mock location.

Using Fake GPS:
1. Open the Fake GPS app and follow the prompts to enable "Mock Locations".
2. If the automated process fails, enable Developer Options manually: Settings, System, About Tablet. Tap "Build Number" seven times.
3. In Settings, System, Developer Options, select "Select Mock Location App" and choose Fake GPS.
4. Open Fake GPS, zoom to the desired area, tap the play icon in the lower-right.
5. Open Chrome, navigate to `maps.google.com`, and confirm the displayed location matches the spoof.

### Connectivity and Performance

Internet access routes through the host computer. If apps lose connectivity unexpectedly, disable and re-enable Wi-Fi under Android Settings. To shut down, click "X" on the VirtualBox window and choose "Send the Shutdown Signal". Select "Power Off" or "Restart" from the Android menu that appears. If no menu appears, repeat and choose "Power off the machine" in VirtualBox.

Speed is a persistent limitation of any Android VM, including premium third-party solutions. Increasing processor or memory allocation does not noticeably improve responsiveness. Recommended practices: boot the device and let it finish all updates before beginning any investigation. Keep the number of installed apps minimal for speed-sensitive work. Do not run multiple apps at once. Reboot if the device is unusually slow.

### Application-Specific Notes

**Facebook, Messenger, and Instagram.** The Android Facebook app can use the Check In feature, which shows real businesses near the spoofed GPS location. Creating a post with Check In builds a verifiable record of the spoofed location within the profile. This can establish credibility for a pseudo identity. The author describes using this technique to help a domestic violence victim mislead an abusive ex-partner who monitored her social media location data.

**WhatsApp.** Requires a phone number for account verification. The number can be cellular, landline, or VOIP. Google Voice and MySudo numbers work. WhatsApp is useful for targets who refuse traditional SMS but communicate freely through the app.

**Twitter.** Sharing the spoofed location within Twitter makes the account appear to be at a location other than the investigator's real position. This is useful when a target is expected to monitor the investigator's social media activity, because it sends the target to the wrong location.
