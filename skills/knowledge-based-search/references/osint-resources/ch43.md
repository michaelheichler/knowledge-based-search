## Overview

This unit concludes Chapter 26 (Virtual Currencies) and covers Chapter 27 (Advanced Linux Tools). The chapter presents four Linux-based OSINT applications, each pre-installed in the custom OSINT virtual machine described earlier in the book. The author's premise is that these tools automate tasks that would otherwise consume hours of manual work, and that readers at any skill level can replicate the tutorials.

The author notes two constraints up front. He does not reproduce full script code in the text, because it is available in the "scripts" and "shortcuts" folders of the previously downloaded "vm-files" archive. Every application is already installed in the custom OSINT VM from Chapter Five, so manual installation steps are provided for understanding rather than for routine use.

## Virtual Currencies Wrap-up (Chapter 26 tail)

### Currency conversion API endpoints

Replace `xxx` with the target value in all URLs below. Prices fluctuate hourly.

BTC to USD:
```
http://codacoin.com/api/public.php?request=convert&type=btctofiat&input=xxx&symbol=enabled&decimal=2&exchange=average&currency=USD&denom=bitcoin
```

Satoshi to USD:
```
http://codacoin.com/api/public.php?request=convert&type=btctofiat&input=xxx&symbol=enabled&decimal=2&exchange=average&currency=USD&denom=satoshi
```

USD to Satoshi:
```
http://codacoin.com/api/public.php?request=convert&type=fiattobtc&input=xxx&symbol=enabled&decimal=10&exchange=average&currency=USD&denom=satoshi
```

### Bitcoin address summary (BTC.com API)

Returns total received, total sent, balance, tx_count, first_tx hash, and last_tx hash.
```
https://chain.api.btc.com/v3/address/xxx
```

### First-seen date (Blockchain.info)

Returns the Unix timestamp of the first transaction for an address. The IntelTechniques tools include a converter for Unix time.
```
https://blockchain.info/q/addressfirstseen/xxx
```

### Worked investigation example

The address `1EzwoHtiXB4iFwedPr49iywjZn2nnekhoj` was used in an extortion email. Querying it produced: valid format, balance of 37,699,570 Satoshi ($7,205.23 USD), total received of 716,409,285,544 Satoshi ($136,925,336.62 USD), 3,534 transactions, Unix creation time 1331482301 (March 11, 2012 10:11:41 UTC), one BitcoinAbuse malicious-activity report with an associated email address, Reddit links from BitcoinWhosWho, and a WalletExplorer wallet ID of 00037fd441 with additional Bitcoin addresses in the same wallet. The investigator would then repeat the process on each newly discovered address and run any found email address through separate tools.

### Scam Search (scamsearch.io)

Scamsearch.io accepts virtual currency addresses in addition to email addresses, usernames, and phone numbers. Searching the address `1FVuyuSN41aa3JN9sn8qkuD2PmaMEMHHnc` returned associated email addresses, IP addresses, and locations tied to an extortion suspect.

### IntelTechniques Virtual Currency Tool

A browser-based tool consolidates all of the above queries into a single interface. Input fields accept Bitcoin, Ethereum, Bitcoin Cash, Litecoin, Bitcoin SV, Dogecoin, and Dash addresses, plus wallet ID, Unix time, dollar amounts, Bitcoin amounts, and Satoshi amounts. Each button opens results in a new tab. A "Scam Report" option queries scamsearch.io directly.

## Internet Archive Tool (waybackpy)

The script `internetarchive.sh` wraps the Python library `waybackpy` (installed with `sudo -H python3 -m pip install waybackpy`). It accepts a single domain or URL and automates the following sequence, using `pretendradio.org` as the example target.

1. Creates a dedicated directory under `~/Documents/waybackpy/`.
2. Downloads all known archived URLs with `waybackpy --url "https://pretendradio.org" --known_urls`, producing a text file of over 500 URLs (with duplicates).
3. Retrieves the oldest known archive URL with `--oldest` and appends the newest with `--newest >> pretendradio.txt`.
4. Appends one representative URL per year from 2010 through 2020 with `--near --year YYYY`.
5. Deduplicates and sorts: `sort -u -i pretendradio.txt > pretendradio.sorted.txt`.
6. Generates screenshots of all unique archive links: `webscreenshot -chrome -i pretendradio.sorted.txt -1` (single thread, slower but stable).
7. Downloads HTML source of the oldest and newest archives with `--get oldest > oldest.html` and `--get newest > newest.html`.
8. Fetches offline HTML pages with `wget` on the sorted URL list.

The result folder contains a sorted URL list, archive snapshots as screenshots, and downloaded HTML pages. Screenshots allow quick visual comparison across years. The downloaded HTML files can be searched by keyword using the Linux Files application search. In the example, searching for "prison" flagged multiple files referencing the story "Jane Whaley's Son-in-Law is Going to Prison."

## GHunt

GHunt is a Terminal-based program that uses Google's internal APIs, requiring valid login cookies from an active Google account. The author recommends using a rarely-accessed account. Once cookies are extracted, the account must not be logged into again from a browser, because doing so invalidates the cookies.

**Installation:**

```bash
cd ~/Downloads/Programs
git clone https://github.com/mxrch/ghunt
cd ghunt
sudo -H pip install -r requirements.txt -I
```

**Cookie extraction.** Log in to Gmail, right-click and choose Inspect, open the Network Tab, navigate to `myaccount.google.com` in the same tab, select the row labeled "302 GET accounts.google.com," and click the Cookies tab. Record the values for: SID, SSID, APISID, SAPISID, HSID, LSID, and `__Secure-3PSID`.

**Configuration.** Run `python3 check_and_gen.py` from the GHunt directory (or use the "GHunt Configuration" option in the custom VM's Username/Email tool), then select "[3] Enter manually all cookies" and supply the seven values.

**Email query.** `python3 ghunt.py email larry@google.com` returned: name (Larry Page), profile photo URL (saved to `profile_pics/`), last profile edit date (2021/11/27 10:01:21 UTC), email address, GAIA ID (111627209495762463002), active Google services (Hangouts, Photos, Maps), four candidate YouTube channels with confidence percentages, a Google Maps contributor URL, and confirmation of no public calendar or map reviews.

**Google Document query.** `python3 ghunt.py doc https://docs.google.com/spreadsheets/d/1BxiMVsOXRA5nFMdKvBdBZjgmUUqptlbs740gvE2upms` returned: creation date (2011/05/12 18:29:28 UTC), last edit date, public permissions (reader), owner name (A Googler), owner email (gdocsteam@gmail.com), owner Google ID (02845897149113753960), and owner profile image URL.

**YouTube channel query.** `python3 ghunt.py youtube https://www.youtube.com/channel/UC_gHAQqoOUZ4ykZBCLdvww` returned: channel name (Thrice), snapshot date (12/09/2016), GAIA ID (105144584335156066992), country (United States), description, total views (78,701,229), join date (Dec 7, 2015), and six primary links (a release page, the band's website, Instagram, Twitter, Facebook, and Spotify).

**GAIA ID query.** `python3 ghunt.py gaia 105144584335156066992` returned: name (Thrice), profile photo URL, GAIA ID, candidate YouTube channels with confidence percentage (50%), and a Google Maps contributor URL.

All four query types are integrated into the custom VM's Username/Email tool on Linux, Mac, and Windows. The GAIA ID connects email, YouTube channel, and Maps profile to a single account. YouTube channel lookups expose linked social profiles. Google Doc queries reveal the owner's email even when the document appears anonymous. The custom script also saves all output to a text file in the Documents folder and opens all results upon completion.

## Spiderfoot

Spiderfoot is a web-based reconnaissance framework the author describes as providing more valuable utilities than any other single resource in the book. It targets domains, IP addresses, or email addresses.

**Installation:**

```bash
cd ~/Downloads/Programs
git clone https://github.com/smicallef/spiderfoot.git
cd spiderfoot
sudo -H python3 -m pip install -r requirements.txt
```

**Launch.** Run `python3 ./sf.py -l 127.0.0.1:5001`, then open `http://127.0.0.1:5001` in Firefox. The custom VM provides a pre-built script `spiderfoot.sh` in the Dock.

**Usage.** Click "New Scan," supply a session name and target domain, choose a use case, and click "Run Scan." The "All" (AU) use case is intrusive toward the target site. Choose the level appropriate to the investigation. Scans may run for hours.

**Example results for inteltechniques.com** included: four external site accounts connected to the author's brand, identification of the author's full name and three associates, 56 Pastebin files referencing the domain, two similar-spelling domains attempting to hijack traffic, and PHP version information from site pages. The Graph view displayed connections from the domain to a Reddit username, Gravatar profile, and email server. Multiple scans can run simultaneously. The Scans button allows stopping, re-running, or deleting any scan.

## Recon-ng

Recon-ng is a Python-based web reconnaissance framework with independent modules, a built-in database, interactive help, and command completion. The author warns it is technically complicated but walks through usage step by step. Version at time of writing: 5.1.1.

**Installation:**

```bash
cd ~/Downloads/Programs
git clone https://github.com/lanmaster53/recon-ng.git
cd recon-ng
sudo -H python3 -m pip install -r REQUIREMENTS
./recon-ng
```

**Launch.** Type `./recon-ng` from within the installation directory. A Dock icon is also available in the custom VM. Upon first launch, Recon-ng notifies the user that no modules are installed. This is normal. Modules are added as needed.

**Update:** `git pull https://github.com/lanmaster53/recon-ng.git` (included in the VM's `updates.sh` script).

**Help command.** Typing `help` at the prompt lists available commands.

| Command | Function |
|---|---|
| `back` | Exits the current context |
| `dashboard` | Displays a summary of activity |
| `db` | Interfaces with the workspace's database |
| `exit` | Exits the framework |
| `help` | Displays this menu |
| `index` | Creates a module index (dev only) |
| `keys` | Manages third party resource credentials |
| `marketplace` | Interfaces with the module marketplace |
| `modules` | Interfaces with installed modules |
| `options` | Manages the current context options |
| `pdb` | Starts a Python Debugger session (dev only) |
| `script` | Records and executes command scripts |
| `shell` | Executes shell commands |
| `show` | Shows various framework items |
| `snapshots` | Manages workspace snapshots |
| `spool` | Spools output to a file |
| `workspaces` | Manages workspaces |

**Module marketplace.** Typing `marketplace search` lists all available modules. The author compares a module to a web resource: just as Bing is used through a browser, `bing_domain_web` is a specific resource used within Recon-ng. Available module categories (at time of writing) include discovery, exploitation, import, and recon modules covering targets such as companies, contacts, credentials, domains, hosts, and locations.

## Key Takeaways

The four tools share a common pattern: accept a piece of target data, automate many queries that would otherwise require manual effort, and store or organize results for further analysis. The Internet Archive Tool preserves historical evidence from a domain. GHunt extracts account details, GAIA IDs, YouTube channels, and Google service activity from email addresses, Google documents, YouTube URLs, or GAIA IDs. Spiderfoot runs a broad passive or active scan against a domain, IP, or email and visualizes connections as a graph. Recon-ng provides a modular, database-backed framework the author describes as technically advanced, with a marketplace of modules for automated OSINT collection.
