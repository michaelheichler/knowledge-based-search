## Overview

This chapter covers the complete lifecycle of an OSINT virtual machine built on Ubuntu Linux inside VirtualBox. The core argument is that a single, clean, fully configured master VM should be created once and then cloned for every investigation, so each case begins from an identical, uncontaminated starting point. The chapter walks through Ubuntu installation, VirtualBox configuration, tool installation (basic and advanced), interface customization, an automated build script alternative, a software update routine, and VM backup and export. It also covers creating an optional Windows 10 VM.

## The Three-VM Strategy

The author recommends maintaining three persistent VMs at all times.

1. "OSINT Original" is the fully configured master. It is never used directly for browsing or investigation. The author updates it weekly and exports it monthly as a backup.
2. "Ubuntu Install" is a bare Ubuntu installation with no OSINT tools. A snapshot is kept here so a clean OS baseline is always recoverable.
3. "Ubuntu Install and Configuration" is Ubuntu with VirtualBox guest additions and OS-level settings applied, also kept at a snapshot. This layer is useful for testing new software before it touches the master.

For each new investigation, the investigator right-clicks "OSINT Original," selects Clone, chooses Full Clone, and names the clone after the case. All investigative work happens inside that clone. Evidence is transferred to a shared folder or USB drive. When the investigation ends, the clone can be exported for evidence retention or deleted.

## Ubuntu Base Installation

Boot an Ubuntu ISO inside a VirtualBox machine. During installation, choose Normal Installation, download updates, and include third-party software. Select "Erase disk and install Ubuntu." Set the username, computer name, and password all to "osint," and enable automatic login. After installation and first reboot, skip telemetry prompts and decline to help improve Ubuntu. Defer any update prompts, then power off. This is the point to create a snapshot or clone titled "Ubuntu Install."

## VirtualBox Guest Additions and OS Settings

With the VM powered off, open VirtualBox settings. Under General > Advanced, set Shared Clipboard and Drag and Drop to Bidirectional. Under Display, set video memory to the maximum. Under Shared Folders, add a host directory with Auto-mount enabled.

Start the VM, then insert the Guest Additions CD image via Devices in the VirtualBox menu. Authenticate when prompted, let the process complete, and press Enter. Power off again.

In the Ubuntu Settings application, disable all notifications, screen lock, file history and trash logging, diagnostics reporting, blank screen timeout, and automatic suspend. These changes prevent the VM from interrupting investigative sessions.

Run the following terminal commands to add the user to the VirtualBox shared-folder group, remove telemetry packages, and rebuild guest additions:

```
sudo adduser osint vboxsf
sudo apt purge -y apport
sudo apt remove -y popularity-contest
sudo apt update
sudo apt install -y build-essential dkms gcc make perl
sudo rcvboxadd setup
```

Apply all OS updates through Software Updater, then power off and create another snapshot or clone titled "Ubuntu Install and Configuration."

## Basic Tool Installation

Restart the "OSINT Original" VM and launch Firefox once to initialize its profile directory. The installation sequence downloads a credential-protected archive from inteltechniques.com using username "osint9" and password "bookl43wt" at `https://inteltechniques.com/osintbook9/vm-files.zip`. This archive contains scripts, icons, and application shortcuts. Scripts go to `~/Documents/scripts`, icons to `~/Documents/icons`, and shortcuts are copied to `/usr/share/applications/`.

Additional tools installed during this phase (via pip, apt, snap, git clone, or .deb package):

- Video tools: ffmpeg (apt), youtube-dl, yt-dlp, youtube-tool, streamlink (all pip), vlc (snap).
- Instagram tools: Instalooter, Instaloader, toutatis (pip), Osintgram (git clone from Datalux, requires libncurses5-dev and libffi-dev).
- Image and media downloaders: gallery-dl (snap, with removable-media connection), ripme (jar file from ripme GitHub releases, requires default-jre).
- Username search: Sherlock (git clone from sherlock-project), socialscan, holehe (pip), WhatsMyName (git clone from WebBreacher).
- Email and phone: email2phonenumber (git clone from martinvigo).
- Web and domain tools: EyeWitness (git clone from ChrisTruncer, setup.sh), amass (snap), Sublist3r (git clone from aboul3la), Photon (git clone from s0md3v), theHarvester (git clone from laramies, also requires testresources, pipenv, and webscreenshot pip packages), Carbon14 (git clone from Lazza).
- Browsers: Tor Browser (via ppa:micahflee/ppa), Google Chrome (downloaded as a .deb from dl.google.com).
- Metadata: mediainfo-gui (apt), ExifTool (apt package libimage-exiftool-perl), mat2 (apt), xeuledoc (pip), sherloq (git clone from GuidoBartoli).
- Website archiving: webhttrack (apt), metagoofil (git clone from opsdisk).
- Reddit: bdfr (via python3.9 -m pip), redditsfinder (pip), DownloaderForReddit (git clone from MalloyDelacroix).
- Mapping: Google Earth Pro (.deb from dl.google.com).
- Utilities: kazam (apt, screen recording), keepassxc (snap, password management).

After all installations, the sequence updates all pip packages in one command, then downloads a preconfigured Firefox profile template (`ff-template.zip`) from inteltechniques.com and copies it into the active Firefox profile directory. A second archive (`tools.zip`) is downloaded to the Desktop.

## Interface Configuration

The following gsettings commands configure the GNOME desktop: clear the wallpaper and set a solid background color of rgb(66, 81, 100), clear the Dock, move the Dock to the bottom, populate it with all OSINT application shortcuts (Firefox, Chrome, Tor Browser, Nautilus, Terminal, and every OSINT tool installed), and set the Dock icon size to 32 pixels.

## Automated Build Script

A colleague named Jesse created a shell script that replicates every manual step described in the chapter. The script is downloaded and executed with two commands:

```
wget --user osint9 --password bookl43wt https://inteltechniques.com/osintbook9/linux.sh
chmod +x linux.sh && ./linux.sh
```

The author recommends completing the manual build first to understand each step, then relying on this script when a fresh VM is needed quickly or when applying updates that have accumulated since the book's publication. The script runs inside either a VirtualBox VM or a bare Ubuntu host installation. If the script fails on any step, the manual commands can be used to isolate and fix the problem.

## Software Update Routine

Before cloning for a new investigation, update the "OSINT Original" VM. The sequence covers four categories: apt updates (`sudo apt update`, `sudo apt -y upgrade`, `sudo apt update --fix-missing`, `sudo apt --fix-broken install`), snap updates (`sudo snap refresh`), pip updates (using a pip list and xargs chain), and git pulls for each cloned repository: sherlock, WhatsMyName, EyeWitness, Sublist3r, Photon, theHarvester, Carbon14, metagoofil, sherloq, recon-ng, spiderfoot, Elasticsearch-Crawler, and GHunt. ripme.jar is re-downloaded with `wget -N` to pick up the latest release.

A script named `updates.sh` is included in the vm-files archive and accessible from the Dock via a circular arrow icon. Running it through the Applications menu automates the entire update sequence. The script ends by printing "Updates Complete!" in Terminal. The author stresses running this script often, because stock Ubuntu software updates do not touch the OSINT tools.

## VM Export and Backup

To guard against hardware failure or corruption, export the OSINT Original VM as an appliance file. The export path in VirtualBox is File > Export Appliance. This produces a single file (in OVA or OVF format) that can be imported into any VirtualBox instance with File > Import Appliance. The author keeps an exported copy on a USB drive for emergencies.

The author's personal maintenance schedule: update OSINT Original weekly, export it monthly, clone it for every new investigation, transfer evidence to external storage at the end of each case, and delete the investigation clone when it is no longer needed. Investigation VMs can also be exported and handed to other investigators or preserved as litigation discovery material. The author states he is prepared to testify with confidence because every investigation was conducted on a clean, isolated clone.

## Windows 10 VM

For work requiring Windows-only applications, a free 90-day trial image is available from Microsoft at `https://developer.microsoft.com/en-us/microsoft-edge/tools/vms/`. Select "MSEdge on Win10" and "VirtualBox," then download and unzip. Import the .ovf file into VirtualBox via File > Import Appliance. Before first launch, add an empty optical drive in Storage settings and create a snapshot. The login password is "PasswOrd!". Install Guest Additions through Devices > Insert Guest Additions CD, navigate to the mounted CD in File Explorer, and complete the installer. Reboot when prompted.

The 90-day trial can be reset by reverting to the original snapshot. Microsoft explicitly allows and encourages this. The VM displays a trial watermark on the desktop. A paid license is required to remove it, but the free image is otherwise fully functional.

## Closing Notes

The author credits David Westcott for introducing the Linux customization techniques described in this chapter. He acknowledges that some tool installations will fail due to dependency changes or upstream breakage, and advises keeping the update routine running so that future releases resolve current failures. The educational value of building the VM manually is emphasized over the convenience of the automated script: a reader who understands each step is better positioned to debug problems and adapt when tool repositories change.
