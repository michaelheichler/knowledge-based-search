## Context and Ethics

This unit covers investigative use of publicly released stolen databases. The author identifies two groups that download such data. The first are amateur criminals who perform credential stuffing, taking a username-and-password pair exposed in one breach (for example, LinkedIn) and trying it against other services (for example, Gmail or Twitter). The author states this is illegal and unethical. The second group are security researchers who download the data, restrict its further distribution, and use it only to improve their own systems. The author argues that since tens of thousands of criminals already use this data to "dox" targets (publicly exposing personal information about a person, a tactic commonly used against law enforcement officers following high-profile incidents), investigators are justified in applying the same techniques to research criminals. Investigators should apply their own judgment and be aware of any employer policies or security-clearance rules that prohibit possessing such data.

## Specific Databases Archived on archive.org

Several breach data sets exist in the Internet Archive because the original hosting sites were taken down. Three examples are covered.

### Kyle Data ("Special K") Spam List

This database contains 178,288,657 email addresses along with associated fields: name, city, state, ZIP code, IP address at collection time, and the website from which the marketing data was gathered. It was temporarily hosted at updates4news.com in November 2015 and is preserved in the Wayback Machine at:

`https://web.archive.org/web/20151110195654/http://www.updates4news.com:80/kyledata/`

The archive holds hundreds of individual CSV files. Downloading them all overnight with a browser extension and then merging them with `cat * > SpecialK.txt` produces a single 19.73 GB file. A Ripgrep search against that file can convert a known email address into a full dossier: name, location, IP address, and the site from which the data originated. This kind of detail is not available through public websites.

### LinkedIn User-ID-to-Email File

A 2017 data set available at `https://archive.org/details/LlLJsers.7z` maps LinkedIn user ID numbers to the email addresses used to create those accounts. It contains no passwords, which is why archive.org preserves it. It supports two directions of lookup. Given a target's email address, a search returns the LinkedIn profile ID number. Given a profile ID (which can be read from a LinkedIn profile's HTML source by searching for the string "member" and locating the numeric value near the bottom of the results), a search returns the email address used to create that account. This is significant because the email used to register a LinkedIn profile is not displayed on the public profile page. In a real investigation, the author extracted a target's personal email address from the LinkedIn profile ID, which then led to old passwords and additional accounts.

### Snapchat Breach (2014)

In January 2014, 4.6 million Snapchat usernames and associated phone numbers were exposed. The file `SnapChat.7z` is available at `archive.org/download/SnapChat.7z`. The last two digits of each phone number are redacted. Searching by username returns the partial phone number. Searching by partial username (for example, "topher4") returns all matching usernames and their partial numbers, which is useful when only part of a username is known. Searching by partial phone number returns all Snapchat usernames registered to numbers matching that prefix, which may reveal additional accounts belonging to the same device.

In a real human-trafficking investigation, the author searched a suspect's Snapchat username and recovered the first eight digits of his phone number. Broadening the search to similar usernames in the same area code, then using reverse caller ID APIs to identify owners of all 100 possible full numbers, reduced the field to three males fitting a physical description. A cooperating witness identified the suspect from those three.

## Credential Compilation Lists

### COMB (Compilation Of Many Breaches)

In 2021, an unknown group published 3.2 billion email-address-and-password pairs assembled from many breaches including LinkedIn, Dropbox, Myspace, and Adobe, along with thousands of smaller ones. The compiled set is called "Compilation Of Many Breaches" (COMB). The file `CompilationOfManyBreaches.7z` can be located by searching Google for the filename or by using the search operator:

`site:anonfiles.com "CompilationOfManyBreaches.7z"`

At the time of writing, this returned a torrent file openable with Transmission. The compressed file is 20 GB and decompresses to 106 GB. The archive password, posted on Twitter at `https://twitter.com/BubbaMustafa/status/1370376039583657985`, is `+w/P3PRqQQoJ6g`. Decompression tools: 7-zip (Linux or Windows), Keka (Mac). The author recommends downloading to a 1 TB external USB drive connected to a Linux VM, which keeps the VM clean and makes the data accessible to multiple machines.

COMB includes a native query script. From inside the `CompilationOfManyBreaches` folder, running `./query michael.bazzell@gmail.com` returns any matching record within seconds. Mac users run `bash /query michael.bazzell`. A partial prefix (for example, `./query michael.bazzell`) returns all matching email addresses across providers. The tool requires an exact string and cannot search by domain or by password. For those operations, Ripgrep is used instead.

### Searching COMB with Ripgrep (rg)

Ripgrep flags used throughout: `-a` (treat binary files as text), `-F` (fixed string, not regex), `-i` (case-insensitive), `-N` (suppress line numbers).

Searching by a full email address returns the password associated with it. Searching by a password returns every account in the database that used that password. Because many people reuse passwords across services, a target's work email password may also appear paired with a personal email address. The author describes a 2017 child-pornography investigation in which a suspect email address (registered under an alias) returned a unique password, which appeared in only one other account, the suspect's personal Gmail in his real name. The primary investigator made an arrest the next day.

Searching by an email domain (for example, `@altonpolice.com`) returns all credentials from that organization's accounts.

### Finding Additional Leaks

The site `haveibeenpwned.com/PwnedWebsites` lists known breaches. When a new breach appears there, the author recommends searching Google for the breach data using "Index Of" file-extension operators such as:

`"myspace" ext:rar OR ext:zip OR ext:7z OR ext:txt OR ext:sql`

Searching Pastebin via Google for a target's email address often returns paste dumps containing additional credential sets. Researchers with time to invest can accumulate more than 10,000 databases totaling over two terabytes from public sources alone. The author advises against buying databases from online sellers: buyers are frequently defrauded, and the money goes to criminals.

## Password Hashing

Most websites store passwords as hashes rather than plain text. A hash is a one-way transformation that converts a password into a fixed string called the hashed password. Common algorithms found in breach data, in order of increasing security:

- MD5: Older, insecure. The hash of "password1234" is `BDC87B9C894DA5168059E00EBFFB9077`.
- SHA1: Longer than MD5 but still crackable. The hash of "password1234" is `E6B6AFBD6D76BB5D2041542D7D2E3FAC5BB05593`.
- SHA256: `B9C950640E1B3740E98ACB93E669C65766F6670DD1609BA91FF41052BA48C6F3`.
- SHA512: Longer still, more resource-intensive to crack.

Some databases add a "salt" (extra data mixed into the password before hashing) which makes cracking harder. If a breach does not include the salt value, the passwords are nearly impossible to crack. If the salt is present, recovering the plain-text password requires considerable additional resources.

Identifying which algorithm produced a given hash can be done using TunnelsUp at `tunnelsup.com/hash-analyzer`.

### Hashes.org Archive

Hashes.org was a service that maintained billions of pre-cracked hash-to-plaintext mappings, allowing a submitted hash to be resolved to the original password. The service closed in late 2020. Its full archive (90 GB compressed) is available as a torrent via magnet links posted at:

- `https://pastebin.com/pS5AQNVO`
- `https://defuse.ca/b/bgQpxtmO`
- `https://old.reddit.com/r/DataHoarder/comments/ohlcye/hashesorg_archives_of_all_cracked_hash_lists_up`

After download, the archive contains two folders, "Hashlists" and "Leaks", each holding thousands of compressed zip files. Each file is named after a specific breach and lists algorithm type, hash value, and the recovered plain-text password for each entry.

### Using the Hashes.org Archive in an Investigation

Two workflows are described.

First: a target's email found in COMB returns a plain-text password. Searching that password in the Hashes.org archive via Ripgrep returns which breached service or services recorded that password as a hash, providing circumstantial evidence about where the target had an account. The breach file name (for example, one named after a No Doubt fan forum or a uTorrent forum) is embedded in the file path returned by Ripgrep.

Second: a breach or website exposes a hash rather than a plain-text password. The investigator identifies the hash algorithm with TunnelsUp, searches the hash string in the Hashes.org archive to recover the plain-text password, and then searches that plain-text password across the full archive to find every other service where it appeared. Each result is a potential additional account for the target.

The author notes that results are circumstantial. A unique, complex password appearing on only one or two other sites gives strong confidence that all accounts belong to the same person. A generic password like "password1234" appearing on hundreds of sites carries no investigative value.

## Key Terms

- **Doxing**: Publicly exposing personal information about a person, commonly used as a threat or retribution against law enforcement.
- **Credential stuffing**: Testing a username-and-password pair from one breach against other online services.
- **Combo list**: A file of email-address-and-password pairs drawn from multiple breaches, without attribution to any specific source.
- **COMB (Compilation Of Many Breaches)**: A 3.2 billion-credential combo list published in 2021.
- **Hash**: A fixed-length string produced by a one-way mathematical function applied to a password.
- **Salt**: Extra data added to a password before hashing to make the result harder to reverse.
- **Ripgrep (rg)**: A fast command-line search tool used to query multi-gigabyte flat files.
- **Hashes.org**: A now-offline service whose archive of cracked hash-to-plaintext mappings remains available as a torrent.
- **TunnelsUp**: A hash-identification website at `tunnelsup.com/hash-analyzer` that identifies which algorithm produced a given hash string.
