## Overview

This unit covers the tail end of Chapter 9 (the IntelTechniques Search Engines Tool) and the full opening section of Chapter 10 (Social Networks: Facebook). The Facebook material is the primary content. It describes the decline of Facebook's public search capabilities from 2019 onward, then presents the techniques that remain functional: official keyword and filter search, direct profile section URLs, numeric user ID extraction, and Base64-encoded graph filter queries.

---

## IntelTechniques Search Engines Tool (Chapter 9 tail)

The IntelTechniques Search Engines Tool is a custom HTML tool that submits a query simultaneously to Google, Bing, Yahoo, Searx, Yandex, Baidu, Exalead, DuckDuckGo, StartPage, Google Newsgroups, Google Blogs, FTP Servers, data folders, Google Scholar, Google Patents, Google News, Google Newspapers, the Wayback Machine, and dark-web engines including DarkSearch, Onionland, Not Evil, and Haystack. Each result opens in a new browser tab. The "Submit All" button runs every service at once. The browser must allow pop-ups. Standard search operators, including quotation marks, work within the tool.

**Source code fingerprinting:** A related technique involves copying a distinctive piece of JavaScript from a target site's page source and searching it on Nerdy Data. This can locate other sites that share the same codebase, identifying cloned pages, stolen code, or related services. In the demonstrated example, searching a code snippet from the GN Ethical Hacker Group search service returned 13 results, four of which revealed previously unknown related search services.

## Facebook Search Timeline and Status

Facebook's OSINT accessibility has declined sharply since 2019. The key events are:

- **June 6, 2019**: Facebook disabled previous graph profile queries. URL modification techniques to view hidden content stopped working.
- **June 17, 2019**: Researchers developed replacement tools and extensions that restored most Graph functionality.
- **August 1, 2019**: Facebook implemented encryption that disabled all browser-based extensions using the Graph API.
- **August 2-3, 2019**: Facebook began blocking automated user ID lookup tools, including the author's own service, even after server migration.
- **September 8, 2019**: Telephone number search via Facebook Messenger and most email-based search options disappeared.
- **2020**: Facebook removed the wildcard (*) search operator, blocked some Base64 methods, and changed the platform layout.
- **2022**: Many methods appeared and disappeared intermittently.

Any technique described in the chapter may no longer work by the time it is read. Despite platform changes, many users continue to share detailed personal information publicly, making Facebook an investigation target worth pursuing with the methods that remain.

## Official Facebook Keyword and Filter Search

After logging in, a search bar appears at the top of every Facebook page. The chapter describes the search landscape as two parts: the keyword (any name, term, location, or entity) and filters (options that narrow results).

Searching a common name such as "Tom Johnson" returns many unrelated profiles. The left-panel filters for city, employer, and school narrow results significantly. The filters require selecting the correct Facebook entity page for schools and employers because multiple entity pages with similar names exist. In the chapter's example, filtering by city (Chicago, Illinois), high school (Vashon High School), and employer (Foot Locker) reduced results from thousands to one profile.

**Direct category search URLs** accept any keyword. Replace `osint` with the desired term:

```
All:         https://www.facebook.com/search/top/?q=osint
Posts:       https://www.facebook.com/search/posts/?q=osint
People:      https://www.facebook.com/search/people/?q=osint
Photos:      https://www.facebook.com/search/photos/?q=osint
Videos:      https://www.facebook.com/search/videos/?q=osint
Marketplace: https://www.facebook.com/search/marketplace/?q=osint
Pages:       https://www.facebook.com/search/pages/?q=osint
Places:      https://www.facebook.com/search/places/?q=osint
Groups:      https://www.facebook.com/search/groups/?q=osint
Apps:        https://www.facebook.com/search/apps/?q=osint
Events:      https://www.facebook.com/search/events/?q=osint
Links:       https://www.facebook.com/search/links/?q=osint
```

**Workaround to access photo filters:** Facebook requires a keyword to display the filter panel. Searching the word `photos` as the keyword forces the filter panel to appear, after which the real target criteria can be applied through the filters. The same approach works with `posts` or `videos` when searching those content types.

Long result pages load continuously on scroll. Holding the spacebar scrolls to the end of a timeline.

## Obtaining the Numeric User ID

The numeric user ID is required for all Base64 graph filter queries. It is a permanent unique identifier that unlocks search capabilities not available through the username alone.

Before mid-2015, the numeric ID was visible by replacing `www` with `graph` in a profile URL. Facebook removed this capability.

**Manual method (most reliable):**
1. Navigate to the target's Facebook profile.
2. Right-click on a blank area of the page (not over a hyperlink) and select "View Page Source."
3. In the source code tab, use the browser's find function (Ctrl+F) to search for `userID`.
4. Read the number from the result. Zuckerberg's user ID, for example, is `4`: `"userID":"4"`.

The chapter advises against extracting the user ID from photo URLs because it fails when the target has no photos and because Facebook's photo display often obscures the ID.

Online tools that automate this lookup existed until Facebook began blocking them in August 2019. Two sites that still attempt it are listed:
- https://fb-search.com/find-my-facebook-id
- https://findidfb.com/

These tools cannot be relied upon.

## Base64-Encoded Graph Filter Queries

After Facebook disabled the old graph URL structure (example: `https://facebook.com/search/4/photos-by`), it replaced it with a Base64-encoded filter system. All queries follow this structure:

```
https://facebook.com/search/[TYPE]/?q=[TYPE]&epa=FILTERS&filters=[BASE64]
```

Where `[TYPE]` is `posts`, `photos`, or `videos`, and `[BASE64]` is a Base64-encoded JSON object describing the filter.

**Three-phase construction process:**

1. Identify the base URL with the desired content type, for example:
   `https://facebook.com/search/photos/?q=photos&epa=FILTERS&filters=`

2. Build the JSON filter object for the desired dimension. For filtering by author (user ID `4`):
   `{"rp_author":"{\"name\":\"author\",\"args\":\"4\"}"}`

3. Encode that JSON to Base64 using https://codebeautify.org/base64-encode and verify the round-trip at https://codebeautify.org/base64-decode. The trailing `==` padding is optional.

The Base64 output for user ID `4` is:
`eyJycF9hdXRob3IiOiJ7XCJuYWllXCI6XCJhdXRob3JcIixcImFyZ3NcIjpcIjRcIn0ifQ`

Append it to the base URL to get the full query.

## Summary of Query Dimensions

The chapter lists these query types as the primary investigative categories. Each can optionally be filtered by year (which changes the Base64 value):

- Posts, Photos, Videos by User
- Posts, Photos, Videos by Location
- Posts, Photos, Videos by Keyword
- Events by Location
- Profiles by Employer
- Profiles by Location
- Profiles by School
- Common Friends (profiles that are friends with two specified targets)
- Posts, Photos, Videos by Date range

## Practical Notes

- Employer and school filters can return incorrect entity matches because multiple Facebook pages share similar names. The chapter notes, for example, that there are multiple Vashon high schools and dozens of Foot Locker pages. Forcing Facebook to focus on the specific correct entity page is necessary.
- Online user ID lookup tools are unreliable because Facebook actively blocks them. Use manual page source inspection.
- The IntelTechniques Facebook tool automates the construction and execution of all these queries.
