The second is the opening of Section II (OSINT Resources and Techniques), which introduces covert accounts and the practical steps for creating and sustaining them.

## How the Offline Search Tools Work

The downloadable tools are plain HTML files that use JavaScript to build and open URLs. Each search option follows the same pattern: a JavaScript function constructs a URL by concatenating a base address with the user's input, then opens the result in a named browser tab. The named tab prevents a later search from overwriting an earlier result.

A representative function looks like this:

```
{window.open('https://haveibeenpwned.com/unifiedsearch/' + Search01, 'Search01window');}
```

The Have I Been Pwned (HIBP) integration illustrates why a static URL matters. The official site at haveibeenpwned.com does not produce a bookmarkable result URL after a search. The tool instead uses the API endpoint `https://haveibeenpwned.com/unifiedsearch/[email]`, which returns the same data in plain text and produces a static, reportable URL. The technique for discovering such hidden static URLs is to use Firefox's Inspector: open the Network tab, run a search on the target site, find the XHR request whose URL contains the query, and copy the Request URL from the Headers panel. This reveals the underlying API address that the tool can replicate.

Some services require modified URL construction. Dehashed requires the query to be wrapped in quotation marks. The tool achieves this by placing a double-quote character inside the JavaScript string using nested single and double quotes:

```
{window.open('https://dehashed.com/search?query="' + Search05 + '"', 'Search05window');}
```

Additional parameters are appended with the `+` character. If a service changes its URL structure, only the base URL portion of the relevant line needs updating.

## Modifying and Extending the Tools

Each search option within a tool file uses a sequentially unique identifier (Search01, Search02, and so on). To add a new service, copy the block for the highest-numbered existing option, paste it in the appropriate location, assign the next available identifier (for example Search26 if the previous highest was Search25), update the target URL, and update the button label. The numbers do not need to be sequential throughout the file, but every identifier must be unique on the page. A new service at emailleaks.com with the URL structure `https://emailleaks.com/ajax.php?query=test@email.com` would use this block:

```
function doSearch26(Search26)
{window.open('https://emailleaks.com/ajax.php?query=' + Search26, 'Search26window');}
```

The `Populate All` feature works by filling every input field whose `id` attribute begins with "Search" followed by any digits, from a single entry. This saves copying the target value into each field individually. Every `id` must be unique on the page for the feature to work.

The `Submit All` button at the bottom of each tool fires every query above it at once. Its code repeats all the `window.open` calls from the individual options within a single function. Any change made to an individual search must also be reflected in the Submit All block.

Firefox blocks pop-ups by default, so the first use of Submit All will fail. The fix is to trigger the block once, then click the yellow banner that appears and choose "Allow pop-ups for file". This must be done separately for each tool file. Alternatively, the pop-up blocker can be disabled entirely via Firefox Preferences, Privacy and Security, Permissions. The author does this inside a dedicated OSINT virtual machine, where the risk is considered acceptable, but advises against it on a personal primary browser.

## Keeping the Tools Current

Updates to individual services require changing only the URL and, if needed, the button label within the relevant script block. The author publishes updated tool files at `https://inteltechniques.com/osintbook9`. An online hosted version is available at `https://inteltechniques.com/osintbook9/tools` (login: osint9 / bookl43wt). The online version is updated as the author revises his own copy, but carries risks: it could be taken down, cannot be customized by the reader, and requires the author's server to be reachable. The offline local copy is preferred for reliability. The tools carry no warranty and are provided as-is.

For quick daily access, the author recommends adding `Search.html` (or `index.html`) to the browser bookmarks toolbar. On Linux and Windows the shortcut is Ctrl+D, on Mac it is Command+D. The file should open in Firefox rather than Chrome or another browser.

## Covert Accounts (Sock Puppets)

Many platforms now require a login before allowing any search or view. Using a personal account during an investigation risks revealing the investigator's identity to the target. Covert accounts are free profiles created with fictitious information. The author maintains multiple covert accounts and never uses a personal social network profile during any investigation, because even without deliberate action a single misclick can send a friend request from a real account to a suspect.

### Email Address for Covert Use

Every social network requires an email address at registration. The address used for covert accounts must have no connection to any personal account.

The recommended provider is Fastmail (`https://ref.fm/ul4547153`). Two properties make it suitable: it does not require a pre-existing email address to create a new account (eliminating linkage to personal accounts), and it is less scrutinized by major platforms for suspicious activity than providers such as Gmail, Yahoo, GMX, ProtonMail, or MSN. Account creation generates a free 30-day trial. Choosing a `fastmail.us` address (rather than `fastmail.com`) is recommended because the `.us` domain is less common. For long-term investigations, a paid Fastmail account provides up to 250 permanent alias addresses.

### Creating Accounts on Major Platforms

Facebook is the most difficult. It typically requires a real cellular number for new account verification. VOIP numbers, including Google Voice, are rejected. The recommended workaround is to connect from a residential or business internet connection with all VPNs, Tor, and cached sessions cleared, then register at `m.facebook.com` (the mobile site) rather than the main site. This often bypasses the phone number requirement. Public library Wi-Fi is cited as the most effective connection type for this purpose. Instagram follows the same rules, as it is owned by Facebook.

Twitter is more permissive. A legitimate email address on a residential or business connection is usually sufficient. A VPN may work during creation but is not guaranteed.

Google, Gmail, and Voice accounts can typically be created by providing a Fastmail address as an alternative contact. Google is more accommodating when Chrome is used rather than a privacy-hardened Firefox (Google owns Chrome), and it blocks creation attempts made over Tor or a VPN.

### Network Considerations

The author prefers conducting all investigations behind a VPN but notes that creating new accounts over a VPN often triggers suspicion. The approach is to create accounts from public Wi-Fi (library or coffee shop), wait a day, then begin accessing the account from a VPN. Using the same VPN provider and general server location on every subsequent login builds a consistent network pattern that helps keep the account in good standing.

### Phone Number Verification

If any service flags a new account as suspicious, it will demand a real cellular number. Landlines and VOIP numbers are rejected at this stage. The author's solution is to keep a supply of Mint Mobile SIM cards, available for $0.99 each from Amazon (`https://amzn.to/2MRbGTI`). Each card includes a number with a one-week free trial. The process is: activate the SIM in an old Android phone, use the number to complete account creation across major networks, then change the registered number to a VOIP option and lock the account with two-factor authentication.

### Two-Factor Authentication and Account Maintenance

2FA should be activated immediately after each account is created. Using 2FA (via Authy or a text code) signals to the platform that a real person controls the account rather than an automated bot. Dormant accounts are likely to be suspended upon the next login, so each covert account should be accessed at least once a week.

## Profile Content for Covert Accounts

An empty profile can attract scrutiny from both the platform and the target. Facebook is known to suspend accounts that lack personal information, and targets may run their own OSINT checks on the investigator's visible profile. The author recommends populating a minimum amount of fictitious content, with nothing that could be traced to the investigator's real identity (no real interests, occupation, or location). The author relies on randomly generated and AI-produced content for this purpose, though the specific resources used are described in the full chapter text beyond what is covered here.

The author notes that full undercover operations exceed the scope of the book. The goal here is only to create accounts sufficient to access platforms and avoid triggering automated suspension.
