## Objective

Wire `--scientific`/`--platform` from `cli.py` through `search_core.py` into `engines.search(providers=...)` and the synchronous `library()` call, completing REQ-14, REQ-01, REQ-02, and the ROADMAP Phase 1 success line.

## Context

- Threading design: `01-RESEARCH-cli-pacing.md` sections 1 and 2. One filtered `providers` parameter (landed in plan 01), no parallel search function.
- Platform vocabulary: `engines.SCIENTIFIC_PLATFORMS | {"library"}`. Library is not a network provider name and never enters the `providers` frozenset.
- Semantics (Lead decision): `--scientific` without `--platform` means the config-enabled web set plus all four scientific platforms, plus library (REQ-01 reads "existing allowlist plus library", REQ-12 adds the four platforms). `--scientific --platform x` means exactly the named platforms. Library runs only when unfiltered or explicitly named.
- Library is gated on both `library_mcp_url` and `library_mcp_token` being configured, mirroring the tavily-key precedent: unconfigured means silently not attempted, matching how tavily never appears without its key.
- Trap found while planning: `search_core._assert_dual_primary` (search_core.py:208) asserts that searxng and duckduckgo outcomes exist whenever a search returns empty under a dual-primary config. A narrowed `providers` set removes those outcomes, so the assertion must be skipped when `providers is not None`.

### Task 2: search_core threading and synchronous library fan-in

**Files:** `server/search_core.py`

**Action:**

1. Add a resolver near the top:

```python
def _resolve_sources(config, options) -> tuple[frozenset | None, bool]:
    """Library rides beside the providers set because it never enters the paced fan-out."""
```

   Returns `(providers, include_library)`. Not scientific: `(None, False)`. Scientific without platform: `(frozenset(engines._DIRECT_DEFAULTS) | {"searxng"} | engines.SCIENTIFIC_PLATFORMS, library_configured)`. With platform list: `(frozenset(platforms) - {"library"}, "library" in platforms and library_configured)`. `library_configured` means both `library_mcp_url` and `library_mcp_token` are in config. Passing all web names in the unfiltered case is safe because `_build_tasks` filters over the config-gated union, so config opt-outs still hold.

2. `_SearchRequest` gains `providers: frozenset | None = None` and `include_library: bool = False`. `quick_web_search`, `web_search` populate them from `_resolve_sources(config, options)`. `deep_research` passes `scientific`/`platform` through `_deep_search`/`_call_web_search`/`_deep_fallback`/`_call_literal_quick` into the underlying `web_search`/`quick_web_search` calls via their `**options`.

3. `_run_engine_search` passes `providers=request.providers` to `engines.search`, and `_apply_refinement` does the same for retries. Skip the refinement loop when `request.providers == frozenset()` (platform=library alone leaves no network work to refine). Guard `_assert_dual_primary` with `request.providers is None` per the trap in Context.

4. Library fan-in at the end of `_run_engine_search`, after refinement settles:

```python
if request.include_library:
    _append_library_hits(state, request)
```

   `_append_library_hits` calls `engines.library(request.query, k=request.k, config=request.config)` synchronously in a try/except over `engines._PROVIDER_FAILURES`, appends hits to `state.hits` with `hit["engines"] = ["library"]` added (merged web hits already carry `engines`, and `_provenance` expects it), and records `outcomes["library"] = {"status": "ok", "count": n}` or `{"status": "error", "error": type(exc).__name__}` on `state.hits.outcomes` when present. This is the one place library errors are converted to structured outcomes (CONV-006).

5. Context path: `_ContextOptions` and `_PoolOptions` gain `scientific: bool = False` and `platform: list | None = None`. `_gather_pool` resolves them once via `_resolve_sources` and builds the initial `_SearchRequest` with both fields. `_append_context_round` passes `providers=` to its direct `engines.search` call but never re-queries the library (one library call per command, reformulation rounds are for the web fan-out).

**Verify:** `python3 -m pytest tests/test_search_core.py tests/test_deep_context_search.py server/tests/ -q` green.

**Done when:** `quick_web_search("q", config, scientific=True)` calls `engines.search` with a providers set containing arxiv and duckduckgo, appends library hits when configured, and plain `quick_web_search("q", config)` behaves byte-identically to today.
